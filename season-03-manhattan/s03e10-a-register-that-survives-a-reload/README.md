## Чему ты научишься

- Делить состояние на данные, вид и местное — и понимать, что из этого
  принадлежит адресу.
- Читать и собирать адрес разбором, а не строкой.
- Работать с историей: `pushState`, `replaceState`, `popstate`.
- Делать так, чтобы ссылка, «назад» и перезагрузка давали один и тот же вид.
- Приёму, который дороже синтаксиса: **сначала форма, потом перехват.** Адрес
  вида придумывать не надо — его уже составляет форма с `method="get"`.
  Модуль пишет в историю ровно то, что отправила бы она.

Подробнее — в [`theory.md`](theory.md).

## Теория: пикет

### Что принадлежит адресу

| Часть состояния | Пример | Где живёт |
|---|---|---|
| **данные** | записи смены | у конторы; страница их отражает |
| **вид** | отбор, страница списка, сортировка | **в адресе** |
| **местное** | мел, черновик в поле, прокрутка | в памяти вкладки |

Признак простой: **в адрес идёт то, что имеет смысл показать другому.** «Смотри
на непрошедшие» — законная просьба. «Смотри на мои меловые пометки» —
бессмыслица: мел Кейла его собственный.

Признак, что вид не в адресе: сослаться нельзя. Ссылка не работает, «назад» не
работает, перезагрузка теряет вид, а две вкладки с одной страницей — две
разные страницы.

### Адрес разбирают

```js
const found = new URLSearchParams(location.search).get("state");

const address = new URL(location.href);
address.searchParams.set("state", "held");
address.pathname + address.search + address.hash;
```

`URLSearchParams` знает про кодирование, про повторяющиеся имена, про плюсы
вместо пробелов. Разрезание строки по `?` и `=` не знает ни про что и ломается
на первом значении с процентом внутри.

Собирать адрес строкой — та же ошибка, что собирать разметку строкой
(`s03e08`). И оттуда же второе: **адрес — чужой текст.** Ссылку присылают, её
правят руками, её достают из закладок прошлой версии. Значение из адреса
проверяют списком разрешённого.

### История

```js
history.pushState({}, "", "/telegraph.html?state=held");   // новый след
history.replaceState({}, "", "/telegraph.html");           // тот же след
```

Ни то, ни другое не грузит страницу и не вызывает `popstate`. Событие приходит,
только когда по истории двигается читатель.

Три правила, из которых состоит вся работа с историей:

- **новый вид — новый след, тот же вид — никакого.** Без первого «назад»
  уведёт со страницы; без второго история наполнится одинаковыми записями, и
  «назад» придётся нажимать пять раз;
- **читать и писать — разные направления.** Обработчик `popstate` применяет
  вид и ничего не пишет. Запись в ответ на чтение — петля;
- **вид берут из адреса, а не из `history.state`.** У первой записи он `null`
  всегда, по чужой ссылке его нет, при восстановлении вкладки он может быть от
  прошлой версии страницы. Адрес есть всегда — и его видит человек.

### Два читателя одного адреса

```
?state=held
   ├── сервер   отдаёт страницу, в которой уже только задержанные
   └── модуль   перехватывает форму и показывает то же самое без перезагрузки
```

Адрес один. Форма отбора с `method="get"` составляет его сама: имя поля
становится именем параметра. Поэтому и порядок такой — сначала форма, потом
перехват. Придумать адрес в коде, а потом подгонять под него форму — значит
развести их в первый же день.

### Где это в Rails

```ruby
resources :entries, only: %i[index create]

def index
  @entries = Entry.where(state: params[:state].presence_in(STATES))
end
```

`params[:state]` — это `readAddress`. `presence_in` — список разрешённого.
`form_with method: :get` собирает тот же адрес.

Turbo Drive делает с адресом то же, что этот файл, только для всей страницы:
перехватывает переход, забирает разметку запросом, подменяет `body` и кладёт
`pushState`. «Назад» после этого работает, потому что запись в истории
настоящая. Отсюда правило, которое переживёт сезон: **если у состояния нет
адреса, Turbo его не сохранит.**

**1.** ADA: «Что из этого кладут в адрес: отбор, мел, черновик в поле,
номер страницы списка?»

<details><summary>Ответ</summary>

Отбор и номер страницы. Мел и черновик — нет.

Признак один: имеет ли смысл показать это другому. «Смотри на непрошедшие,
вторая страница» — просьба. «Смотри на мой недописанный текст» — нет, а вдобавок
черновик в адресе утечёт в журналы сервера и в историю браузера.
</details>

**2.** ADA: «Обработчик `popstate` применил вид и записал его в историю.
Что увидит читатель?»

<details><summary>Ответ</summary>

Что «назад» не работает.

Он нажимает — браузер отходит на запись назад и шлёт `popstate`; обработчик
кладёт новую запись вперёд. Читатель остался на месте и нажимает ещё раз.

Чтение и запись — разные направления. `popstate` только применяет.
</details>

**3.** ADA: «Почему вид читают из адреса, а не из `history.state`?»

<details><summary>Ответ</summary>

Потому что `history.state` бывает пустым, чужим и старым.

У первой записи он `null` всегда. По чужой ссылке его нет вовсе. При
восстановлении вкладки после перезапуска браузера в нём может лежать то, что
клала прошлая версия страницы.

Адрес есть всегда, его видит человек, и его же прочитает сервер.
</details>

## Разбор типичных ошибок

1. **Вид живёт в памяти вкладки.** Ссылка не работает, перезагрузка теряет.
2. **Адрес разрезают строкой.** Ломается на первом же значении с процентом.
3. **Адрес собирают заново.** Чужие параметры и якорь исчезают.
4. **Пустой отбор оставляет `?state=`.** Ссылка говорит, что вид выбран,
   когда он не выбран.
5. **Значение из адреса не проверяют.** Адрес — чужой текст.
6. **Каждое нажатие кладёт след, даже если вид тот же.** «Назад» перестаёт
   работать для читателя, оставаясь исправным формально.
7. **`popstate` пишет в историю.** Петля.
8. **Вид берут из `history.state`.** Пусто по чужой ссылке.
9. **Поле отбора не приводят к виду.** В поле одно, на странице другое.
10. **Мел в адресе.** Ссылка с чужими пометками.
11. **Форма отбора ведёт в контору.** Читатель без скрипта получает JSON
    вместо журнала.
