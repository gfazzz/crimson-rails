## Обстановка

У каждой точки линии есть пикет: миля и сотые. Адрес нужен не тому, кто стоит
на месте, а тому, кто должен туда прийти.

У журнала точки нет. Отбор живёт в памяти вкладки: ссылка не работает, «назад»
не работает, перезагрузка теряет вид, и показать соседу то же самое нельзя.

## Приказ

Дать виду адрес.

## `address.js`

### `view({ filter })`

Вид журнала. Поле пока одно, и всё равно это отдельная вещь: у вида есть
адрес, у состояния журнала — нет. Отбор берётся из списка разрешённого;
неизвестное значение — не ошибка, а «не отбор».

### `readAddress(search)`

Что сказано в адресе. Разбирать `URLSearchParams`, а не строку руками.

### `addressOf(shown, here)`

| Вид | Адрес |
|---|---|
| `{ filter: "held" }` | `…?state=held` |
| `{ filter: "" }` | без вопроса: «все записи» — это та же страница |
| чужие параметры и якорь | сохраняются: адрес принадлежит не только нам |

### `showAddress(shown, { replace })`

| Способ | Когда |
|---|---|
| `pushState` | новый вид: «назад» должен вернуть прошлый |
| `replaceState` | привести адрес в порядок, не оставляя следа |

Адрес, совпадающий с нынешним, **не писать вовсе**: иначе одно и то же
нажатие копит историю из одинаковых видов, и «назад» формально работает, а для
читателя нет.

### `onAddress(handler)`

Читатель нажал «назад». Вид брать из **адреса**, а не из `history.state`: у
первой записи состояние `null` всегда, а адрес есть всегда. Вернуть функцию
отписки.

## `telegraph.html`

Форма отбора обязана вести на саму страницу (`method="get"`,
`action="telegraph.html"`), а не в контору: читателю без скрипта нужен журнал,
а не ответ конторы. Имя поля — это имя параметра в адресе.

## `telegraph.js`

- отбор при загрузке берётся из адреса, а не из разметки;
- поле отбора приводится к виду, а не наоборот: читатель мог прийти по ссылке;
- смена отбора меняет состояние **и** адрес — вместе, в одном месте;
- «назад» применяет вид, но обратно в историю не пишет;
- мел в адрес не пишется: он местный.

## Критерии приёмки

**Вид и адрес**

- [ ] Неизвестный отбор — не отбор.
- [ ] Адрес читается разбором параметров, а не разрезанием строки.
- [ ] Адрес — тоже чужой текст: `?state=<script>` ничего не ломает.
- [ ] Пустой отбор вопроса в адресе не оставляет.
- [ ] Чужие параметры и якорь не теряются.

**История**

- [ ] Смена вида оставляет след; тот же вид — нет.
- [ ] «Назад» возвращает прошлый вид и приводит поле отбора.
- [ ] «Назад» в историю не пишет.
- [ ] Вид берётся из адреса, а не из записи в истории.

**Ссылка**

- [ ] Ссылка открывает тот же вид.
- [ ] Перезагрузка вид не теряет.
- [ ] Неизвестный отбор в ссылке журнал не ломает.
- [ ] «Все записи» убирают вопрос из адреса.
- [ ] Мел в адрес не пишется.

**Без скрипта**

- [ ] Форма отбора ведёт на страницу методом `GET`.
- [ ] Сервер по тому же адресу отдаёт тот же вид.

**Приёмка сезона**

- [ ] Журнал приходит из конторы и заменяет разметочный.
- [ ] Чужой текст остаётся текстом.
- [ ] Свой элемент поднят и показывает время.
- [ ] Живая область объявлена живой и говорит.
- [ ] Отрисовать дважды — то же, что один раз.
- [ ] Запись уходит одним запросом и с ключом приёма.
- [ ] Страница работает без единой ошибки.

- [ ] `make test` → двадцать четыре зелёные проверки.

## Подводный камень

Первый: писать адрес в ответ на `popstate`. Это петля — читатель нажимает
«назад» и остаётся на месте, потому что обработчик тут же кладёт новый след.
Читать и писать — разные направления, и смешивать их нельзя.

Второй: `history.state`. Он кажется удобным местом для вида, но у первой
записи он `null`, при восстановлении вкладки — чужой, а при переходе по чужой
ссылке — отсутствует. Адрес есть всегда, и он же виден человеку.

Третий: класть в адрес всё подряд. Адрес — это то, чем делятся. Мел, черновик
в поле, раскрытая подсказка туда не идут: ссылка с чужим мелом бессмысленна.
