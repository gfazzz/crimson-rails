# Теория — s03e10

## 1. Какое состояние принадлежит адресу

Не всё состояние одинаково. Раздели его на три части и спроси про каждую: что
случится, если читатель перезагрузит страницу или пришлёт ссылку соседу?

| Часть | Пример в журнале | Где живёт |
|---|---|---|
| **данные** | записи смены | у конторы; страница их отражает |
| **вид** | отбор, страница списка, сортировка, открытая вкладка | **в адресе** |
| **местное** | мел, черновик в поле, раскрытая подсказка, положение прокрутки | в памяти вкладки |

Правило простое: **в адрес идёт то, что имеет смысл показать другому.** Мел
Кейла смысла не имеет — ссылка с чужим мелом это бессмыслица. Отбор имеет:
«посмотри на непрошедшие» — законная просьба.

Признак, что вид не в адресе: невозможно сослаться. Нельзя дать ссылку,
нельзя вернуться кнопкой, перезагрузка теряет вид, и две вкладки с одной
страницей — это две разные страницы.

## 2. Адрес разбирают

```js
const found = new URLSearchParams(location.search).get("state");
```

`URLSearchParams` знает про кодирование, про повторяющиеся имена
(`getAll`), про плюсы вместо пробелов. Разрезание строки по `?` и `=` не знает
ни про что из этого и ломается на первом же значении с процентом внутри.

Адрес целиком разбирает `URL`:

```js
const address = new URL(location.href);
address.searchParams.set("state", "held");
address.searchParams.delete("page");
address.pathname + address.search + address.hash;
```

Собирать адрес строкой — та же ошибка, что собирать разметку строкой (`s03e08`),
и по той же причине: части адреса надо кодировать, и правила кодирования у
каждой части свои.

**Адрес — чужой текст.** Ссылку присылают, её правят руками, её сохраняют в
закладках прошлой версии страницы. Значение из адреса проверяют списком
разрешённого, как и всё остальное, что пришло снаружи.

## 3. История

```js
history.pushState(данные, "", "/telegraph.html?state=held");    // новый след
history.replaceState(данные, "", "/telegraph.html");            // тот же след
```

Ни то, ни другое **не грузит страницу** и не вызывает `popstate`. Событие
приходит, только когда по истории двигается читатель — кнопками «назад» и
«вперёд».

Три правила, из которых состоит вся работа с историей.

**Новый вид — новый след, тот же вид — никакого.** Без первого «назад» уведёт
читателя со страницы вместо прошлого вида. Без второго история наполнится
одинаковыми записями, и «назад» придётся нажимать пять раз.

**Читать и писать — разные направления.** Обработчик `popstate` применяет вид
и ничего не пишет. Запись в ответ на чтение — петля: читатель нажимает
«назад» и остаётся на месте.

**Вид берут из адреса, а не из `history.state`.** Второй аргумент `pushState`
кажется удобным хранилищем, но у первой записи он `null` всегда, при переходе
по чужой ссылке его нет, а при восстановлении вкладки он может быть от
прошлой версии страницы. Адрес есть всегда — и его, в отличие от `state`,
видит человек.

Отдельно стоит `hashchange` и адрес с `#`: он тоже переживает перезагрузку, но
не уходит на сервер, а значит читателю без скрипта достанется страница без
вида. Для отбора это не годится.

## 4. Два читателя одного адреса

Главное, ради чего всё это.

```
?state=held
   ├── сервер   отдаёт страницу, в которой уже только задержанные
   └── модуль   перехватывает форму и показывает то же самое без перезагрузки
```

Адрес один. Форма отбора с `method="get"` **сама** его составляет — имя поля
становится именем параметра, и ничего изобретать не надо. Модуль не выдумывает
адрес: он пишет в историю ровно то, что отправила бы форма.

Отсюда порядок работы, который стоит запомнить: **сначала форма, потом
перехват.** Если сначала придумать адрес в коде, а потом подгонять под него
форму, они разойдутся в первый же день.

## 5. Где это в Rails

```ruby
# routes.rb
resources :entries, only: %i[index create]

# entries_controller.rb
def index
  @entries = Entry.where(state: params[:state].presence_in(STATES))
end
```

`params[:state]` — это и есть `readAddress`. `presence_in` — список
разрешённого. `form_with method: :get` собирает тот же адрес, что и наша форма
отбора.

Turbo Drive делает с адресом ровно то, что делает этот файл, только для всей
страницы: перехватывает переход, забирает разметку запросом, подменяет `body`
и кладёт `pushState`. Кнопка «назад» после этого работает, потому что запись в
истории настоящая. А `turbo_frame_tag` с `src` — это адрес куска страницы, и
он тоже настоящий: его можно открыть отдельно и увидеть тот кусок.

Отсюда правило, которое переживёт этот сезон: **если у состояния нет адреса,
Turbo его не сохранит.** Ни при переходе, ни при «назад», ни при
восстановлении.

## 6. Чего эта серия не закрывает

- **прокрутка.** Turbo и браузер спорят за неё; `history.scrollRestoration`
  существует именно поэтому;
- **адрес и отбор на сервере.** У нас отбор применяется дважды: сервером — для
  читателя без скрипта, модулем — для читателя со скриптом. В Rails это одна
  строка контроллера и один шаблон;
- **длинные виды.** Когда в адресе оказывается десять параметров, пора
  спрашивать, не пора ли сохранить вид на сервере и дать ему короткий адрес.
