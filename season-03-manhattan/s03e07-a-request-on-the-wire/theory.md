# Теория — s03e07

## 1. `fetch`

```js
const answer = await fetch(address, {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify(payload),
  signal,
  credentials: "same-origin",   // куки: по умолчанию только свои
  cache: "no-store",
  redirect: "follow",
});
```

Что удивляет первым: **`fetch` не отклоняется на плохой код ответа.** 404, 422,
500 — это ответы, и обещание ими разрешается. Отклоняется он, только когда
ответа нет вовсе: обрыв, неразрешимое имя, запрет политики, отмена.

```js
if (!answer.ok) { … }          // ok === (status >= 200 && status < 300)
```

Второе: **тело читается один раз.** `answer.json()`, `answer.text()`,
`answer.blob()`, `answer.arrayBuffer()` — любой из них помечает поток
прочитанным, и второй вызов бросит. Нужны оба — читают текст и разбирают сами
(или `answer.clone()` до чтения).

## 2. Коды ответа

| Класс | О чём | Повторять |
|---|---|---|
| 1xx | «ещё не всё» | — |
| 2xx | принято | — |
| 3xx | идите туда | `fetch` переходит сам |
| 4xx | про запрос: так нельзя | нет (кроме 429) |
| 5xx | про контору: нам плохо | да |

Те, что встречаются каждый день:

- `200 OK`, `201 Created` (и `Location` с адресом созданного), `204 No Content`;
- `303 See Other` — «переходите сюда методом GET»: ответ формы без скрипта;
- `400` — не разобрать; `422` — разобрали, но так нельзя;
- `401` — вы кто; `403` — вы не тот; `404` — нет такого;
- `409` — столкновение: кто-то успел раньше;
- `429` — слишком часто, и в `Retry-After` написано, сколько ждать;
- `500`, `502`, `503`, `504` — у конторы пожар, шлюз молчит, перегрузка.

Граница по сотне и есть правило повтора: четырёхсотые не повторяют — ответ не
изменится.

## 3. Идемпотентность

Метод **идемпотентен**, если повтор не меняет итога:

| Метод | Безопасный | Идемпотентный |
|---|---|---|
| GET, HEAD | да | да |
| PUT, DELETE | нет | да |
| POST | нет | **нет** |
| PATCH | нет | как написали |

`POST` создаёт — значит повтор создаёт второе. Лечится ключом приёма:

```js
headers: { "x-receipt": receipt }   // в Rails-мире: Idempotency-Key
```

Контора помнит ключ и на повтор возвращает тот же ответ, ничего не заводя.
Ключ один на попытку и все её повторы; новый ключ на каждом повторе — то же,
что без ключа.

Зачем это нужно: ответ теряется **после** того, как запись заведена. Клиент об
этом не знает и повторяет — и именно плохая связь, ради которой повтор и
написан, создаёт задвоение.

## 4. Отмена

```js
const stop = new AbortController();
fetch(address, { signal: stop.signal });
stop.abort("передумали");           // причина попадёт в signal.reason

AbortSignal.timeout(2000);          // сам оборвёт по сроку
AbortSignal.any([stop.signal, AbortSignal.timeout(2000)]);
```

Отклонение приходит с `name === "AbortError"`. Его **не переодевают** в свою
ошибку и не показывают читателю: отмену вызвал он сам.

Сигнал понимают не только `fetch`, но и `addEventListener`
(`{ signal }` — `s03e03`), и `stream`, и многие свои функции: принять сигнал
и слушать `abort` стоит дёшево.

## 5. Повтор

```js
for (let attempt = 1; attempt <= times; attempt += 1) {
  try {
    return await work(attempt);
  } catch (error) {
    if (!error?.retriable || attempt === times) throw error;
    await new Promise((r) => setTimeout(r, pause * attempt + Math.random() * pause));
  }
}
```

Три правила: повторять только повторяемое; выдержку увеличивать; добавлять
разброс, чтобы сотня клиентов не пришла в себя одновременно.

Чего повтор не чинит: ошибку в запросе. Если контора сказала «поле пустое»,
трижды спросить её об этом — значит трижды получить тот же ответ.

## 6. Тело и заголовки

```js
body: JSON.stringify(entry)            + content-type: application/json
body: new FormData(form)               браузер сам поставит заголовок с границей
body: new URLSearchParams(data)        + content-type: application/x-www-form-urlencoded
```

`FormData` — единственный случай, когда заголовок ставить **нельзя**: браузер
добавит к нему границу частей, а вручную её не угадать.

Значения заголовков — ASCII. Кириллица бросает ошибку ещё до отправки; для
текста существует кодирование, но лучше просто не класть текст в заголовки.

Ответ:

```js
answer.status; answer.ok; answer.redirected; answer.url;
answer.headers.get("location");
```

## 7. Чужая контора

Запрос к другому источнику браузер разрешает только с позволения самой конторы
(CORS): она отвечает `Access-Control-Allow-Origin`, а на «непростые» запросы
браузер сперва шлёт `OPTIONS`. Непростым делает почти всё: свой заголовок
(`x-receipt` — уже непростой), `content-type: application/json`, метод `PUT`.

В этом сезоне контора своя, и вопрос не встаёт. Он встанет в сезоне 6, когда
появятся внешние службы.

## 8. Что показывать читателю

| Случилось | Читателю |
|---|---|
| 422 с полем | сказать, назвать поле, поставить фокус |
| 5xx после всех попыток | сказать; введённое сохранить |
| обрыв | сказать; показать то, что есть |
| отмена | ничего |

И правило: **отказ ничего не стирает.** Ни формы, ни журнала. Пустой журнал
из-за недоступной конторы — худшее, что можно показать: он выглядит как
«записей нет».

## 9. Где это в Rails

```ruby
def create
  entry = Entry.new(entry_params)
  if entry.save
    render json: { entry: }, status: :created
  else
    render json: { error: entry.errors.full_messages.first }, status: :unprocessable_entity
  end
end
```

Turbo читает код ответа буквально: `422` — перерисовать форму с ошибками,
`303` — перейти, прочее 4xx/5xx — показать ошибку. Отсюда правило Rails 8:
**отвечать на неудачную форму `422`, а не `200`**, иначе Turbo решит, что всё
хорошо.

`Idempotency-Key` в Rails обычно кладут в таблицу с уникальным индексом —
и это `s04`, где выяснится, что единственная надёжная защита от задвоения
живёт в базе, а не в коде.
