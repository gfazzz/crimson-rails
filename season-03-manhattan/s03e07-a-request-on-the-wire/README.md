## Чему ты научишься

- Ходить в контору `fetch`: метод, заголовки, тело, разбор ответа.
- Различать коды ответа: какие повторяют, а какие нет.
- Отменять запрос, а не только переставать его ждать.
- Повторять так, чтобы повтор не заводил вторую запись.
- Приёму, который дороже синтаксиса: **повтор — это не «то же самое ещё

  связь и без того плохая.

## Теория: провод

### `fetch`

```js
const answer = await fetch(`${origin}/entries`, {
  method: "POST",
  headers: { "content-type": "application/json", "x-receipt": receipt },
  body: JSON.stringify(entry),
  signal,
});
```

Две вещи удивляют первыми. **`fetch` не отклоняется на 404 и 500:** ответ
пришёл — обещание разрешилось; отклоняется он, только когда ответа нет вовсе
(обрыв, отказ в имени, отмена), а код проверяешь ты. И **тело читается один
раз:** `await answer.json()` работает однажды, второй раз бросит.

### Код ответа — это три случая Пейджа

| Код | Что значит | Повторять |
|---|---|---|
| 200, 201, 204 | принято | — |
| 303 | принято, идите туда (форма без скрипта) | — |
| 400, 422 | так нельзя: бланк не годится | нет, ответ не изменится |
| 401, 403, 404 | не вам; нет такого | нет |
| 409 | столкновение: кто-то успел раньше | иногда, разобравшись |
| 429 | слишком часто | да, подождав |
| 500, 502, 503, 504 | у нас пожар, попробуйте позже | да |

Граница проходит по сотне: четырёхсотые — про запрос, пятисотые — про контору.
Повторять имеет смысл только вторые и `429`.

### Отмена

```js
const stop = new AbortController();
fetch(address, { signal: stop.signal });
stop.abort();          // обещание отклонится ошибкой с name === "AbortError"
```

Отмена — не срок ожидания (`s03e06`): срок перестаёт **ждать**, а запрос идёт
дальше; отмена обрывает **запрос**. Отмену не переодевают в ошибку —
жаловаться читателю не на что; обработка отмены это `return`, а не сообщение.
Зачем она здесь: два нажатия на «Передать» подряд без отмены дают два запроса
и две записи.

Рядом стоят `AbortSignal.timeout(ms)` — срок, который отменяет
по-настоящему, — и `AbortSignal.any([…])`, когда причин оборвать несколько.

### Повтор и ключ приёма

Повторять нужно — сеть рвётся, контора перегружается. Но повтор опасен ровно
тем, чем полезен:

```
пост → контора   запись заведена
контора → пост   ответ потерялся в пути
пост → контора   тот же бланк ещё раз
```

Без ключа приёма контора заведёт вторую запись — настоящую, с номером и датой.
Ключ один на **попытку и все её повторы**: новый ключ на каждом повторе — то
же, что без ключа, только с видимостью порядка. Значение — только ASCII:
кириллица в заголовке даёт ошибку ещё до отправки, а `crypto.randomUUID()`
берётся бесплатно.

### Что повторять, а что нет

```js
export async function withRetry(work, { times = 3, pause = 50 } = {}) {
  for (let attempt = 1; attempt <= times; attempt += 1) {
    try {
      return await work(attempt);
    } catch (error) {
      if (!error?.retriable || attempt === times) throw error;
      await new Promise((resolve) => setTimeout(resolve, pause * attempt));
    }
  }
}
```

Выдержка растёт: конторе, которой плохо, не станет лучше от трёх вопросов
подряд. Настоящие клиенты добавляют разброс, чтобы сотня страниц не пришла в
себя одновременно.

### Отказ, который надо показать, и отказ, который не надо

| Что случилось | Читателю |
|---|---|
| 422 с полем | сказать, назвать поле, поставить туда фокус |
| 500 после трёх попыток | сказать; введённое сохранить |
| обрыв провода | сказать; журнал показать по странице |
| отмена | ничего: он сам её и вызвал |

И общее правило: **отказ ничего не стирает.** Ни полей, ни журнала.

### Где это в Rails

```ruby
def create
  entry = Entry.new(entry_params)
  if entry.save
    render json: { entry: }, status: :created
  else
    render json: { error: entry.errors.full_messages.first }, status: :unprocessable_entity
  end
end
```

`:created`, `:unprocessable_entity`, `:no_content` — Rails называет коды
словами, и это тот же разговор. Turbo смотрит именно на код: `422`
перерисовывает форму с ошибками, `303` ведёт дальше, `500` показывает страницу
ошибки. Ключ приёма в Rails зовут `Idempotency-Key`, и в сезоне 6 он появится
снова: очередь повторяет задачу по тем же причинам, по которым сеть повторяет
запрос.

**1.** ADA: «Контора ответила 500. `fetch` отклонился?»

<details><summary>Ответ</summary>

Нет. Ответ пришёл — обещание разрешилось, и `await` вернул ответ со
`status: 500` и `ok: false`.

`fetch` отклоняется, только когда ответа нет вовсе: обрыв, неразрешимое имя,
отмена. Проверка кода — твоя работа, и `if (!answer.ok)` — самая пропускаемая
строка во всём переднем крае.
</details>

**2.** ADA: «Повтор с новым ключом приёма. Что получится?»

<details><summary>Ответ</summary>

То же, что без ключа: контора увидит другой бланк и заведёт вторую запись.

Ключ существует, чтобы контора **узнала повтор**. Новый ключ на каждой попытке
— видимость порядка: код выглядит правильным и делает ровно то, от чего ключ
должен был спасти.
</details>

**3.** ADA: «Читатель нажал «Передать» дважды. Срок ожидания спасёт?»

<details><summary>Ответ</summary>

Нет: срок ограничивает ожидание, а не отправку — оба запроса уже ушли и оба
дойдут. Спасают две вещи, и обе нужны: отмена незаконченного запроса на своей
стороне и ключ приёма на стороне конторы.
</details>

## Разбор типичных ошибок

1. **Код ответа не проверяют.** `fetch` не отклоняется на 500.
2. **Тело без заголовка типа.** Контора разберёт JSON как форму.
3. **422 не отличают от 500.** Первое повторять бессмысленно, второе нужно.
4. **Поле из отказа теряется.** Читателю не показали, что именно не так.
5. **Обрыв провода роняет чужой ошибкой.** Непонятно, что случилось.
6. **Отмену переодевают в отказ.** Читатель видит жалобу на то, что сделал
   сам.
7. **Ключ приёма не уезжает** или меняется на каждом повторе. Задвоение.
8. **Повторяют всё подряд.** Контору спросили трижды об одном и том же.
9. **Двойное нажатие не отменяет предыдущий запрос.** Две записи.
10. **Отказ стирает введённое.** Наказание за чужой пожар.
