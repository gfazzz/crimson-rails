# Теория — s03e04

## 1. Что делает браузер при отправке

1. читатель нажимает кнопку отправки (или Enter в текстовом поле);
2. браузер проверяет форму по разметке — `required`, `type`, `pattern`,
   `min`/`max`, `minlength`/`maxlength`;
3. **если проверка не прошла** — показывает своё окно у первого неверного поля,
   ставит туда фокус и останавливается. События `submit` не будет;
4. если прошла — собирает поля, шлёт запрос, переходит по ответу.

Отсюда главное: обработчик `submit` вызывается **после** проверки. Всё, что
модуль хочет сказать вместо браузера, требует сперва объявить, что он
сообщает сам.

```js
form.noValidate = true;   // «дальше сообщаю я»
```

Ставит это **модуль**, не разметка. Написанный в разметке `novalidate`
выключает проверку и без скрипта — а сказать вместо неё некому.

## 2. Проверка по разметке

```html
<input required>                       обязательно
<input type="email">                   формат
<input pattern="[A-Z]{3}">             своё выражение, целиком
<input minlength="5" maxlength="120">  длина
<input type="number" min="1" max="6" step="1">
<textarea required maxlength="120">
```

Что даёт бесплатно: подходящая клавиатура на телефоне, календарь у дат,
сообщение на языке читателя, работа без скрипта и правильное объявление
голосовым браузером.

Ловушка `maxlength`: оно не даёт **ввести** больше, но не сообщает об этом.
`minlength` наоборот — сообщает при отправке.

## 3. Состояние поля

```js
field.willValidate              участвует ли в проверке вообще
field.checkValidity()           проходит ли; при отказе шлёт событие invalid
field.reportValidity()          то же плюс показать окно браузера
field.validationMessage         текст, который показал бы браузер
field.validity                  объект с причинами
```

`validity` по пунктам:

| Свойство | Когда истинно |
|---|---|
| `valueMissing` | `required` и пусто |
| `typeMismatch` | не тот формат (`email`, `url`) |
| `patternMismatch` | не подошло под `pattern` |
| `tooShort` / `tooLong` | длина |
| `rangeUnderflow` / `rangeOverflow` | число вне границ |
| `stepMismatch` | не кратно `step` |
| `badInput` | браузер не смог разобрать введённое |
| `customError` | поставлено через `setCustomValidity` |
| `valid` | всё в порядке |

## 4. Своё правило

```js
const text = field.value.trim();
field.setCustomValidity(text.length < 5 ? "Не короче пяти знаков." : "");
```

Две вещи, о которых забывают:

- **правило залипает.** Пока не позвали `setCustomValidity("")`, поле остаётся
  неверным — даже когда текст исправлен;
- **правило проверяют в нужный момент.** Поставленное только на `submit`, оно
  не обновится при вводе; поставленное только на `input`, не сработает при
  отправке с клавиатуры. Обычно нужно и то и другое.

Сообщение пишут словами, объясняющими, что сделать: «не короче пяти знаков»
вместо «неверное значение».

## 5. `FormData`

```js
const data = new FormData(form);
data.get("text");
data.getAll("marks");                  несколько значений одного имени
[...data.entries()];
new URLSearchParams(data).toString();  для отправки как форма
```

Что попадает: только поля с `name`, только не `disabled`, отмеченные
переключатели и флажки, выбранное в списках, файлы.

Что не попадает: поля без имени, отключённые, кнопки (кроме той, которой
отправили, — и то только если у неё есть `name`).

`new FormData(form, submitter)` — вторым аргументом кнопка: так в данные
попадает `name`/`value` именно той кнопки, которой отправляли.

## 6. Сообщение, которое услышат

```html
<p role="status" hidden></p>          вежливое: дождётся паузы
<p role="alert"></p>                  настойчивое: перебьёт
<p aria-live="polite" aria-atomic="true"></p>
```

Правила:

1. **область создаётся заранее и пустой.** Живая область объявляет изменения
   внутри себя. Узел, вставленный сразу с текстом, — не изменение внутри, а
   новый узел: его пропустят молча;
2. **`status`, а не `alert`.** Ошибка формы не пожар; `alert` перебивает
   читателя на полуслове и оправдан только там, где промедление опасно;
3. **`aria-atomic="true"`**, если текст меняется целиком: иначе объявят только
   изменившийся кусок;
4. **фокус — в первое неверное поле.** Сообщение объявят, но идти к полю
   читателю придётся самому.

Связать поле и его ошибку можно и адресно:

```html
<textarea id="text" aria-describedby="text-error" aria-invalid="true"></textarea>
<p id="text-error">Не короче пяти знаков.</p>
```

Тогда сообщение прочтут вместе с полем, когда читатель до него дойдёт.

## 7. Чего отказ не делает

- **не стирает введённое.** Ни полей, ни выбранного, ни прокрутки;
- **не прячет форму** и не заменяет её сообщением;
- **не уводит фокус** в начало страницы;
- **не мешает отправить снова** после исправления.

## 8. Три уровня и один настоящий

| Где | Что ловит | Обходится |
|---|---|---|
| разметка | опечатку | инспектором за секунду |
| модуль | опечатку раньше и понятнее | инспектором за секунду |
| сервер | всё | нет |
| база | целостность | нет |

Проверка на месте — про удобство. Проверка в конторе — про правильность. Ни
одна не заменяет другую, и путать их опасно в обе стороны: без первой читатель
узнаёт об опечатке через трое суток, без второй в базе оказывается что угодно.

## 9. Где это в Rails

```ruby
validates :text, presence: true, length: { minimum: 5 }
```

```erb
<%= form.text_area :text, required: true, minlength: 5 %>
```

Одно правило записано дважды — и это не дублирование, а разные уровни. При
отказе Turbo перерисовывает форму вместе с ошибками, сохраняя введённое;
Stimulus добавляет то, что здесь делает модуль.

Отдельная мелочь, которая пригодится в `s05`: Rails кладёт в форму скрытое
поле с токеном (`authenticity_token`). Оно тоже уезжает с `FormData` — и
именно поэтому запрос, собранный руками мимо формы, получает от сервера отказ.
