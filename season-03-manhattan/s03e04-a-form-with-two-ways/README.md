## Чему ты научишься

- Перехватывать отправку формы и знать, когда этого делать **нельзя**.
- Пользоваться встроенной проверкой браузера и добавлять к ней своё правило.
- Показывать ошибку так, чтобы её услышали: живая область и фокус.
- Не терять введённое.
- Приёму, который дороже синтаксиса: **проверка на месте не отменяет проверку
  в конторе.** Первую обходят открытым инспектором; вторая — единственная
  настоящая.

Подробнее — в [`theory.md`](theory.md).

## Теория: отправка

### Два пути к одной конторе

```
без скрипта:  нажал → браузер проверил → отправил → перешёл
со скриптом:  нажал → браузер проверил → модуль объяснил → отправил → перешёл
```

Путь один и кончается в конторе; разница в том, кто и когда объясняет ошибку.
Поэтому модуль **не заменяет** отправку, пока ему нечем: он отменяет её ровно
тогда, когда отправлять нельзя. Замена появится в `s03e07`, когда журнал
научится ходить в контору сам.

### Событие `submit`

```js
form.addEventListener("submit", (event) => {
  if (form.checkValidity()) return;   // не мешаем
  event.preventDefault();             // мешаем, потому что есть что сказать
});
```

`submit` случается **после** того, как браузер проверил форму: не прошла
проверку — события не будет вовсе. Отсюда `noValidate`: им модуль объявляет,
что сообщает сам. Ставит его **модуль**, не разметка: написанный в разметке, он
выключает проверку и без скрипта, а сказать вместо неё будет некому.

### Что даёт встроенная проверка

```js
field.willValidate         участвует ли поле в проверке
field.checkValidity()      проходит ли
field.validity.valueMissing / tooShort / patternMismatch / typeMismatch / rangeOverflow
field.validationMessage    сообщение браузера на языке читателя
field.setCustomValidity(s) своё правило: непустая строка делает поле неверным
form.checkValidity()       проходит ли форма целиком
form.reportValidity()      проверить и показать своё окно браузера
```

Своё правило обязательно **снимается** при исправлении — `setCustomValidity("")`:
поле, которому один раз сказали «неверно», иначе останется таким навсегда.

### `FormData`

```js
const data = new FormData(form);
data.get("text");
[...data];               // [["from","23"], ["text","…"]]
new URLSearchParams(data).toString();
```

`FormData` собирает то же, что уехало бы на сервер: только поля с `name`,
только включённые, отмеченные переключатели — по одному на группу. Смотришь на
то, что действительно отправится, а не на то, что видно.

### Сообщение, которое услышат

```html
<p role="status" hidden></p>
```

Три правила, и каждое нарушают:

1. **область создаётся заранее и пустой.** Голосовой браузер объявляет то, что
   появилось в уже существующей живой области; узел, вставленный вместе с
   текстом, он молча пропустит;
2. **`role="status"`, а не `alert`.** Первое объявляется, когда читатель
   доберётся, второе перебивает на полуслове. Ошибка формы — не пожар;
3. **фокус — в первое неверное поле.** Иначе его ищут вслепую.

### Не терять введённое

Форма, очищающаяся после отказа, наказывает за ошибку, которую читатель ещё не
понял. **Отказ ничего не стирает:** ни полей, ни выбранного, ни прокрутки.

### Проверка на месте обходится за секунду

Инспектор, `curl`, чужой клиент — любой из них отправит форму мимо всякого
модуля. Поэтому:

| Где | Что проверяет | Можно обойти |
|---|---|---|
| разметка (`required`, `pattern`) | опечатку | да, тривиально |
| модуль | опечатку раньше и понятнее | да, тривиально |
| сервер | всё | нет |
| база | целостность | нет |

Первые две строки — про удобство, третья — про правильность, и одно другим не
заменяется.

### Где это в Rails

```ruby
class Entry < ApplicationRecord
  validates :text, presence: true, length: { minimum: 5 }
end
```

```erb
<%= form_with model: @entry do |form| %>
  <%= form.text_area :text, required: true, minlength: 5 %>
<% end %>
```

Одно правило записано дважды: в модели — потому что это единственная настоящая
проверка, в разметке — потому что читателю лучше узнать сразу. Turbo при
отказе сервера перерисовывает форму вместе с ошибками, а Stimulus добавляет то,
что делает здесь модуль. Основание при этом — валидация модели, и её видно в
`s04`.


**1.** ADA: «`novalidate` в разметке. Что произойдёт без скрипта?»

<details><summary>Ответ</summary>

Форма перестанет проверяться вовсе: браузеру сказали молчать, а сказать вместо
него некому. Пустая запись уедет в контору, и вернётся оттуда через трое
суток.

`noValidate` ставит модуль — и только после того, как приготовился сообщать
сам.
</details>

**2.** ADA: «Модуль отменяет отправку всегда и показывает сообщение, когда
надо. Что не так?»

<details><summary>Ответ</summary>

Правильно заполненная форма перестала уходить. Отменили — и не заменили: в
контору не попадает ничего, и заметит это не проверка, а пост, чья запись
пропала.

Отменять можно только то, что отправлять нельзя, — пока не появилось, чем
отправлять самому (`s03e07`).
</details>

**3.** ADA: «Сообщение об ошибке вставили в форму вместе с текстом. Кто его не
услышит?»

<details><summary>Ответ</summary>

Тот, кто слушает страницу. Живая область объявляет **изменения внутри себя**;
узел, появившийся сразу с текстом, для неё не изменение, а новый узел — и он
проходит молча.

Поэтому область создают заранее, пустой и спрятанной, а текст кладут в неё
потом.
</details>

## Разбор типичных ошибок

1. **`novalidate` в разметке.** Без скрипта форма не проверяется вовсе.
2. **Модуль не ставит `noValidate`.** Два сообщения об одной ошибке.
3. **Отправка отменяется всегда.** Правильная запись не уходит никуда.
4. **Отправка не отменяется при ошибке.** Проверку сделали и не применили.
5. **Живая область создаётся вместе с текстом.** Её не объявят.
6. **`role="alert"` вместо `status`.** Читателя перебили на полуслове.
7. **Фокус не переставлен.** Неверное поле ищут вслепую.
8. **Форма очищается после отказа.** Наказание за непонятую ошибку.
9. **Своё правило без объяснения.** «Нельзя» — не сообщение.
10. **`setCustomValidity` не снимается.** Поле неверно навсегда.

## Debriefing

Форма читает себя сама. Пустая не уходит и объясняет почему; «ок» не уходит и
объясняет, что текст короче пяти знаков; заполненная уходит в контору, как
уходила раньше.

Ты выключаешь скрипт и проверяешь ещё раз. Пустая не уходит — браузер не
пускает сам. Заполненная уходит. Кнопка «Показать» на месте.
