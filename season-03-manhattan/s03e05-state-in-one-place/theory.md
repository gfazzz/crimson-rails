# Теория — s03e05

## 1. Модули ES

```js
export function withChalk(state, id) { … }     именованный экспорт
export const LIMIT = 120;
export default class Register { … }            по умолчанию — один на файл
export { a, b as c };                          списком
export * from "./other.js";                    перенаправление

import { withChalk } from "./state.js";
import { withChalk as toggle } from "./state.js";
import * as state from "./state.js";
import Register from "./register.js";          по умолчанию
import "./setup.js";                           только ради выполнения
const mod = await import("./heavy.js");        динамически, в любой момент
```

Четыре свойства, из которых следует всё остальное:

1. **выполняется один раз.** Сколько бы файлов ни импортировали модуль, тело
   выполнится однажды; все получат одни и те же значения;
2. **импорты поднимаются.** Зависимости выполняются раньше тела
   импортирующего, независимо от места строки `import`;
3. **связь живая.** Импортированное имя — не копия значения: если
   экспортирующий модуль его переприсвоит, импортирующий увидит новое;
4. **строгий режим и своя область.** Ничего не утекает в глобальное
   пространство.

Из первого следует практическое: **изменяемая переменная на уровне модуля —
это глобальная переменная.** Она переживает всё, включая повторный импорт.

## 2. Циклические импорты

```js
// a.js
import { b } from "./b.js";
export const a = () => b();

// b.js
import { a } from "./a.js";
export const b = () => a();
```

Это работает — пока обращение происходит **внутри функции**, то есть после
того, как оба модуля выполнились. Обращение на верхнем уровне даст
`ReferenceError`: имя ещё в «временной мёртвой зоне».

Цикл почти всегда означает, что деление прошло не по тому шву.

## 3. Состояние и его преобразования

```js
export function withChalk(state, id) {
  return {
    ...state,
    entries: state.entries.map((e) => (e.id === id ? { ...e, chalk: !e.chalk } : e)),
  };
}
```

Три свойства такой функции:

- **не меняет вход.** Прежнее состояние остаётся целым;
- **зависит только от входа.** Один и тот же вход даёт один и тот же выход;
- **ничего не знает про страницу.** Проверить можно, не открывая браузера.

Что это даёт на практике: отмена (прежнее состояние цело), сравнение («что
именно поменялось»), проверка без дерева и возможность отрисовать одно
состояние двумя способами — на странице и, скажем, в печати.

Расплата — копирование. `{ ...state }` копирует **верхний уровень**; вложенное
приходится копировать явно. На шести записях это бесплатно; на больших объёмах
берут либо структурное разделение (`structuredClone` для копии, библиотеки
неизменяемых структур), либо сознательно отказываются — по измерению, а не по
вкусу.

## 4. Что хранят и что вычисляют

| Хранится | Вычисляется |
|---|---|
| записи, как пришли | счёт по состояниям |
| нынешний отбор | какие записи показывать |
| что помечено мелом | последняя принятая |

Правило: **хранится то, что пришло; вычисляется то, что из него следует.**
Хранимый счёт — вторая правда; он разойдётся с записями в тот день, когда
запись добавят мимо него.

Здесь же причина, по которой отбор ничего не выбрасывает: отбор — это взгляд,
а не изменение. Выбросил — «показать все» возвращать нечего.

## 5. Один путь

```
событие → новое состояние → отрисовка
```

Три запрета, которые из этого следуют:

- обработчик не трогает дерево (иначе следующая отрисовка это затрёт);
- отрисовка не принимает решений (иначе решений два места);
- состояние не знает про дерево (иначе его нельзя проверить и нельзя
  отрисовать иначе).

Проверяется это одним движением: испортить дерево руками, позвать отрисовку и
посмотреть, вернулось ли оно к состоянию.

## 6. Отрисовка приводит

```js
// ✔ приводит
node.hidden = !visible.has(item.id);
setFlag(node, "chalk", item.chalk ? "yes" : null);

// ✘ дописывает
if (!visible.has(item.id)) node.hidden = true;
if (item.chalk) node.dataset.chalk = "yes";
```

Второй вариант умеет включать и не умеет выключать. Пока состояние только
растёт, разницы нет; в первый же раз, когда что-то отменили, на странице
остаётся прошлое.

Отрисовка при этом **не пересоздаёт** узлы (`s03e02`): она находит их по
`data-id` и меняет то, что изменилось. Это и есть разница между «перерисовать»
и «перестроить».

## 7. Когда состояния становится много

Приёмы, которые появляются дальше по мере роста, — в порядке усложнения:

```js
// 1. одна переменная и функция обновления — то, что здесь
let state = read(root);
const update = (next) => { state = next; render(root, state); };

// 2. подписчики: кто-то ещё хочет знать об изменении
const listeners = new Set();
const update = (next) => { state = next; for (const f of listeners) f(state); };

// 3. свои события: подписчик не знает про источник
document.dispatchEvent(new CustomEvent("register:changed", { detail: state }));
```

Дальше начинаются готовые решения, и все они — та же схема с добавленным
удобством. Понимать её стоит до того, как брать библиотеку, потому что
отлаживать придётся её же.

## 8. Отладка

Состояние в одном месте отлаживается вопросом «а что в нём сейчас»:

```js
const update = (next) => {
  console.debug("состояние", state, "→", next);
  state = next;
  render(root, state);
};
```

Пока состояние было в дереве, такой вопрос задать было некому: ответ
приходилось восстанавливать по внешнему виду.

## 9. Где это в Rails

```js
export default class extends Controller {
  static values = { filter: String }
  static targets = ["entry"]

  filterValueChanged() { this.render() }
  chalk(event) { this.filterValue = event.params.state }
}
```

Stimulus называет состояние `values`, а его изменение само вызывает
`…ValueChanged`. Тот же один путь, объявлением.

Этажом выше то же делает Turbo: настоящее состояние живёт на сервере, страница
— его отрисовка, Turbo Stream — сообщение «изменилось, вот новый кусок».
Сезоны 4 и 5 — про то, где этому состоянию жить по-настоящему, и там
выяснится, что половина сложности переднего края берётся от попытки хранить
состояние дважды.
