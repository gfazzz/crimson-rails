## Обстановка

На новой доске восемьдесят шторок и один барабан: барабан помнит, что на
каждом пути, шторки показывают то, что он помнит. Не наоборот.

В восемьдесят седьмом на Шестой авеню было наоборот, и состав ушёл на занятый
путь.

## Приказ

Разделить модуль на три файла и связать их. Разметка не меняется.

```
artifacts/state.js       что есть              ни одного обращения к странице
artifacts/render.js      как это выглядит      ни одного решения
artifacts/telegraph.js   кто кому что говорит  ни того ни другого
```

## `state.js`

Ни одна функция не получает узла — кроме `read`, и та только читает.
Ни одна **не меняет** то, что ей дали: возвращается новое состояние.

| Функция | Что делает |
|---|---|
| `register({ entries, filter })` | собрать состояние |
| `entry({ id, state, hand, text, chalk })` | одна запись |
| `read(root)` | прочитать начальное состояние из разметки |
| `withFilter(state, filter)` | новый отбор; записи не трогает |
| `withChalk(state, id)` | переключить мел у одной записи |
| `withEntry(state, fresh)` | добавить запись в конец |
| `shown(state)` | какие записи показывать при нынешнем отборе |
| `counts(state)` | сколько записей в каждом состоянии |
| `lastHand(state)` | почерк последней записи, **у которой он есть** |

Отбор — это взгляд на записи, а не изменение записей: `withFilter` ничего не
выбрасывает. Счёт и «последняя принятая» вычисляются, а не хранятся.

## `render.js`

Одна вынесенная функция: `render(root, state)`. Она **приводит** дерево к
состоянию — ставит и снимает, показывает и прячет, пишет и стирает.

Что отрисовывается:

- сводка: по строке на состояние (`data-tally` = `sent`/`held`/`failed`) плюс
  строка `hand` про последний почерк;
- у каждой записи: `data-state` из состояния, `hidden` по отбору,
  `data-chalk`, `data-unsigned` и видимая пометка «почерка нет»;
- запись, которая есть в состоянии и которой нет на странице, — создаётся;
- записи не пересоздаются: их находят по `data-id` (`s03e02`).

## `telegraph.js`

Точка входа. Держит состояние в одной переменной, меняет его в одном месте и
после каждого изменения зовёт отрисовку. Проверка формы из `s03e04` остаётся
здесь: она не про состояние журнала.

```
событие → новое состояние → отрисовка
```

Обратного пути нет: обработчик не трогает дерево, отрисовка не принимает
решений.

## Критерии приёмки

**Разделение**

- [ ] `state.js` импортируется и отдаёт `read`, `withFilter`, `withChalk`,
      `counts`.
- [ ] `render.js` импортируется и отдаёт `render`.
- [ ] `withChalk`, `withFilter`, `counts` работают, не получая узла.
- [ ] `read(root)` собирает шесть записей с их `id`, состоянием, почерком и
      текстом; у четвёртой почерк `null`.

**Неизменяемость**

- [ ] `withChalk` не меняет переданное состояние и возвращает новое.
- [ ] Мел — переключатель: дважды подряд возвращает как было.
- [ ] `withFilter` меняет только отбор; исходное состояние цело.
- [ ] Отбор ничего не выбрасывает: записи остаются все, `shown` показывает
      подходящие.
- [ ] `counts` и `lastHand` считают по состоянию.

**Отрисовка**

- [ ] Мел, снятый в состоянии, исчезает со страницы.
- [ ] Пометка «почерка нет» уходит, когда почерк появился.
- [ ] Испорченное руками дерево возвращается к состоянию.
- [ ] Отрисовать дважды — то же, что один раз.
- [ ] Записи не пересоздаются.
- [ ] Запись, добавленная в состояние, появляется на странице со своим
      состоянием и текстом, и сводка её считает.

**Связь**

- [ ] Нажатие ставит и снимает мел.
- [ ] Отбор работает и **переживает следующую отрисовку**.
- [ ] Решение принимается по состоянию: испорченный атрибут в дереве на него
      не влияет.
- [ ] Прежние редакции целы: `data-script`, сокрытие, сводка, пометка,
      `noValidate`, живая область, отмена отправки отбора, ноль ошибок.
- [ ] Второй запуск не удваивает ни страницу, ни обработчики.

- [ ] `make test` → двадцать одна зелёная проверка.

## Подводный камень

Отрисовка, которая умеет включать и не умеет выключать, проходит половину
проверок. Ловится она так: сними мел в состоянии и перерисуй — на странице он
останется.

Второй: отбор, сделанный прямо в дереве, тоже проходит первую проверку. Ловится
следующей отрисовкой — она о нём не знает и вернёт все записи.

Третий: не заводи изменяемую переменную состояния **внутри `state.js`**. Модуль
выполняется один раз на процесс; такая переменная — глобальная, и две страницы
будут спорить за неё.
