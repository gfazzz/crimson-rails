## Чему ты научишься

- Разделять модуль на файлы и связывать их `import`/`export`.
- Держать состояние в одном месте и менять его, не меняя прежнего.
- Писать отрисовку, которая **приводит** страницу к состоянию.
- Проверять логику, не открывая страницы.
- Приёму, который дороже синтаксиса: **дерево — отражение, а не источник.**
  Когда они спорят, прав источник, и это решается заранее, а не в отладчике.

Подробнее — в [`theory.md`](theory.md).

## Теория: один путь

### Куда уезжает состояние, если за ним не следить

В четвёртой редакции состояние журнала лежало в трёх местах сразу:

```
мел    → атрибут data-chalk на строке
отбор  → hidden у строк
счёт   → текст в сводке
```

Пока страница одна, это работает. Ломается в тот день, когда состояние
приходит не из разметки: по проводу (`s03e07`), из адреса (`s03e10`). Спросить
«а что у нас сейчас» становится не у кого — надо обойти дерево и восстановить
ответ по внешнему виду.

### Один путь

```
событие → новое состояние → отрисовка
```

И никакого обратного. Обработчик не трогает дерево; отрисовка не принимает
решений; состояние не знает, что существует страница.

Проверяется это просто: если испортить дерево руками и позвать отрисовку, оно
обязано вернуться к состоянию.

### Три файла

```
state.js       что есть              ни одного обращения к странице
render.js      как это выглядит      ни одного решения
telegraph.js   кто кому что говорит  ни того ни другого
```

Деление не по размеру, а по причине изменения: правила меняются от того, что
решили в конторе, вид — от того, что решил художник, связь — от того, что
появилось новое событие.

### Модули: `import` и `export`

```js
export function withChalk(state, id) { … }      именованный
export default function render() { … }          по умолчанию — один на файл

import { withChalk, counts } from "./state.js";
import { withChalk as toggle } from "./state.js";
import * as state from "./state.js";
```

Что стоит знать сразу: импорты поднимаются (зависимость выполняется раньше);
модуль выполняется **один раз**, сколько бы файлов его ни импортировали; связь
живая — импортированное имя не копия; путь пишется с расширением, потому что
голое имя браузер без карты импортов не поймёт (`s03e01`).

Отсюда практическое: **изменяемое состояние на уровне модуля — это глобальная
переменная.** Поэтому состояние живёт в точке входа, а `state.js` только его
преобразует.

### Не менять, а заменять

```js
// ✘ меняет то, что дали
export function withChalk(state, id) {
  state.entries.find((e) => e.id === id).chalk = true;
  return state;
}

// ✔ возвращает новое
export function withChalk(state, id) {
  return {
    ...state,
    entries: state.entries.map((e) => (e.id === id ? { ...e, chalk: !e.chalk } : e)),
  };
}
```

Зачем: пока прежнее состояние цело, можно сравнить, отменить и понять, что
поменялось. Расплата — копирование: на шести записях она бесплатна, на шести
тысячах о ней думают отдельно и решают по измерению, а не по вкусу.

### Отбор — это взгляд, а не изменение

```js
export function shown(state) {
  return state.filter === "" ? state.entries : state.entries.filter((e) => e.state === state.filter);
}
```

Отбор **не выбрасывает** записи: иначе «показать все» возвращать будет нечего.
Правило общее — хранится то, что пришло, вычисляется то, что из него следует:
счёт, отбор, «последняя принятая».

### Отрисовка приводит, а не дописывает

```js
setFlag(node, "chalk", item.chalk ? "yes" : null);   // ✔ и поставит, и снимет
if (item.chalk) node.dataset.chalk = "yes";          // ✘ только поставит
```

Самая частая ошибка серии — отрисовка, умеющая включать и не умеющая
выключать: в первый же раз, когда что-то отменили, на странице остаётся
прошлое.

### Где это в Rails

```js
// app/javascript/controllers/register_controller.js
export default class extends Controller {
  static values = { filter: String }
  filterValueChanged() { this.render() }
}
```

Stimulus называет это `values`: состояние объявлено, его изменение вызывает
отрисовку. Тот же один путь, только объявлением. Этажом выше так же устроен
Turbo: состояние живёт на сервере, страница — его отрисовка, Turbo Stream —
сообщение «состояние изменилось, вот новый кусок».

**1.** ADA: «Мел хранится в `data-chalk` на строке. Что сломается, когда
записи начнут приходить по проводу?»

<details><summary>Ответ</summary>

Всё, что связано с отрисовкой. Пришли новые записи — надо перерисовать список;
перерисовали — мел стёрся, потому что он был в дереве и больше нигде.

Обойти это можно, вычитывая мел из дерева перед отрисовкой и возвращая после.
Так и делают — и получают две копии состояния, которые расходятся.
</details>

**2.** ADA: «`withFilter` меняет `state.filter` и возвращает то же состояние.
Что на этом теряется?»

<details><summary>Ответ</summary>

Возможность узнать, что было. Сравнить не с чем: старое состояние и новое —
один и тот же объект.

Практически это ловится не в философии, а в отладке: «страница показывает не
то» превращается в вопрос «а что в состоянии было до этого», и ответа нет.
</details>

**3.** ADA: «Отрисовка ставит `data-chalk`, когда мел есть. Что не так?»

<details><summary>Ответ</summary>

Она не снимает его, когда мела нет. Отрисовка обязана **приводить** страницу
к состоянию: ставить и снимать, показывать и прятать, писать и стирать.

Проверить это можно, не думая: испортить дерево руками, позвать отрисовку и
посмотреть, вернулось ли оно к состоянию.
</details>

## Разбор типичных ошибок

1. **Состояние меняется на месте.** Сравнить не с чем, отменить нечем.
2. **Отбор выбрасывает записи.** «Показать все» возвращать нечего.
3. **Счёт хранится, а не вычисляется.** Две правды вместо одной.
4. **Состояние спрашивает дерево.** Проверить его теперь можно только на
   странице.
5. **Изменяемое состояние на уровне модуля.** Это глобальная переменная.
6. **Отрисовка умеет включать и не умеет выключать.** На странице остаётся
   прошлое.
7. **Отрисовка пересобирает список.** Записи пересозданы (`s03e02`).
8. **Отрисовка принимает решения.** Их два места, и они разойдутся.
9. **Обработчик трогает дерево.** Следующая отрисовка это затрёт.
10. **Отбор живёт в дереве.** Следующая отрисовка о нём не знает.

## Debriefing

Три файла. Состояние не знает про страницу, отрисовка не знает про события,
точка входа не знает ни правил, ни вида.

Ты проверяешь по-бауэровски: ставишь мел на строку, которой в барабане нет, и
зовёшь отрисовку. Мел исчезает. Кейл просит показать ещё раз.

— А теперь наоборот, — говорит Кейл. — Уберите строку из барабана. Из вашего
этого. Из памяти.

Ты убираешь четвёртую запись из состояния и перерисовываешь. Строка с 59-й
улицы остаётся на странице.

Она там, потому что была в разметке — и отрисовка её не создавала, а значит и
не убирает. В барабане её нет. На доске она есть.

— Вот, — говорит Кейл. — Ровно это и было в восемьдесят седьмом.
