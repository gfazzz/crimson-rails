## Обстановка

Контора требует: отбили — пост квитирует; нет квитанции — запись
недействительна. Квитанция приходит когда как: с 14-й сразу, со 129-й — пока
сходят на пост, а иногда не приходит вовсе.

У Дарнелл три столбца: отбито, квитировано, отказано. Два ответа и одно
молчание — и срок на молчание она назначает себе сама.

## Приказ

Написать `artifacts/office.js` — разговор с линией — и связать его с журналом.
`wire.js` дан готовым и изменению не подлежит: в этой серии линия поддельная и
отвечает по расписанию, чтобы поведение было одинаковым от прогона к прогону.
В `s03e07` её заменит настоящий провод, и `office.js` от этого не поменяется.

## `office.js`

### `LineError`

Своя ошибка с номером записи (`id`, строкой) и исходной причиной (`cause`).
Пойманная ошибка без записи, к которой она относится, бесполезна.

### `acknowledge(entry, wire, { timeout })`

Обещание подтверждения одной записи. Четыре случая:

| Линия | Обещание |
|---|---|
| ответила | разрешается `{ id, state: "sent", hand }` |
| отказала | отклоняется `LineError` с причиной внутри |
| молчит | отклоняется по сроку |
| бросила исключение | тоже отклоняется, а не роняет всё |

Срок ограничивает **ожидание**, а не линию: она продолжит работать и однажды
ответит — уже никому. Поздний ответ ничего не меняет и ничего не роняет.

### `acknowledgeAll(entries, wire, { timeout, onSettled })`

- спрашивает **параллельно**, а не по очереди: шесть постов по две секунды —
  это две секунды, а не двенадцать;
- один отказ не отменяет остальных: нужен отчёт по каждой записи, а не первый
  провал;
- о каждом ответе сообщает **сразу** через `onSettled({ id, state, reason })`
  — иначе один молчащий пост задержит весь журнал на весь срок;
- про каждую запись сообщает **один раз**;
- возвращает `{ sent, failed }` в порядке **записей**, а не ответов;
- на пустом списке возвращает пустой отчёт и на линию не ходит.

## Критерии приёмки

- [ ] `acknowledge` возвращает обещание.
- [ ] Ответ линии даёт `{ id, state: "sent" }`.
- [ ] Отказ даёт `LineError` с номером записи, сообщением линии и `cause`.
- [ ] Молчание даёт отказ по сроку — заметно раньше, чем через вчетверо
      больший срок.
- [ ] Поздний ответ после срока ничего не ломает и не роняет.
- [ ] Исключение внутри линии становится отказом обещания.
- [ ] Четыре записи по 80 мс укладываются меньше чем в 240 мс.
- [ ] Один отказ из четырёх даёт отчёт из трёх удач и одного провала с
      причиной.
- [ ] Отчёт собран в порядке записей, даже когда линия отвечает вразнобой.
- [ ] Через 120 мс из четырёх записей (одна молчит) применено не меньше трёх
      ответов, и ни об одной не сообщено дважды.
- [ ] Пустой список: пустой отчёт, на линию не ходили.
- [ ] Сразу после загрузки есть записи в состоянии `sending` с
      `aria-busy="true"`.
- [ ] Через 150 мс запись №1 подтверждена, а №3 ещё ждёт.
- [ ] Через 700 мс: 1, 2, 4 — переданы; 3, 5, 6 — не прошли; занятых не
      осталось.
- [ ] Итог смены сообщён живой областью смены и содержит число.
- [ ] Страница не получила ни одной ошибки.
- [ ] Прежние редакции целы: пометка, сводка, `noValidate`, мел, отбор по
      состоянию.
- [ ] `make test` → семнадцать зелёных проверок.

## Подводный камень

`for (const entry of entries) await acknowledge(…)` проходит все проверки,
кроме одной — той, что меряет время. Ошибка незаметна на двух записях и
убийственна на двадцати.

Второй: `Promise.all` вместо `allSettled` выглядит короче и теряет пять
ответов из-за одного отказа.

Третий: `confirmShift()` без `.catch` — отказ, о котором никто не узнает. В
браузере он молча уедет в `unhandledrejection`.
