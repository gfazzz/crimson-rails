## Чему ты научишься

- Читать и писать обещания: `then`, `catch`, `async`/`await`.
- Различать три исхода и назначать срок, превращающий третий во второй.
- Спрашивать многих сразу и собирать отчёт, не роняя всё из-за одного отказа.
- Приёму, который дороже синтаксиса: **молчание — не ответ.** «Ничего не
  случилось» выглядит как «всё хорошо» и им не является.

Подробнее — в [`theory.md`](theory.md).

## Теория: время

### Три исхода, а не два

```
обещание ──┬─ разрешилось  (fulfilled)  пост квитировал
           ├─ отклонилось  (rejected)   пост отказал
           └─ так и висит  (pending)    пост молчит
```

Третий исход — не ошибка: `catch` не сработает, в консоли пусто, обещание
просто никогда не кончится. Поэтому срок назначают снаружи — **ограничивают не
линию, а ожидание.**

### Чтение

```js
wire(entry).then(onAnswer).catch(onRefusal).finally(always);

try { const answer = await wire(entry); } catch (error) { … } finally { … }
```

`await` — то же самое сверху вниз. Он не «останавливает браузер»: он
приостанавливает **эту функцию**, а страница живёт дальше.

Два правила, которые нарушают чаще всего: `await` работает только внутри
`async`-функции (и на верхнем уровне модуля), а `async`-функция **всегда**
возвращает обещание — даже если внутри нет ни одного `await`.

### Отказ, который никто не ловит

```js
confirmShift();                  // ✘ отказ всплывёт в никуда
confirmShift().catch(report);    // ✔
```

Отклонённое обещание без `catch` и без `try` — ошибка, о которой узнают
последними: в браузере она попадает в `unhandledrejection`, в Node роняет
процесс, и в обоих случаях не там, где причина.

### Срок

```js
const timer = setTimeout(() => reject(new LineError("не ответила вовремя")), timeout);
…
clearTimeout(timer);
```

Чего срок **не** делает: не отменяет запрос — линия продолжает работать и
однажды ответит уже никому (отмена появится в `s03e07`). Что делает:
превращает третий исход во второй, и с отказом уже можно что-то сделать.

### Своя ошибка

```js
export class LineError extends Error {
  constructor(message, { id, cause } = {}) {
    super(message, { cause });
    this.name = "LineError";
    this.id = id === undefined ? null : String(id);
  }
}
```

Ошибка без записи, к которой она относится, бесполезна: «не ответила» — а
кто? `cause` хранит исходную, не заслоняя её.

### Восемь разом

```js
await Promise.all(promises);        первый отказ отменяет всё
await Promise.allSettled(promises); отчёт по каждому
await Promise.race(promises);       первый любой
await Promise.any(promises);        первый успешный
```

Ошибка, которую делают все, — спрашивать по очереди:

```js
for (const entry of entries) await acknowledge(entry, wire);   // ✘ сумма сроков
await Promise.allSettled(entries.map((e) => acknowledge(e, wire)));  // ✔ максимум
```

Шесть постов по две секунды: двенадцать против двух. Это и есть квадруплекс
Эдисона — один провод, но ждать можно всем сразу. `Promise.all` здесь не
годится: при первом отказе он бросает всё.

### Отчёт готов, когда ответил последний

У `allSettled` есть цена: он ждёт всех, и один молчащий пост задержит журнал
на весь срок. Лечится это не заменой `allSettled`, а тем, что о каждом ответе
сообщают **сразу**:

```js
entries.map(async (entry) => {
  try {
    const answer = await acknowledge(entry, wire, options);
    onSettled({ id: answer.id, state: "sent" });
    return answer;
  } catch (error) {
    onSettled({ id: String(entry.id), state: "failed", reason: error.message });
    throw error;
  }
});
```

Быстрые записи меняются на глазах, медленные ждут срока, а отчёт по-прежнему
собирается в конце — для тех, кому нужен итог.

### Ожидание видно и слышно

Пока ждём, запись не «передана» и не «не прошла». `sending` — не украшение:
журнал, показывающий в этот промежуток старое, врёт. Ожидание помечают
`aria-busy="true"` и снимают пометку по ответу.

### Где это в Rails

Turbo делает это само: на время запроса вешает `aria-busy` и полосу хода, а
события `turbo:submit-start` / `turbo:submit-end` — те же три исхода, только
объявленные. В контроллере Stimulus то же пишется руками: `await` внутри
`async`-действия, снятие пометки в `finally`.

**1.** ADA: «Обещание не разрешилось и не отклонилось. Что покажет `catch`?»

<details><summary>Ответ</summary>

Ничего: обещание просто висит, `catch` ждёт отказа, а отказа нет. Поэтому
третий исход — единственный, который создают сами: назначают срок и превращают
молчание в отказ. Иначе запись останется «передаётся» до перезагрузки, и все
будут считать, что она в порядке.
</details>

**2.** ADA: «Шесть записей, по две секунды каждая. `for … await` или
`allSettled`?»

<details><summary>Ответ</summary>

`allSettled` — две секунды против двенадцати: `for … await` складывает сроки.
Ошибка незаметна на двух записях и убийственна на двадцати, и ловится не
глазами, а измерением — как в проверке этой серии.
</details>

**3.** ADA: «`Promise.all` вместо `allSettled`. Один пост отказал. Что в
отчёте?»

<details><summary>Ответ</summary>

Ничего: `all` отклоняется при первом отказе, и результаты остальных теряются
— хотя пять постов ответили. `all` уместен там, где без любого из ответов
дальше нельзя; отчёт по смене — обратный случай.
</details>

## Разбор типичных ошибок

1. **Нет срока ожидания.** Молчание никогда не становится отказом.
2. **Чужая ошибка вместо своей** или потерянная причина. Непонятно, к какой
   записи она относится и что случилось на самом деле.
3. **Исключение внутри линии роняет всё.** Оно тоже должно стать отказом.
4. **Спрашивают по очереди.** Сумма сроков вместо максимума.
5. **`Promise.all` вместо `allSettled`.** Один отказ уносит пять ответов.
6. **Отчёт в порядке ответов.** Линия отвечает как придётся.
7. **Ответы применяются только в конце.** Один молчащий держит весь журнал.
8. **Нет промежуточного состояния.** Журнал показывает старое и врёт.
9. **Отказ без `catch`.** Ошибка, о которой узнают последними.
