## Обстановка

На линии восемь постов и один аппарат. Провод идёт петлёй: жмёт кто угодно —
щёлкает у всех. Кому адресовано, определяют по позывному, а не по тому, к
какому столбу подключились.

Новый пост на такой линии — это не новый провод. Это новый позывной.

## Приказ

Довести `artifacts/telegraph.js` до третьей редакции. Разметка не меняется.

## Отбор на месте

Без скрипта форма отбора уходит на сервер и страница перезагружается. Со
скриптом отбор отрабатывает здесь же:

- изменение значения в списке состояний прячет записи, у которых `data-state`
  не тот;
- пустое значение показывает весь журнал;
- записи **прячутся**, а не удаляются: журнал за смену — это всё, что за смену
  было;
- отправка формы отбора отменяется — она уже отработала. Иначе Enter в списке
  перезагрузит страницу и сотрёт всё, что на ней помечено.

Форму подачи записи не трогать. Заменить её отправку пока нечем — это `s03e04`.

## Меловые пометки

Нажатие по записи ставит `data-chalk="yes"`, повторное — снимает. Свод правил
обводит помеченную запись пунктиром; ничего дописывать в стили не нужно.

Требования к обработчику:

- **один слушатель на весь журнал**, а не по одному на запись;
- запись находится от места нажатия вверх по дереву: нажали по абзацу внутри —
  значит нажали по записи;
- нажатие мимо записей ничего не делает и ничего не роняет;
- нажатие по ссылке, кнопке или полю внутри записи мел **не** ставит: у них
  своё дело;
- запись, пришедшая в журнал после загрузки, работает сама собой.

## Слушатель тоже вешается дважды

Второе выполнение модуля не должно давать вторую пару обработчиков: иначе
нажатие сработает дважды и отменит само себя. Приём тот же, что в `s03e02`, —
проверить пометку перед тем, как вешать.

## Критерии приёмки

- [ ] Выбор состояния прячет записи с другим `data-state`; пустое значение
      показывает все шесть.
- [ ] Число записей в журнале при отборе не меняется.
- [ ] Отправка формы отбора отменяется.
- [ ] Отправка формы подачи **не** отменяется.
- [ ] На отдельных записях нет слушателей нажатия.
- [ ] Слушателей нажатия на странице не больше трёх.
- [ ] Запись, добавленная после работы модуля, откликается на нажатие.
- [ ] Отбор видит записи, пришедшие после загрузки, — в обе стороны.
- [ ] Нажатие ставит мел, второе снимает.
- [ ] Нажатие по вложенному узлу считается нажатием по записи.
- [ ] Нажатие вне журнала не ставит мел и не роняет обработчик.
- [ ] Нажатие по ссылке внутри записи мел не ставит.
- [ ] Мел переживает отбор туда и обратно.
- [ ] Прежние редакции целы: сводка, пометка записи без почерка,
      `data-script="on"`, формы со своими `action`/`method`.
- [ ] Второй запуск модуля не меняет страницу и не удваивает обработчики.
- [ ] `make test` → семнадцать зелёных проверок.

## Подводный камень

Проверка «запись, которой не было при загрузке, работает» — главная в серии и
единственная, которую нельзя пройти случайно. Цикл с `addEventListener` по
записям пройдёт все остальные проверки и споткнётся об эту.

Второй: `event.target` — это узел, на котором нажатие **началось**. В записи
есть вложенные абзацы, и нажимают обычно по ним. Сравнение `target` со списком
записей даст ложь в большинстве случаев; нужен `closest`.

Третий: слушателей считает проверка. Не «сколько строк с `addEventListener`» —
сколько их зарегистрировано во время работы. Цикл по записям даст шесть, и
это видно.
