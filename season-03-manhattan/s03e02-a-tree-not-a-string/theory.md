# Теория — s03e02

## 1. Разметка и дерево — разные вещи

Браузер читает разметку один раз и строит из неё дерево объектов. Дальше живёт
дерево. Исходной разметки больше нет: `innerHTML` не возвращает написанное, он
**печатает нынешнее дерево заново** — с нормализованными кавычками, без
комментариев форматирования, с закрытыми тегами.

Проверить это можно в одну строку:

```js
document.body.innerHTML !== исходный_текст_страницы;   // почти всегда true
```

Отсюда главное: у узла есть **тождество**. Два узла с одинаковой разметкой —
разные вещи.

## 2. Что живёт на узле и не видно в разметке

| Что | Пропадает при пересоздании |
|---|---|
| слушатели событий | да |
| фокус | да |
| выделение текста | да |
| положение прокрутки внутри узла | да |
| `open` у `<details>`, состояние `<dialog>` | да |
| введённое в поле, но не отправленное | да |
| проигрывание `<video>`, `<audio>` | да |
| анимация и переход в середине | да |
| собственные свойства, которые повесил код | да |

Ничего из перечисленного в `innerHTML` не попадает. Поэтому

```js
list.innerHTML = list.innerHTML;
```

выглядит как «ничего не делать», а на деле заменяет все узлы списка.

## 3. Найти

```js
document.getElementById("entries")          быстрее всех, только по id
document.querySelector("#entries li")       первый подходящий
document.querySelectorAll("li[data-id]")    все, статическим списком
document.getElementsByClassName("hand")     живой список — меняется сам
node.closest("li[data-id]")                 ближайший предок, включая себя
node.matches("[data-state='held']")         подходит ли узел под селектор
node.contains(other)                        внутри ли
```

Разница между `querySelectorAll` и `getElementsBy*` заметна ровно один раз —
когда по такому списку идут и одновременно его меняют: первый статический,
второй живой, и цикл по второму может не кончиться.

`closest` и `matches` — то, на чём держится делегирование (`s03e03`).

## 4. Создать и разместить

```js
const item = document.createElement("li");
item.dataset.tally = "sent";
item.textContent = "переданных: 4";

list.append(item);        внутрь, в конец
list.prepend(item);       внутрь, в начало
list.before(item);        рядом, перед
list.after(item);         рядом, после
old.replaceWith(item);    вместо
list.replaceChildren();   опустошить
list.replaceChildren(a, b);  заменить содержимое целиком
```

`append` принимает и узлы, и строки, и несколько сразу — в отличие от старого
`appendChild`, который брал один узел.

Когда узлов много, их собирают в `DocumentFragment` и вставляют одним
движением: дерево перестраивается один раз, а не по разу на узел.

```js
const batch = document.createDocumentFragment();
for (const row of rows) batch.append(makeRow(row));
list.append(batch);
```

## 5. `textContent`, `innerText`, `innerHTML`

```js
node.textContent   весь текст, включая спрятанный; не считает раскладку
node.innerText     видимый текст; заставляет браузер посчитать раскладку
node.innerHTML     разметка; при записи — исполняется
```

`innerText` кажется удобнее, пока не выясняется, что чтение его заставляет
браузер пересчитать раскладку страницы — в цикле это заметно.

`innerHTML` при записи **разбирает строку как разметку**. Это не оформление, а
передача решения: что окажется на странице, решает автор строки. Если строка
пришла из данных — решает автор данных (`s03e08`).

Правило: данные кладутся `textContent`; разметка строится узлами.

Безопасное исключение для случаев, когда разметку всё-таки надо собрать из
доверенного куска, — `<template>` и `cloneNode` (`s03e08`).

## 6. Данные, вид, видимость

```js
entry.dataset.state = "held";        // data-state="held"
entry.dataset.id                     // строка, всегда
delete entry.dataset.unsigned;       // снять атрибут

entry.classList.add("selected");
entry.classList.toggle("selected", условие);
entry.classList.contains("selected");

entry.hidden = true;                 // атрибут hidden
```

`dataset` — чтение и запись атрибутов `data-*`. Значения всегда строки: `"0"`
истинно, `Number(entry.dataset.count)` обязателен.

Разделение простое: **данные — в `data-*`, вид — в классах.** Состояние
записи приходит извне и по нему считают, поэтому оно данные. Подсветка
выбранной строки — вид.

Свод правил из сезона 2 стилизует журнал по `data-state`, а не по классу, и это
не прихоть: так у состояния одно место, а не два, которые рассинхронизируются.

## 7. Найти или создать

```js
function need(selector, make, root = document) {
  return root.querySelector(selector) ?? make();
}
```

Единственная форма отрисовки, которую можно выполнить дважды. «Создать и
добавить» при втором выполнении даёт второе, и повод для второго выполнения
найдётся: возврат страницы из кеша, повторное подключение контроллера, горячая
перезагрузка при разработке.

То же правило в обратную сторону: **снимать то, что перестало быть верным.**
Отрисовка приводит страницу к нынешнему состоянию данных — а не дописывает к
прошлому. Пометка, которую поставили и не сняли, живёт дольше причины.

## 8. Обход дерева

```js
node.children          только элементы
node.childNodes        включая текстовые узлы и комментарии
node.parentElement
node.nextElementSibling / previousElementSibling
node.compareDocumentPosition(other)   кто раньше в документе
```

Разница между `children` и `childNodes` ловит новичков ежедневно: переносы
строк в разметке — тоже узлы.

`compareDocumentPosition` отвечает на вопрос «что раньше»: результат — набор
битов, где `4` значит «other следует за node».

## 9. Где это в Rails

```erb
<%= turbo_stream.replace "tally" do %>…<% end %>
<%= turbo_stream.update "entry_4" do %>…<% end %>
<%= turbo_stream.append "entries" do %>…<% end %>
```

Turbo Stream меняет **названный кусок** страницы: `replace` заменяет узел,
`update` — его содержимое, `append` добавляет. Потому у каждого куска и есть
`id`.

Это та же доска Бауэра: щёлкает одна шторка. И та же опасность: `replace`
контейнера со всем содержимым закроет открытые `<details>`, потеряет фокус и
сотрёт наполовину введённый текст — ровно как `innerHTML` здесь. В Turbo для
этого есть `data-turbo-permanent`: пометка «этот узел не заменять».
