# С чего начать

## Что нужно поставить

**Ruby 3.3 или новее.** Больше в первом сезоне ничего: минитест входит в
поставку Ruby, внешних гемов нет, базы и сети не нужно.

```bash
ruby -v        # ruby 3.3.x, 3.4.x или 4.0.x
```

Курс проверяется на трёх ветках Ruby, которые сейчас поддерживаются: 3.3, 3.4
и 4.0. Старше 3.3 не пойдут сезоны на Rails: их гемы требуют 3.3.

Чем ветки отличаются на глаз — только видом сообщений. Ruby 3.4 и новее
пишет `undefined method 'call' for nil` и хеш `{road: "NTK"}`; 3.3 —
`` undefined method `call' for nil `` и `{:road=>"NTK"}`. Тексты курса
приводят вид 3.4. И минитест разных версий по-разному считает
**утверждения** (`assertions`), так что это число от машины к машине
плавает; число **проверок** (`runs`) — нет, и зелёными они обязаны быть
везде.

Если версия старше или Ruby не стоит вовсе:

| Система | Как |
|---|---|
| macOS | `brew install ruby` — но лучше менеджер версий: `brew install rbenv`, затем `rbenv install -l` и `rbenv install` с последней версией 3.4 или 4.0 |
| Linux | `mise use -g ruby@3.4` или `rbenv install` с последней версией из `rbenv install -l` |
| Windows | [RubyInstaller](https://rubyinstaller.org) с DevKit, либо WSL2 и путь для Linux |

Системный Ruby в macOS (`/usr/bin/ruby`) устарел — на нём курс не пойдёт.

## Где это проходить

Курс рассчитан на **Cursor**: код, README и терминал видны одновременно, а
ADA — это чат редактора, открытый рядом.

Режим чата — **`Ask`**, не `Agent`. Разница принципиальная: `Agent` напишет
решение сам, и серия будет потеряна. Правила для помощника лежат в
[`.cursorrules`](../.cursorrules), редактор подхватит их сам.

Годится и VS Code с любым ИИ-помощником, и обычный редактор с терминалом —
всё, кроме режима, в котором помощник пишет код за тебя.

## Первый запуск

```bash
git clone https://github.com/gfazzz/crimson-rails.git
cd crimson-rails
make test SERIES=s01e01
```

Первый прогон идёт по эталону — так репозиторий всегда зелёный. Увидишь:

```
Источник: s01e01-one-pass/solution/ledger.rb
(артефакта нет — проверяю эталон)
13 runs, 23 assertions, 0 failures, 0 errors, 0 skips
```

(Число `assertions` у тебя может отличаться на одно-два — зависит от версии
минитеста; `runs` и нули — нет.)

## Как проходить серию

```bash
cd season-01-yokohama/s01e01-one-pass
```

1. **README.md** — сцена, теория, «Проверка», задание. Читать целиком, в
   Markdown-предпросмотре (`Cmd+Shift+V` / `Ctrl+Shift+V`), иначе не работают
   таблицы и сворачиваемые ответы.
2. **mission.md** — критерии приёмки. Держать открытым, пока пишешь.
3. Скопировать каркас и работать в нём:

```bash
cp starter.rb artifacts/ledger.rb
make test
```

4. Красный тест — это спецификация. Открыть `tests/` и прочитать, какое
   свойство проверяется, — законный ход, а не жульничество: тесты курса не
   ищут подстроку в твоём коде, они проверяют поведение.
5. **theory.md** — после задания: углубление, компромиссы, книги.
6. `solution/` — после честной попытки, а не вместо неё.

## Полезные команды

```bash
make test                  # весь курс
make test SEASON=01        # сезон
make test SERIES=s01e07    # серия
make progress              # где я остановился
make links                 # битые ссылки в документах
make check                 # links + test, как в CI
```

## Если что-то не сходится

| Симптом | Причина |
|---|---|
| `ruby: command not found` | Ruby не в `PATH`; проверить менеджер версий |
| `syntax error, unexpected` в чужом файле | Ruby старше 3.1: курс пользуется синтаксисом 3.x |
| тест зелёный, а ты ничего не писал | артефакта нет, проверяется эталон — видно в первой строке вывода |
| `make: command not found` | поставить `make` (в Windows — через WSL2) |
| правки не влияют на результат | файл лежит не в `artifacts/` или назван иначе, чем в задании |

## Порядок прохождения

Подряд — если Ruby незнаком. Знающему Ruby можно начинать с S2 или S4: каждый
сезон стартует из состояния, зафиксированного в репозитории, и всё нужное от
прошлых сезонов лежит готовым в `support/`.

Внутри сезона серии идут строго по порядку: каждая опирается на предыдущую.
