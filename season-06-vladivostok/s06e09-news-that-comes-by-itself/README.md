## Чему ты научишься

- Подписывать страницу на поток Turbo по Action Cable.
- Посылать по кабелю действие Turbo, когда меняется запись, — из работника и

- Приёму, который дороже синтаксиса: **поток по кабелю — тот же протокол,

## Теория: доска у причала

### Подписка

```erb
<%= turbo_stream_from Delivery::PIER %>
```

Рисует в странице элемент:

```html
<turbo-cable-stream-source channel="Turbo::StreamsChannel"
                           signed-stream-name="InBpZXIi--4c1f…"></turbo-cable-stream-source>
```

Turbo в браузере открывает соединение Action Cable (WebSocket на `/cable`) и
подписывается на канал `Turbo::StreamsChannel` с этим именем. Имя
**подписано** сервером: подделать его и подписаться на чужой поток нельзя —
сервер проверит подпись тем же ключом, что поставил.

### Трансляция

```ruby
class Delivery < ApplicationRecord
  PIER = "pier"
  after_create_commit -> { broadcast_append_later_to PIER, target: PIER, partial: "board/delivery", locals: { delivery: self } }
  after_update_commit -> { broadcast_replace_later_to PIER, target: self, partial: "board/delivery", locals: { delivery: self } }
end
```

| Часть | Что значит |
|---|---|
| `broadcast_replace…` | действие Turbo: заменить элемент |
| `…_later…` | нарисовать и отправить — работнику (`Turbo::Streams::ActionBroadcastJob`) |
| `…_to PIER` | в поток «pier» |
| `target: self` | цель — элемент с `id` = `dom_id(delivery)` |
| `after_…_commit` | после того, как правка легла |

По кабелю уходит тот же `<turbo-stream action="replace" target="delivery_7">`,
что в `s05e09` приходил в ответ на форму. Разница — только в том, кто его
получает: не тот, кто отправил форму, а все, кто подписан.

Новая квитанция и выплата трогают поставку (`touch: true`, `s06e07`), и
`touch` запускает `after_update_commit`: строка табло обновляется от
квитанции и выплаты без отдельных трансляций.

### Почему `_later` и почему `_commit`

`broadcast_replace_to` без `_later` рисует строку и отправляет её в том же
процессе, прямо при правке. Правит запрос линии (`s06e06`) или работник выплат
(`s06e04`) — и ждёт, пока табло нарисуется. С `_later` рисует отдельный
работник.

`after_update` без `_commit` отправит новость внутри транзакции. Откатится
правка — табло уже показывает то, чего в книге нет.

### Кабель

| `config/cable.yml` | Кто кому передаёт |
|---|---|
| `async` | внутри одного процесса |
| `solid_cable` | через таблицу `solid_cable_messages` — любые процессы |
| `redis` | через Redis — любые процессы |
| `test` | запоминает, что ушло, — для проверок |

Строку табло рисует работник (`bin/jobs`), а браузер слушает сервер (`bin/rails
server`) — два процесса. `async` в разработке — и табло молчит, хотя всё
«работает». В этом сезоне кабель в разработке — Solid Cable, таблица в той же
базе.

## Проверка: ADA задаёт вопросы

```
[ADA · КАБЕЛЬ НАГАСАКИ]
ТРИ ВОПРОСА.
```

**1.** ADA: «Табло подписано на `"board"`, модель транслирует в `"pier"`.
Проверки на трансляцию — зелёные. Что увидит Сабуров?»

<details><summary>Ответ</summary>

Ничего. По кабелю в «pier» уходят верные строки — и их никто не слушает.
Табло подписано на другой поток и молча ждёт.

Поэтому проверка сначала читает, какой поток слушает страница (подписанное
имя, проверенное ключом сервера), и только в этот поток смотрит.
</details>

**2.** ADA: «Строку табло можно разослать из `DisburseJob` сразу после
выплаты — явно, без колбэков. Чем хуже?»

<details><summary>Ответ</summary>

Тем, что поставка меняется не только от выплаты: квитанция, пароход у
причала, правка номера. Каждое место, где поставку правят, должно помнить о
табло — и одно забудет.

Колбэк на модели делает «табло знает о поставке» одним решением в одном
месте. Цена — скрытость: трансляция не видна там, где правят. Её выводят на
свет комментарием и проверкой.
</details>

**3.** ADA: «Зачем имя потока подписывать? Это же просто „pier“».

<details><summary>Ответ</summary>

Здесь — просто. Но поток часто называют по записи: `turbo_stream_from
@company` — поток, названный по GlobalID дороги номер 7. Без подписи любая
страница могла бы подписаться на поток любой записи, подставив её номер, и
получать чужие новости. Подписанное имя может выдать только сервер — тот, кто знает, кому
что показывать.
</details>

## Разбор типичных ошибок

1. **Нет `turbo_stream_from`.** Трансляции уходят — табло не слушает.
2. **Подписка на другой поток.** То же, только тише.
3. **Трансляция без `_later`.** Правящий ждёт, пока рисуется табло.
4. **`after_update` вместо `after_update_commit`.** Откатившаяся правка на
   табло.
5. **Строка табло без `id`.** Замене не во что попасть.
6. **Цель трансляции — чужой `id`.** То же.
7. **`update` вместо `append` для новой поставки.** Новая строка стирает
   остальные.
8. **`async` в разработке.** Всё зелёное, табло молчит.
