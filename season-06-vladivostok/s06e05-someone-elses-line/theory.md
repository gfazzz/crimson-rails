# Теория — s06e05

## 1. Точка интеграции

Каждый вызов чужой системы — **точка интеграции**, и Найгард в «Release It!»
называет её главной причиной, по которой ложатся живые системы. Не потому,
что чужие системы плохие, а потому, что их неудачи становятся твоими:

| Чужая неудача | Во что превращается у тебя |
|---|---|
| отвечает медленно | занятые потоки, соединения, работники |
| не отвечает вовсе | то же, но навсегда — если нет предела |
| ответила, ответ потерян | повтор, который удваивает эффект |
| отвечает не тем | исключение там, где его не ждут |

Каждую из них обезвреживают отдельно: предел ожидания, ключ повтора, разбор
ответа по коду (`s06e03`).

## 2. Пределы ожидания

У `Net::HTTP` три предела и все по умолчанию — 60 секунд:

| Предел | Что ограничивает | Исключение |
|---|---|---|
| `open_timeout` | установить соединение | `Net::OpenTimeout` |
| `read_timeout` | дождаться очередной порции ответа | `Net::ReadTimeout` |
| `write_timeout` | отправить тело запроса | `Net::WriteTimeout` |

`read_timeout` — не «весь ответ за N секунд», а «между порциями не больше
N». Сервер, который шлёт по байту раз в секунду, уложится в любой
`read_timeout`. Для полного предела на весь вызов нужен внешний таймер; этой
серии хватает трёх.

Как выбирать число. Не «сколько не жалко ждать», а **сколько отвечает живая
система, с запасом**: посмотреть в журнал, взять медленный хвост (99-й
процентиль) и добавить. Всё, что дольше, — не ответ, а его отсутствие.

## 3. Повторы внутри `Net::HTTP`

`Net::HTTP` сам повторяет запрос — один раз, если метод идемпотентен (`GET`,
`HEAD`, `PUT`, `DELETE`, `OPTIONS`, `TRACE`) и соединение оборвалось или
ответ не пришёл вовремя. Это `max_retries`, по умолчанию 1.

Внутри задачи с `retry_on` это вредно: предел ожидания удваивается, а
обрыв прячется — вызывающий получает ответ второго запроса и не знает, что
был первый. Правило: **повторяет кто-то один.** Здесь — задача.

`POST` `Net::HTTP` не повторяет: он не идемпотентен. Для `POST` повтор
безопасен только тогда, когда сервер умеет узнать его по ключу.

## 4. Ключ повтора для чужой стороны

Задача в `s06e04` защищалась от повтора своим индексом. От повтора к чужой
системе свой индекс не защитит: эффект — передача телеграммы — случается у
них. Узнать повтор может только тот, у кого эффект.

Поэтому ключ отдают им:

```http
POST /messages HTTP/1.1
Idempotency-Key: 5d0c6f0e-7a1d-4e3c-9f2a-0b7b1a6f3c11
Content-Type: application/json
```

Сервер, видевший этот ключ, не повторяет эффект, а возвращает прежний
результат. Требования к ключу:

| Требование | Почему |
|---|---|
| один и тот же у всех попыток одной операции | иначе повтор — новая операция |
| разный у разных операций | иначе новая операция — «повтор» |
| известен до первой попытки | ответ на неё может не дойти |
| уникален без договорённостей | другая контора не должна его совпасть |

`SecureRandom.uuid`, записанный в строку телеграммы при заведении, выполняет
все четыре. Так делают Stripe, Adyen и большинство платёжных API; IETF
описывает это в черновике «The Idempotency-Key HTTP Header Field».

## 5. «Не знаю» — значение

У справки три исхода, и только один из них исключительный:

| Ответ | Значение | Что вернуть |
|---|---|---|
| 200 | линия знает | хеш |
| 404 | линия не знает | `nil` |
| 5xx, молчание | линия ничего не сказала | `Down` |

Исключения — для того, что вызывающий не ждёт и не может обработать на
месте. «Такой телеграммы нет» — ровно то, что спрашивающий хочет узнать.

## 6. Никакой транзакции вокруг чужого вызова

```ruby
telegram.with_lock do                # BEGIN IMMEDIATE … SELECT … FOR UPDATE
  TelegraphLine.deliver(telegram)    # сколько думает линия
  telegram.update!(…)
end                                  # COMMIT
```

Пока линия думает:

- на SQLite пишущая транзакция одна на базу — **вся контора** не может
  записать ни строки;
- на PostgreSQL заперта строка телеграммы и занято соединение из пула;
  десять задумавшихся подач — десять занятых соединений;
- если линия молчит без предела, всё это держится минуту.

Порядок, который не держит ничего:

```
1. записать «иду» (attempts + 1)      — короткая транзакция
2. сходить на линию                   — без транзакции
3. записать «пришёл» (номер, sent)    — короткая транзакция
```

Если умереть между 2 и 3, повтор пойдёт на линию снова — и ключ повтора
сделает так, что линия не передаст второй раз.

## 7. Чего эта серия не закрывает

- **автоматический выключатель** (circuit breaker): после N обрывов подряд
  не ходить на линию вовсе, пока не пройдёт время; у Найгарда — отдельная
  глава, сезону не нужен: работник один и так не долбит;
- **ограничение частоты** (rate limit, `429`, `Retry-After`) — упомянуто в
  `s06e03`;
- **HTTPS и проверка сертификата** — станция через улицу, линия без
  шифрования; в сезоне 7 появится подпись;
- **гемы-клиенты** (Faraday, HTTP.rb) — дают то же самое удобнее; под ними
  те же пределы и те же исключения.
