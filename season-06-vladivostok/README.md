## Что даёт сезон

Всё, что приложение делает **не в ответ на запрос**: работу в фоне, повтор
после сбоя, вызовы чужих систем и их вызовы к нам, копии, которые экономят
чтение, и страницы, которые обновляются сами.

Критерий отбора тот же, что во всех сезонах: **концепт входит, только если без
него Rails выглядит магией.** Поэтому здесь есть Active Job и таблицы Solid
Queue, `retry_on` и `discard_on`, HTTP наружу с пределами ожидания и HTTP
внутрь с подписью, `Rails.cache` и `ETag`, Turbo Streams по кабелю и
повторяющиеся задачи — и нет ни Redis, ни Sidekiq, ни внешних сервисов.

Главная мысль сезона: **очередь обещает «хотя бы раз», а не «ровно раз».**
Работник может умереть между «сделал» и «отметил»; чужая линия может
передать телеграмму и не ответить; квитанция может прийти дважды, двумя
путями. «Ровно раз» — свойство эффекта, и строится оно ключом и индексом, а не
настройкой очереди.

**Чем сезон кончается.** Вся линия под нагрузкой: обрывы, повторы, туман,
две квитанции на одну поставку, два работника разом, — и ни одной двойной
выплаты. И путь денег с Ломбард-стрит, прослеженный до конца.

## Контракт проверки сезона

`SPEC.md` §4. Для этого сезона:

**Обязан проверять** — идемпотентность и повторяемость: задача, выполненная
дважды, даёт тот же результат; повтор после сбоя не дублирует эффект.

**Не засчитывается как проверка** — «задача поставлена в очередь».

Как это выглядит на деле: проверка не спрашивает, лежит ли записка в очереди.
Она зовёт работника — настоящего работника Solid Queue, по строкам настоящих
таблиц, — и считает эффект: сколько телеграмм приняла линия, сколько выплат
легло в книгу казны. Исполняет записку дважды. Убивает работника после
работы и будит утром. Запускает двух работников в двух потоках разом.
Передвигает часы вместо того, чтобы ждать.

## Среда

Ruby 3.3 или новее, Rails 8, SQLite. Установка — в
[`docs/GETTING_STARTED.md`](../docs/GETTING_STARTED.md).

```bash
cd season-06-vladivostok/app
bundle install
bin/rails db:prepare
```

Прогон — обычный minitest:

```bash
make test SEASON=06             # весь сезон
make test SERIES=s06e04         # одна серия
```

Что стоит знать про эту среду:

- **приложение стартует с конца сезона 5.** В `app/` — реестр сезона 4 и
  окно сезона 5, а сверху — основание конторы: таблицы Solid Queue, Solid
  Cache и Solid Cable в той же базе, книги дома (поставки, телеграммы,
  квитанции, выплаты) и часовой пояс Владивостока. `starter/` и `solution/`
  — патч-наборы, как в сезонах 4 и 5;
- **с этого сезона курс даёт интерфейсы и ТЗ, а не каркас** (SPEC §8): в
  `starter/` — сигнатуры, шаблоны и пустые места под код;
- **работник очереди — в процессе проверки.** Проверка берёт записки из
  таблиц Solid Queue и исполняет их тем же кодом, что `bin/jobs`, но по
  команде. Время — время проверки: 12 мая 1892 года, 9 утра по
  Владивостоку, и дальше — сколько проверка передвинет;
- **линия Большого Северного — поддельная, но настоящая по сокету**
  (`support/line.rb`). Она поднимается на свободном порту и отвечает, как
  линия: номером, отказом, обрывом, молчанием. Вживую:

  ```bash
  cd app && bundle exec ruby ../support/line.rb   # линия на 127.0.0.1:4750
  cd app && bin/jobs                              # работник
  cd app && bin/rails server                      # контора
  ```

## Сквозной артефакт: `dispatch`

Контора отправлений поверх реестра и окна. Растёт от серии к серии:

```
app/
├── app/jobs/                 e01–e11 — записки и те, кто их исполняет
├── app/models/telegraph_line e01–e05 — клиент чужой линии: номер, обрыв, отказ, молчание
├── config/queue.yml          e02     — какие работники слушают какие очереди
└── db/migrate/1892…          e04     — «одна выплата на поставку»
```

В сезоне 7 поверх конторы появятся ключи: кто вправе отдать телеграмму,
кто — выплатить, и запись о каждом действии, которую нельзя поправить.
