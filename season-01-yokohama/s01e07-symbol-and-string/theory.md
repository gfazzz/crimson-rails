# Теория — s01e07

## 1. Символ: имя, а не текст

| | `String` | `Symbol` |
|---|---|---|
| каждый литерал | новый объект | один и тот же объект |
| изменяемость | изменяем (если не заморожен) | всегда заморожен |
| сравнение | посимвольное | по тождеству, мгновенно |
| смысл | текст | имя |

```ruby
"road".equal?("road")   # false
:road.equal?(:road)     # true
```

Символы живут в таблице имён интерпретатора. Там же лежат имена всех методов,
классов и переменных: `Abacus::Ledger.instance_methods` возвращает массив
символов, потому что имя метода — это и есть имя.

Выбор между ними почти всегда очевиден, если задать вопрос: **это имя чего-то
или это данные?** Ключ хеша, имя метода, состояние (`:pending`, `:paid`), роль
— имена. Название груза, код дороги, сообщение — данные.

Пограничный случай — код дороги `"SJI"`. Он выглядит как имя, но приходит
снаружи, участвует в отчётах и может быть каким угодно. Строка.

## 2. Как хеш находит ключ

```ruby
h = { road: "SJI" }
h["road"]    # nil
```

Поиск идёт в два шага: сначала по `hash` (число, которым объект себя
представляет), потом, при совпадении, по `eql?`. У строки и символа разные
`hash` и `eql?` — значит, разные ключи.

`eql?` — не `==`. Второе допускает приведение типов (`1 == 1.0` истинно),
первое не допускает (`1.eql?(1.0)` ложно), и хеш пользуется именно `eql?`:

```ruby
{ 1 => :a }[1.0]     # nil
```

В `s01e08` ты будешь определять `hash` и `eql?` для своего класса — и тогда
эта пара из любопытного факта превратится в рабочий инструмент.

## 3. Замороженные строки

```ruby
# frozen_string_literal: true
```

Эта строка в начале файла делает все строковые литералы в нём замороженными: их
нельзя изменить и они переиспользуются, а не создаются заново. Экономия памяти
и защита от случайной мутации чужой строки.

Точечная форма — оператор `-`:

```ruby
key = -"road"      # интернированная строка: один объект на всю программу
key = +"road"      # гарантированно изменяемая копия
```

`-"строка"` — способ получить преимущество символа (один объект), оставаясь
строкой. Применяется там, где ключи приходят извне и приводить их к символам не
хочется.

## 4. Приведение ключей: три подхода

```ruby
# однажды, вручную
raw.transform_keys(&:to_sym)              # только верхний уровень!

# рекурсивно, самому
def symbolize(value) = ...                # задание этой серии

# в Rails
raw.deep_symbolize_keys                   # ActiveSupport
raw.with_indifferent_access               # обёртка, принимающая оба вида
```

`transform_keys` не рекурсивен — это главная ловушка «быстрого решения»:
верхний уровень приведётся, вложенный тариф останется строковым, и
`config[:tariff][:base_rate]` вернёт `nil`.

## 5. `HashWithIndifferentAccess`: удобство ценой границы

Rails-обёртка хранит все ключи строками и приводит к строке любой ключ при
обращении. `params[:road]` и `params["road"]` дают одно и то же.

Цена:

- он **не** `Hash` (хотя очень похож), и при передаче в чужой код это иногда
  вылезает;
- обращение чуть дороже: каждый ключ приводится;
- и главное — стирается признак, по которому видно, откуда пришли данные.

Практика: пользоваться им там, где Rails его даёт (`params`, `session`), и не
превращать в него свои внутренние структуры.

## 6. `to_sym` на чужом вводе: что было и что осталось

До Ruby 2.2 символы не собирались сборщиком мусора: строка, превращённая в
символ, занимала память навсегда. Приведение произвольного ввода к символам
было способом исчерпать память чужого сервера.

С Ruby 2.2 динамически созданные символы собираются, и эта атака перестала
работать. Но само правило осталось в силе по другой причине: **приводя чужие
ключи, ты молча принимаешь всё, что прислали.** Список разрешённого
(`params.permit`, проверка `KNOWN` из `s01e06`) важен не из-за памяти, а из-за
того, что неизвестное поле не должно становиться настройкой.

## 7. Нормализация для сравнения, оригинал для хранения

Общий приём, не про Ruby:

```
исходные данные ──┬──► нормализованная копия ──► сравнение, поиск, дедупликация
                  └──► хранение как есть ──────► отчёт, доказательство, разбор
```

Так работают поиск по тексту (нормализуют регистр и диакритику, хранят
оригинал), сверка адресов, дедупликация записей. Переписанные данные отвечают
на вопрос «одинаковы ли они», но перестают отвечать на вопрос «что именно
прислали».

В `dedupe` это ровно та строка, где в результат кладётся `row`, а не
`normalized`.
