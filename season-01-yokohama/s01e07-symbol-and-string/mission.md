## Обстановка

Японская контора шлёт ведомость с ключами-строками, Палата ведёт свод с
ключами-символами. При слиянии появилась лишняя запись, и `uniq` её не видит:
для Ruby это два разных хеша.

## Приказ

Написать `artifacts/keys.rb`: модуль `Abacus::Keys`, умеющий приводить ключи и
находить записи, которые различаются только их видом.

## Договор вызова

```ruby
Abacus::Keys.symbolize("road" => "SJI", "tariff" => { "base_rate" => 40 })
# => { road: "SJI", tariff: { base_rate: 40 } }

Abacus::Keys.stringify(road: "SJI")
# => { "road" => "SJI" }

Abacus::Keys.same_row?({ "road" => "SJI" }, { road: "SJI" })
# => true

Abacus::Keys.dedupe([japanese_row, british_row])
# => [japanese_row]
```

## Критерии приёмки

- [ ] `symbolize` рекурсивен: вложенные хеши и хеши внутри массивов приводятся
      тоже.
- [ ] `symbolize` **не трогает значения**: груз «чай» остаётся строкой.
- [ ] Ключ, не умеющий стать символом (число, например), остаётся как есть —
      `1` не превращается в `:"1"`.
- [ ] `symbolize` идемпотентен: повторное приведение ничего не меняет.
- [ ] `symbolize` не меняет переданный хеш и возвращает новый.
- [ ] Значение, не являющееся хешем или массивом, возвращается как есть.
- [ ] `stringify` делает обратное, тоже рекурсивно; `symbolize(stringify(h))`
      возвращает исходное.
- [ ] `same_row?` считает одинаковыми записи, различающиеся только видом
      ключей, и различает записи с разными значениями.
- [ ] `dedupe` убирает такие двойники, оставляя **первую** встретившуюся
      **в исходном виде** и на исходном месте.
- [ ] `dedupe` не меняет переданный массив; на пустом списке возвращает пустой.
- [ ] `make test` → девятнадцать зелёных проверок.

## Подводный камень

Соблазн положить в результат `dedupe` уже приведённую запись — она же
«правильная». Нельзя: в ведомости должно остаться то, что пришло из конторы.
Приведение существует ради сравнения, а не ради хранения.
