## Приказ

Дополнить `artifacts/ledger.rb`: научить `Abacus::Ledger` хранить правила и
применять их тогда, когда правило станет исполнимым.

## Договор вызова

```ruby
ledger = Abacus::Ledger.new(entries)

surcharge = 0
ledger.add_rule(:tea) { |e| e[:cargo] == "чай" ? e[:charge] * surcharge : 0 }
ledger.register(:weight, ->(e) { e[:weight] })
ledger.register(:custom, СвойОбъектСМетодомCall.new)

ledger.rule_names          # => [:tea, :weight, :custom]
ledger.rule(:tea)          # => объект, отвечающий на call
ledger.apply(:tea)         # => 0

surcharge = 0.15           # пришла вторая бумага
ledger.apply(:tea)         # => пересчитано
```

## Критерии приёмки

- [ ] `add_rule(name, &rule)` сохраняет **сам блок** объектом, а не результат
      его вызова; возвращает `self`, чтобы вызовы сцеплялись.
- [ ] `add_rule` без блока поднимает `ArgumentError`, и в тексте видно имя
      правила.
- [ ] Повторное `add_rule` с тем же именем заменяет правило, не плодя дубликат
      в `rule_names`.
- [ ] `register(name, callable)` принимает **любой** объект, отвечающий на
      `call`: лямбду, `proc`, метод, свой класс.
- [ ] `register` с объектом без `call` поднимает `ArgumentError`, и в тексте
      назван класс переданного.
- [ ] `rule(name)` для неизвестного имени поднимает `KeyError`, в тексте —
      искомое имя и список имеющихся.
- [ ] `rule_names` возвращает имена в порядке добавления.
- [ ] `apply(name)` применяет правило ко всей ведомости и возвращает сумму;
      работает и для правил из `register`, а не только из `add_rule`.
- [ ] `apply` считает через `total_by`, а не своим циклом, и достаёт правило
      один раз, а не на каждой записи.
- [ ] Правило, замкнувшее переменную, видит её **новое** значение.
- [ ] `make test` → пятнадцать зелёных проверок.

## Подводный камень

Внутри `apply` тянет написать `total_by(&rule(name))`. Это скомпилируется и
пройдёт часть проверок — ровно до правила, зарегистрированного объектом.
Оператор `&` зовёт `to_proc`, а не `call`; у чужого объекта `to_proc` нет.
