## Чему ты научишься

- Принимать блок **объектом** — `&rule` в сигнатуре — и хранить его, пока он
  не понадобится.
- Превращать объект обратно в блок оператором `&`, и понимать, почему это
  работает не с любым объектом.
- Замыканию: правило помнит **переменную**, а не её значение, и потому
  пересчитается само, когда придёт вторая бумага.
- Приёму, который дороже синтаксиса: **не спрашивай, какого объект класса —
  спрашивай, что он умеет.**

Подробнее — в [`theory.md`](theory.md).

## Теория: блок, у которого появилось имя

### Почему `yield` не годится

`yield` вызывает блок в момент исполнения метода. Когда метод закончился, блока
больше нет: он нигде не хранится, у него нет имени, сослаться на него не на что.

Для «посчитай сейчас» этого достаточно. Для «запомни, посчитаешь в пятницу» —
нет.

### `&rule` в сигнатуре: блок становится предметом

```ruby
def add_rule(name, &rule)
  @rules[name] = rule     # rule — обычный объект класса Proc
  self
end
```

Амперсанд в списке параметров означает: «переданный блок заверни в объект и
положи в переменную `rule`». Дальше это обычное значение — его можно хранить в
хеше, передавать, возвращать, вызывать через `call`:

```ruby
rule = ledger.rule(:tea_surcharge)
rule.call(entry)          # то же, что делал бы блок
```

Обратная сторона: `&rule` создаёт объект на каждый вызов метода, а `yield` — нет.
Поэтому в `each_entry` остался `yield`: там блок не переживает вызов.

### `&` в вызове: предмет снова становится блоком

```ruby
ledger.total_by(&saved_rule)      # saved_rule — Proc
%w[ntk sji].map(&:upcase)         # :upcase — Symbol
```

Один и тот же оператор. И тот же механизм: **`&` зовёт у объекта `to_proc`.**
У `Proc` он возвращает себя, у `Symbol` — процедуру «вызови у аргумента метод с
этим именем». `&:upcase` — не особый синтаксис, а `Symbol#to_proc`.

Отсюда важное следствие, на котором споткнёшься в задании: у произвольного
объекта с методом `call` **нет** `to_proc`, и `&` с ним не работает:

```ruby
total_by(&callable)   # TypeError: wrong argument type (expected Proc)
total_by { |entry| callable.call(entry) }   # так — работает с чем угодно
```

### Замыкание помнит переменную, а не значение

```ruby
surcharge = 0
ledger.add_rule(:tea) { |e| e[:cargo] == "чай" ? e[:charge] * surcharge : 0 }

ledger.apply(:tea)   # 0 — множителя ещё нет

surcharge = 0.15     # пришла вторая бумага
ledger.apply(:tea)   # пересчиталось само
```

Блок не скопировал ноль в момент создания — он держится за саму переменную
`surcharge`. Это и есть ответ Ито про конверт: в конверт кладут не число, а
распоряжение, где это число будет взято.

То же свойство — источник ошибок, когда правило замыкает переменную цикла. Разбор
в [`theory.md`](theory.md).

### `proc` против `lambda`

Блок, принятый через `&`, — это `proc`. Различия существенны ровно в двух местах:

| | `proc` | `lambda` |
|---|---|---|
| лишние и недостающие аргументы | прощает | `ArgumentError` |
| `return` внутри | выходит из объемлющего метода | выходит из самой лямбды |

Проверить можно: `rule.lambda?`. Для правил, которые вызывает чужой код, лямбда
честнее: она сразу скажет, что её вызвали неправильно.

### Утиная типизация

```ruby
raise ArgumentError unless callable.respond_to?(:call)
```

Не `is_a?(Proc)`. Правилом может оказаться лямбда, `proc`, метод
(`method(:foo)`), или объект своего класса с методом `call` — в сезоне 6 таким
станет фоновая задача. Проверка на класс отсечёт их все без всякой причины.

### Где это в Rails

```ruby
scope :recent, -> { where("created_at > ?", 1.week.ago) }
validates :charge, numericality: true, if: -> { road.present? }
before_action :require_clerk, only: %i[edit update]
```

Все три — сохранённые вызываемые объекты, которые фреймворк достанет и вызовет
позже, в нужный момент запроса. Ровно то, что ты пишешь сегодня.

**1.** ADA: «`add_rule(:tea) { |e| e[:charge] }` — что попадёт в хеш правил, если
написать `@rules[name] = rule.call`?»

<details><summary>Ответ</summary>

Ошибка: `call` без аргумента на блоке, который ждёт один. Но даже если бы
прошло — в хеш попало бы **значение**, посчитанное один раз, а нужно **правило**,
которое можно вызвать много раз с разными записями. В конверт кладут
распоряжение, а не результат.
</details>

**2.** ADA: «`register(:x, obj)` принял объект с методом `call`. Почему
`total_by(&obj)` внутри `apply` упадёт?»

<details><summary>Ответ</summary>

Оператор `&` не вызывает `call` — он вызывает `to_proc`. У `Proc` тот есть, у
`Symbol` есть, у произвольного объекта — нет, и Ruby скажет
`TypeError: wrong argument type (expected Proc)`.

Лечится либо явным вызовом `call` внутри блока, либо определением `to_proc` у
своего класса. В задании — первое.
</details>

**3.** ADA: «Правило замкнуло переменную `surcharge`, равную нулю. Через неделю
переменной присвоили 0.15. Что вернёт `apply`, и почему это не магия?»

<details><summary>Ответ</summary>

Вернёт пересчитанное значение. Блок хранит ссылку на саму переменную из области,
где он был создан, а не копию значения. Пока жива переменная — живо и правило,
и наоборот: это одна из причин, по которой замыкание удерживает объекты от сборки
мусора.

Не магия: это то же самое, что делает `-> { where("created_at > ?", 1.week.ago) }`
в Rails, вычисляя `1.week.ago` в момент вызова, а не в момент объявления.
</details>

## Разбор типичных ошибок

1. **Сохранить `rule.call`, а не `rule`.** В ящике окажется число, посчитанное
   один раз неизвестно на чём.
2. **`total_by(&rule(name))` в `apply`.** Работает, пока правила приходят
   блоками, и падает с `TypeError` на первом же объекте, зарегистрированном
   через `register`. Тест это поймает.
3. **`@rules[name]` вместо `fetch`.** Опечатка в имени вернёт `nil`, и падение
   случится на две строки позже, в чужом коде, с сообщением
   `undefined method 'call' for nil`.
4. **`is_a?(Proc)` в `register`.** Отсечёт метод, объект и всё, что в сезоне 6
   станет фоновой задачей. Спрашивай про умение, а не про происхождение.
5. **Достать правило внутри блока обхода.** `each_entry { rule(name).call(e) }`
   ищет в хеше на каждой записи. На четырёхстах двенадцати — незаметно, на
   четырёхстах тысячах — заметно.
