## Чему ты научишься

- Именованным аргументам: обязательным, с умолчаниями и с остатком `**`.
- Оператору `**` в обе стороны: собрать лишнее в хеш и раскрыть хеш в
  именованные аргументы.
- Делать объект неизменяемым и отдавать изменённую копию вместо правки на
  месте.
- Приёму, который дороже синтаксиса: **неизвестный ключ — это ошибка.**
  Опция, которую молча проигнорировали, — правило, которое не применилось, и
  никто об этом не узнал.

Подробнее — в [`theory.md`](theory.md).

## Теория: у числа должно быть имя

### Позиционные против именованных

```ruby
charge_for(entry, 40, 250, :up, 15, 0.1)            # что есть что?
charge_for(entry, base_rate: 40, minimum: 250)      # видно на месте вызова
```

Правило простое: **два однотипных аргумента подряд — повод назвать их.** Два
числа рядом перепутать местами можно и нужно будет только один раз.

### Обязательные, с умолчанием и остаток

```ruby
def initialize(base_rate:, minimum: 0, rounding: :up)
```

- `base_rate:` — без умолчания, значит **обязателен**. Забудешь — Ruby скажет
  `missing keyword: :base_rate`. Не нужно писать проверку: язык уже написал её
  за тебя;
- `minimum: 0` — умолчание;
- `**rest` — всё, что не подошло ни под один из объявленных ключей.

Умолчание вычисляется **при каждом вызове**, а не при чтении файла:

```ruby
def report(at: Time.now)   # новое время на каждый вызов
```

Это отличается от языков, где умолчание вычисляется один раз, и там же
находится их классическая ловушка с общим изменяемым умолчанием.

### `**` в обе стороны

```ruby
def self.from(**options)          # собрать: хеш из всех именованных
  new(**options)                  # раскрыть: хеш обратно в именованные
end

rules = { base_rate: 40, minimum: 250 }
Tariff.from(**rules)              # раскрыть при вызове
```

В Ruby 3 это уже не формальность. Хеш и именованные аргументы разделены строго:

```ruby
Tariff.from(rules)     # ArgumentError: хеш поехал позиционным аргументом
Tariff.from(**rules)   # верно
```

В Ruby 2 они путались автоматически, и это был источник такого количества
неприятностей, что разделение стало главным несовместимым изменением третьей
версии.

### Неизвестный ключ — ошибка

```ruby
def self.from(**options)
  unknown = options.keys - KNOWN
  raise ArgumentError, "неизвестные правила: #{unknown.inspect}" unless unknown.empty?

  new(**options)
end
```

Соблазнительная альтернатива — `options.slice(*KNOWN)`: взять то, что понимаем,
остальное отбросить. Она приятна ровно до первой опечатки. Правило `mimimum:
250` из чужой тетради тихо не применится, плата сойдётся не с тем минимумом, а
расхождение обнаружится через квартал и не здесь.

**Общее правило: разбирая чужие данные, отвергай то, чего не понимаешь.**
Молчаливое игнорирование превращает опечатку в невидимое изменение поведения.

### Неизменяемость и `with`

```ruby
def with(**overrides)
  self.class.from(**to_h, **overrides)
end
```

Два раскрытия подряд: сначала свои правила, поверх — новые. При совпадении
ключей побеждает последний. Исходный тариф не меняется вовсе — он заморожен
(`freeze`) прямо в конструкторе.

Зачем: тариф, который может измениться между расчётом и проверкой расчёта,
нельзя сверить. Неизменяемость здесь не академическая аккуратность, а условие
проверяемости.

### Где это в Rails

```ruby
has_many :entries, dependent: :destroy, inverse_of: :road
validates :charge, numericality: { greater_than: 0 }, allow_nil: true
redirect_to entry_path(entry), notice: "Сохранено", status: :see_other
```

Весь API Rails — именованные опции. И там же видна обратная сторона: часть
методов Rails исторически принимает options hash и **молча игнорирует**
неизвестные ключи. Опечатка `dependant: :destroy` не сделает ничего и ничего
не скажет. Знать об этом — значит перечитывать имена опций, а не полагаться на
то, что ошибка проявится.

**1.** ADA: «Почему `base_rate:` объявлен без умолчания, а не с проверкой
`raise if base_rate.nil?`?»

<details><summary>Ответ</summary>

Потому что язык проверит раньше и точнее. Именованный аргумент без умолчания
обязателен: вызов без него не состоится вовсе, и сообщение
`missing keyword: :base_rate` появится в месте вызова, а не внутри объекта.

Ручная проверка на `nil` вдобавок путает два случая: «не передали» и
«передали `nil` намеренно». Язык их различает, самописная проверка — нет.
</details>

**2.** ADA: «`Tariff.from(rules)` вместо `Tariff.from(**rules)`. Что скажет
Ruby 3 и почему в Ruby 2 это работало?»

<details><summary>Ответ</summary>

Ruby 3 скажет `wrong number of arguments (given 1, expected 0)`: хеш поехал
позиционным аргументом, а метод позиционных не принимает.

В Ruby 2 последний хеш-аргумент автоматически превращался в именованные, и
наоборот. Удобно ровно до тех пор, пока метод не принимает и то и другое —
тогда начинались неразрешимые неоднозначности. Ruby 3 разделил их насовсем;
это было главное несовместимое изменение версии.
</details>

**3.** ADA: «`options.slice(*KNOWN)` короче и не падает. Чем плохо?»

<details><summary>Ответ</summary>

Тем, что не падает. Опечатка в имени правила — `mimimum` вместо `minimum` —
превратится в отсутствующее правило, расчёт пройдёт с умолчанием, и результат
будет выглядеть нормально.

Разница между ошибкой и молчанием: ошибка стоит минуту сейчас, молчание — день
через квартал, когда расхождение придётся искать с конца.
</details>

## Разбор типичных ошибок

1. **Позиционные аргументы «потому что короче».** Через неделю никто не
   вспомнит, что означает третье число.
2. **`options.slice(*KNOWN)`.** Опечатка станет невидимой.
3. **`with`, меняющий сам объект.** Тогда это не копия, а правка, и сверить
   расчёт задним числом уже нельзя.
4. **Забыть `freeze`.** Тариф можно будет поменять между расчётом и проверкой.
5. **Порядок счёта наугад.** Надбавка до скидки и после неё дают разные
   деньги. Порядок — часть договора, а не деталь реализации.
6. **`entry[:weight]` вместо `entry.fetch(:weight)`.** Запись без веса
   посчитается как нулевая и попадёт в отчёт.
