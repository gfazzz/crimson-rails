# Теория — s01e06

## 1. Четыре вида аргументов

```ruby
def charge(entry, rate, minimum: 0, rounding: :up, **rest, &block)
#          └──┬──┘ └─┬┘  └──────────┬─────────┘   └──┬─┘  └──┬─┘
#      позиционные      именованные          остаток   блок
```

Порядок в объявлении фиксирован: позиционные, `*splat`, именованные,
`**rest`, `&block`. Нарушить его синтаксически нельзя.

Практическое правило выбора:

| Сколько и каких | Как передавать |
|---|---|
| один-два, разных типов, очевидных | позиционно |
| два и больше однотипных | именованно |
| необязательные настройки | именованно с умолчаниями |
| заранее неизвестный набор | `**rest` и проверка |

«Два однотипных подряд» — главный признак. `charge(entry, 40, 250)` перепутать
можно; `charge(entry, base_rate: 40, minimum: 250)` — нет.

## 2. Что изменилось в Ruby 3

В Ruby 2 хеш в конце списка аргументов автоматически становился именованными
аргументами и наоборот:

```ruby
def f(opts = {}); end
def g(a:); end

f(a: 1)        # хеш
g({ a: 1 })    # в Ruby 2 — именованные, в Ruby 3 — ошибка
```

Эта автоматика ломалась, когда метод принимал и позиционный хеш, и
именованные: нельзя было понять, чем считать `{ a: 1 }`. Ruby 3 разделил их
окончательно. Отсюда обязательный `**` при передаче хеша в именованные
аргументы — и обязательный `**` при пересылке дальше:

```ruby
def wrapper(*args, **options, &block)
  target(*args, **options, &block)     # перенаправление без потерь
end
```

Эта строчка — идиома, которую стоит знать наизусть.

## 3. Умолчания вычисляются при вызове

```ruby
def report(at: Time.now, into: [])
```

`Time.now` берётся на каждый вызов — это удобно и ожидаемо. `into: []` —
тоже новый массив каждый раз, в отличие от языков, где умолчание вычисляется
один раз при определении функции и общий изменяемый объект становится
классической ловушкой.

Умолчание может ссылаться на предыдущие аргументы:

```ruby
def charge(weight, minimum: weight * 2)   # законно
```

## 4. `freeze`: что именно замораживается

`freeze` запрещает менять **сам объект**, но не объекты, на которые он
ссылается:

```ruby
config = { rates: [40, 50] }.freeze
config[:rates] << 60      # пройдёт: заморожен хеш, а не массив внутри
```

Это поверхностная заморозка. Для глубокой нужно замораживать рекурсивно или,
что честнее, не хранить внутри изменяемых структур.

`# frozen_string_literal: true` в начале файла замораживает строковые
литералы — в Ruby 3.x это уже почти обязательная строка: экономит память и
ловит случайные мутации строк.

Неизменяемость даёт три вещи: объект можно свободно делить между потоками,
его можно кешировать, и — главное для нас — расчёт, сделанный им, можно
воспроизвести позже.

## 5. Отказ от неизвестного

Три стратегии обращения с непонятным ключом:

| Стратегия | Код | Чем кончается |
|---|---|---|
| проигнорировать | `options.slice(*KNOWN)` | опечатка становится невидимой |
| принять всё | `@options = options` | опечатка доживает до места использования |
| отвергнуть | `raise unless (options.keys - KNOWN).empty?` | ошибка в момент, когда её дёшево исправить |

Третья дороже в написании на три строки и дешевле в эксплуатации на порядок.
Общее правило разбора чужих данных — **строго то, что понимаешь**; оно же
лежит в основе разбора HTTP-параметров в Rails (`params.permit`).

Обратная сторона тоже реальна: строгая проверка ломает совместимость, когда
отправитель добавляет новое поле. Поэтому в протоколах, которые обязаны
переживать обновления, применяют смягчённую форму: неизвестное не отбрасывают
и не роняют, а **сохраняют и логируют**. Выбор между «упасть» и «записать в
журнал» зависит от того, кто по ту сторону: чужая система или твой же файл
настроек.

## 6. `to_h` и обратная сборка

```ruby
def to_h = { base_rate: base_rate, minimum: minimum, rounding: rounding }
def with(**overrides) = self.class.from(**to_h, **overrides)
```

Пара `to_h` + `from(**hash)` — это сериализация объекта в данные и обратно.
Проверка, что они согласованы: `Tariff.from(**t.to_h).to_h == t.to_h`. Такое
свойство называется круговым и очень хорошо проверяется тестом.

При двойном раскрытии `**a, **b` побеждают ключи из последнего хеша. Это и
делает `with` однострочным.

## 7. Где это в Rails

```ruby
has_many :entries, dependent: :destroy
validates :charge, numericality: { greater_than: 0 }
params.require(:entry).permit(:road, :cargo, :weight)
```

Первые две строки — options hash, и часть таких методов в Rails **молча**
игнорирует неизвестные ключи: `dependant:` с опечаткой не сделает ничего.
Третья — ровно та же идея, что в задании: явный список того, что мы понимаем,
и отказ от всего остального. Не случайно она стоит на границе с внешним миром.
