# Теория — s01e10

## 1. `self` — это получатель текущего вызова

Одно правило объясняет все четыре случая: **`self` — тот объект, которому был
послан метод, исполняющийся прямо сейчас.**

| Код | Кому послан метод | Кто `self` |
|---|---|---|
| `def register` в классе | объекту-реестру | реестр |
| тело `class Registry` | классу `Registry` (Ruby исполняет тело) | класс |
| `class << self ... def instance` | классу `Registry` | класс |
| блок | никому — блок не вызов | тот же, что снаружи |

Четвёртая строка — ключевая. Блок не является методом, у него нет получателя,
и потому он не может сменить `self`. Он его наследует, как наследует
локальные переменные.

## 2. Переменные: четыре вида и три полезных

```ruby
roads      # локальная: живёт до конца метода или блока
@roads     # экземпляра: принадлежит self
@@roads    # класса: одна на всю иерархию — избегать
$roads     # глобальная: одна на программу — избегать
```

`@roads` в теле класса и `@roads` в методе экземпляра — **разные** переменные,
потому что `self` в этих местах разный. Это обычный источник недоумения:

```ruby
class Registry
  @roads = {}          # у класса

  def add(code)
    @roads[code] = 1   # NoMethodError: у ЭКЗЕМПЛЯРА @roads нет, там nil
  end
end
```

Именно поэтому доступ к состоянию класса пишут методами класса.

## 3. Чем плоха `@@`

```ruby
class Registry
  @@roads = {}
end

class JapaneseRegistry < Registry; end
JapaneseRegistry.class_variable_set(:@@roads, {})   # реестр родителя тоже пуст
```

Переменная класса общая для всей иерархии. Наследник не заводит свою — он
пишет в ту же. В Ruby 3 попытка изменить переменную класса из наследника,
когда она определена в родителе, даёт предупреждение, а обращение к
переопределённой — `RuntimeError`.

Альтернатива на все случаи: переменная объекта-класса плюс `attr_accessor` в
`class << self`.

## 4. Одиночный класс

У каждого объекта может быть невидимый класс, стоящий перед его настоящим:

```ruby
ship = Shipment.new
def ship.weight_kg = 0           # метод только у этого объекта
ship.singleton_class             # #<Class:#<Shipment:0x...>>
ship.singleton_class.ancestors   # [#<Class:...>, Shipment, ...]
```

Методы класса — тот же механизм: `def self.instance` кладёт метод в одиночный
класс объекта `Registry`. Никакого отдельного понятия «статический метод» в
Ruby нет — и именно поэтому методы класса наследуются: одиночные классы
выстраиваются в такую же цепочку, как обычные.

## 5. `instance_eval`, `instance_exec`, `class_eval`

| Метод | Что меняет | Куда попадают `def` |
|---|---|---|
| `instance_eval` | `self` → получатель | в одиночный класс |
| `instance_exec` | то же, но принимает аргументы | туда же |
| `class_eval` (он же `module_eval`) | `self` → сам класс | в обычные методы класса |

```ruby
Registry.instance_eval { def foo; end }   # метод КЛАССА Registry
Registry.class_eval    { def foo; end }   # метод ЭКЗЕМПЛЯРА
```

Разница неочевидна и является источником регулярной путаницы. Мнемоника: имя
метода говорит, кем становится `self`, а не куда попадут определения.

`instance_exec` нужен, когда в блок надо передать значения:

```ruby
registry.instance_exec(1435) { |gauge| register("TKY", gauge: gauge, unit: :kg) }
```

## 6. DSL с подменённым `self`: за и против

**За:** короткая запись, читается как объявление, а не как код.

**Против:**

- непонятно, чей метод вызывается — объекта или окружения;
- опечатка в имени метода даёт `NoMethodError` в неожиданном месте;
- инструменты (подсказки редактора, поиск по коду) перестают помогать.

Практика, к которой пришли многие библиотеки: давать **оба** варианта.

```ruby
Registry.configure { register(...) }        # instance_eval
Registry.configure { |r| r.register(...) }  # аргумент
```

Реализуется одной проверкой: `block.arity.zero? ? instance_eval(&block) : block.call(self)`.
Так устроен, например, `Rails.application.configure` и половина гемов с
настройкой.

## 7. Единственность без `Singleton`

Стандартная библиотека даёт модуль `Singleton`: он делает `new` приватным и
заводит `instance`. Мы не берём его сознательно: приватный `new` мешает
тестам — второй реестр нельзя создать, и тесты начинают влиять друг на друга
через общее состояние.

Наш вариант — «обычный объект плюс короткий доступ» — даёт то же удобство,
оставляя возможность создать отдельный экземпляр. Отсюда же `reset!`: явная
точка, в которой общее состояние можно вернуть в исходное.

Общее правило: **единственность — свойство использования, а не свойство
класса.** Класс, запрещающий второй экземпляр, ограничивает в первую очередь
тех, кто его тестирует.
