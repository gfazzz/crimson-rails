## Чему ты научишься

- Отвечать на вопрос «кто сейчас `self`» в четырёх разных местах кода.
- Хранить состояние у класса, не прибегая к `@@переменным`.
- `class << self` — что это за место и почему методы класса живут именно там.
- Приёму, который дороже синтаксиса: **блок не меняет `self`.** Если хочется,
  чтобы менял, это отдельное решение и отдельный метод — `instance_eval`.

Подробнее — в [`theory.md`](theory.md).

## Теория: кто сейчас `self`

### Четыре места

```ruby
class Registry            # (2) self — сам класс Registry
  @instance = nil         #     переменная принадлежит классу

  class << self           # (3) self — одиночный класс Registry
    def instance          #     всё, что здесь, — методы класса
      @instance ||= new   #     @instance — тот же, что в (2)
    end
  end

  def register(code)      # (1) self — конкретный реестр
    @roads[code] = ...    #     переменная принадлежит объекту
    self
  end

  def each
    @roads.each { |c, r| ... }   # (4) self внутри блока — тот же, что снаружи
  end
end
```

| Где | Кто `self` | Кому принадлежит `@переменная` |
|---|---|---|
| метод экземпляра | сам объект | объекту |
| тело класса | класс | классу |
| `class << self` | одиночный класс | классу |
| блок | тот же, что снаружи | тому же, что снаружи |

Третья и вторая строки таблицы важны вместе: `@instance`, записанная в теле
класса, и `@instance`, прочитанная в `class << self`, — **одна и та же
переменная**, потому что `self` в обоих случаях указывает на один объект-класс.

### Класс — это объект

```ruby
Registry.class        # Class
Registry.frozen?      # false
Registry.instance_variables   # [:@instance]
```

Отсюда всё остальное: у класса есть переменные экземпляра, ему можно
подмешивать модули (`extend` из `s01e09`), его можно передавать в методы.

**Переменные класса `@@` — не то же самое и почти всегда хуже.** `@@roads`
общая для класса и всех его наследников: наследник, записавший туда своё,
меняет реестр родителя. Ошибка вылезает через полгода и в другом файле.
Переменная объекта-класса (`@roads` в теле класса) такого не делает.

### `class << self`

`class << self` открывает **одиночный класс** объекта — тот, где живут методы,
принадлежащие именно этому объекту и никому больше. Для класса это то же, что
«методы класса».

```ruby
class << self
  def instance; end
end

def self.instance; end     # то же самое, но по одному методу
```

Форма `class << self` удобнее, когда методов класса несколько: они стоят
вместе, а `attr_reader` и `private` внутри работают как обычно — чего с
`def self.` не выйдет.

### Блок не меняет `self`

```ruby
registry.each do |code, rules|
  # self здесь — тот, кто вызвал each, а не registry
end
```

Это свойство, а не ограничение: именно поэтому в блоке видны переменные и
методы вызывающего кода — замыкание сохраняет весь контекст, включая `self`.

Когда нужно иначе — говорят об этом явно:

```ruby
def configure(&block)
  instance_eval(&block)
  self
end

Registry.configure do
  register("NTK", gauge: 1067, unit: :lb)   # без получателя
end
```

`instance_eval` выполняет блок, подменив `self` на получателя. Локальные
переменные при этом остаются видны — замыкание никуда не делось, подменён
только `self`.

**Цена.** Внутри такого блока непонятно, чей метод вызывается: `register` —
это метод реестра или метод окружающего объекта? Поэтому подменять `self`
уместно в узком месте — в объявлении настроек, в DSL, — и неуместно в обычном
коде.

### Где это в Rails

```ruby
Rails.application.configure do          # instance_eval: self — конфигурация
  config.time_zone = "Tokyo"
end

RSpec.describe Ledger do                # тот же приём
  it "считает" do ... end
end

class Entry < ApplicationRecord
  scope :heavy, -> { where("weight > 2000") }   # блок, self подменён при вызове
end
```

Всё, что в Rails выглядит как «особый синтаксис настройки», — блок с
подменённым `self`. Увидев это один раз, перестаёшь искать в документации
несуществующие ключевые слова.

**1.** ADA: «`@instance` в теле класса и `@instance` внутри `class << self` —
одна переменная или разные?»

<details><summary>Ответ</summary>

Одна. Переменная экземпляра принадлежит тому объекту, на который указывает
`self` в момент обращения. В теле класса `self` — класс `Registry`; внутри
`class << self` методы выполняются на том же `Registry`. Значит, объект один и
переменная одна.

Разными они были бы, если бы `self` указывал на разные объекты, — например, в
методе экземпляра.
</details>

**2.** ADA: «Чем `@@roads` хуже `@roads` в теле класса?»

<details><summary>Ответ</summary>

`@@roads` — одна на всю иерархию: наследник, записавший в неё, изменит реестр
родителя и соседних наследников. Поймать тяжело — сломавший код и сломавшийся
лежат в разных файлах. `@roads` в теле класса принадлежит только этому классу;
наследник заведёт свою, если захочет.
</details>

**3.** ADA: «`configure` через `block.call(self)` вместо `instance_eval(&block)`.
Что перестанет работать?»

<details><summary>Ответ</summary>

Перестанет работать вызов `register` без получателя. `block.call(self)` передаёт
реестр **аргументом**, не меняя `self`, и внутри блока придётся писать
`|r| r.register(...)`.

Это, кстати, законный и более честный вариант — `Rails.application.configure`
устроен именно так, через аргумент. Выбор между ними — выбор между краткостью
и явностью, и его надо делать сознательно, а не по привычке.
</details>

## Разбор типичных ошибок

1. **`instance`, создающий новый объект каждый раз.** Книга дорог станет
   личной у каждого, кто её открыл.
2. **`@@instance` вместо `@instance`.** Работает, пока не появится наследник.
3. **Короткий доступ со своим складом.** `Registry.register` должен
   делегировать, а не заводить второе хранилище: иначе книг снова две.
4. **`block.call(self)` в `configure`.** Вызов без получателя перестанет
   работать.
5. **`register`, не возвращающий `self`.** Сцепление вызовов сломается.
6. **`@roads[code]` вместо `fetch`.** Неизвестная дорога вернёт `nil`, и он
   уедет в расчёт платы.
