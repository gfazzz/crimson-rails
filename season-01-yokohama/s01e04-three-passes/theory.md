# Теория — s01e04

## 1. Три формы, а не тридцать методов

Почти любой обход коллекции — это одна из трёх вещей:

| Форма | Сколько на выходе | Методы |
|---|---|---|
| преобразование | столько же | `map`, `flat_map`, `filter_map`, `each_with_index` |
| отбор | меньше или столько же | `select`, `reject`, `partition`, `find`, `take_while`, `grep` |
| свёртка | одно значение | `reduce`, `sum`, `count`, `min_by`, `max_by`, `tally`, `group_by` |

Практический приём: прежде чем искать метод, назови форму. «Мне нужно из
каждой записи достать плату» — преобразование. «Мне нужны только тяжёлые» —
отбор. «Мне нужна одна цифра по всем» — свёртка. После этого имя находится за
десять секунд в `ri Enumerable`, и не нужно помнить сорок названий.

## 2. `map` и его родственники

```ruby
entries.map { |e| e[:charge] }                        # 412 → 412
entries.flat_map { |e| e[:tags] }                     # разворачивает вложенные массивы
entries.filter_map { |e| e[:charge] if e[:cargo] == "чай" }   # отбор и преобразование за раз
entries.each_with_index.map { |e, i| [i, e[:road]] }
```

`map { ... }.compact` — почти всегда признак того, что нужен был `filter_map`:
он появился в Ruby 2.7 именно ради этого случая.

`map!` меняет исходный массив. В отчётах ему делать нечего: отчёт не должен
портить то, из чего он составлен.

## 3. Отбор: почему `reject` существует

```ruby
select { |e| !(e[:weight] > 2000) }
reject { |e| e[:weight] > 2000 }
```

Второй вариант не «красивее» — он не содержит отрицания. Отрицание удваивает
число состояний, которые надо держать в голове при чтении, и именно в нём делают
ошибки при правке условия («тяжелее» → «не легче» → тихий сдвиг границы).

`partition` решает другую проблему: **дублирование условия**. Пока условие
записано один раз, порог можно менять в одном месте.

Родня, которую стоит знать: `find` (первый подошедший, дальше не смотрит),
`take_while` / `drop_while` (для упорядоченных данных), `grep` (отбор по `===`,
работает с классами и регулярными выражениями: `entries.grep(Hash)`).

## 4. `reduce`: накопитель может быть любым

```ruby
# число
entries.reduce(0) { |sum, e| sum + e[:charge] }

# строка
entries.reduce("") { |acc, e| acc + e[:road] }

# хеш — но для этого случая есть each_with_object, см. s01e05
entries.reduce({}) { |acc, e| acc.merge(e[:road] => e[:charge]) }

# выбор, а не накопление
entries.reduce(nil) { |best, e| best.nil? || e[:charge] > best[:charge] ? e : best }
```

Последняя форма — то же, что `max_by`, написанное руками. Писать так не нужно;
уметь читать — нужно, потому что половина чужого кода написана именно так.

**`inject` — то же самое.** Исторический псевдоним из Smalltalk. Встретишь оба
имени; в новом коде принято `reduce`.

**Символьная форма.** `reduce(:+)` и `reduce(0, :+)` — сокращение для сложения:

```ruby
[1, 2, 3].reduce(:+)        # 6
[].reduce(:+)               # nil
[].reduce(0, :+)            # 0
```

## 5. Пустая коллекция — отдельный случай всегда

| Выражение | Результат |
|---|---|
| `[].reduce(:+)` | `nil` |
| `[].reduce(0, :+)` | `0` |
| `[].sum` | `0` |
| `[].max` | `nil` |
| `[].first` | `nil` |
| `[].partition { }` | `[[], []]` |
| `0 / 0` | `ZeroDivisionError` |
| `0.0 / 0` | `NaN`, без исключения |

Вывод, который стоит унести: **Ruby редко падает на пустоте — он возвращает
`nil`.** Поэтому ответ на пустой коллекции надо выбирать сознательно, а не
наблюдать.

## 6. `nil` против `0`: это про смысл, а не про стиль

- «сколько заплачено за декабрь» при отсутствии перевозок → `0`. Сумма пустого
  множества равна нулю, это арифметика.
- «какая средняя плата» при отсутствии перевозок → `nil`. Средней не
  существует, и ноль здесь не «пусто», а конкретное утверждение: «перевозки
  были, все бесплатные».

Практика, к которой это ведёт: `nil` — законный ответ, если он означает «нет
ответа». Плохой `nil` — тот, который означает «я не подумал».

В Rails та же развилка встречается ежедневно: `Entry.sum(:charge)` на пустой
выборке вернёт `0`, а `Entry.average(:charge)` — `nil`. Не случайность, а тот же
рассуждение.

## 7. Целочисленное деление

```ruby
3 / 2         # 1
3.0 / 2       # 1.5
3.fdiv(2)     # 1.5
Rational(3, 2) # (3/2) — точно, без плавающей точки
```

В расчётах с деньгами дробная часть обычно не нужна вовсе: суммы держат в
минимальных единицах (сен, копейках, центах) целыми числами, а делят в
последний момент и с явно выбранным округлением. `BigDecimal` — когда нужна
десятичная точность, `Rational` — когда нужна абсолютная.

Самая дорогая ошибка здесь не в формуле, а в молчании: `3 / 2` не выдаёт ни
исключения, ни предупреждения.
