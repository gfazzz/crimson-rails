# Теория — s01e01

## 1. Откуда у Ruby блоки

Идея «передать в метод кусок кода» старше Ruby. В Smalltalk есть блоки
(`[:each | ...]`), в языке CLU 1975 года — итераторы с оператором `yield`,
откуда Мацумото и взял само слово. Новизна Ruby не в идее, а в том, **насколько
дёшево** это выглядит: блок не оформляется как аргумент, не требует объявления
типа и пишется прямо на месте вызова.

Цена решения — блок в Ruby ровно один. Нельзя передать методу два блока; если
нужны два действия, придётся передавать их объектами (`Proc`), и это уже
следующая серия.

> *Ито, на третий день: «У вас в Лондоне на каждый вопрос заводят бланк.
> Бланков становится больше, чем вопросов».*

## 2. Почему блок — не обычный аргумент

Можно было бы обойтись без особого синтаксиса:

```ruby
ledger.total_by(->(entry) { entry[:charge] })   # так тоже можно
ledger.total_by { |entry| entry[:charge] }      # но пишут так
```

Разница в том, где кончается вызов. Во втором варианте действие стоит **после**
скобок, снаружи списка аргументов, — и потому его можно записать многострочно,
не превращая вызов в лестницу из скобок:

```ruby
ActiveRecord::Base.transaction do
  entry.save!
  audit.record!(entry)
end
```

Это не косметика. Весь Rails построен на том, что блок читается как тело
конструкции языка, а не как последний параметр функции. `respond_to`,
`form_with`, `transaction`, `around_action` — обычные методы, которые выглядят
как синтаксис, потому что блок вынесен за скобки.

## 3. `{ }` против `do ... end`

Ведут себя одинаково, но связываются по-разному: `{ }` крепче, чем `do ... end`.

```ruby
puts ledger.total_by { |e| e[:charge] }      # блок уходит в total_by
puts ledger.total_by do |e| e[:charge] end   # блок уходит в puts — и ломается
```

Правило, которого держатся: `{ }` для однострочников, значение которых
используют; `do ... end` для многострочников, которые выполняют ради действия.
Оно не про эстетику — оно обходит ловушку приоритета.

## 4. Что возвращает блок и что возвращает метод

Блок возвращает значение последнего выражения, и `yield` это значение отдаёт
вызвавшему:

```ruby
def total_by
  sum = 0
  each_entry { |entry| sum += yield(entry) }   # yield(entry) — это число
  sum
end
```

`return` внутри блока возвращает **не из блока, а из метода, где блок написан**.
Это регулярный источник неожиданностей:

```ruby
def report
  ledger.each_entry { |e| return e if e[:charge].zero? }   # выйдет из report
  nil
end
```

Иногда этого и хотят. Но если хотели «перейти к следующей записи» — нужен
`next`, а не `return`.

## 5. `Enumerator`: что возвращает обход без блока

`enum_for(:each_entry)` не выполняет обход. Он возвращает объект, который знает
**как** его выполнить, и делает это по требованию:

```ruby
e = ledger.each_entry     # ничего ещё не обошли
e.next                    # первая запись
e.next                    # вторая
ledger.each_entry.with_index { |entry, i| ... }
ledger.each_entry.lazy.select { |x| x[:weight] > 2000 }.first(3)
```

Отсюда правило стандартной библиотеки: **обход без блока возвращает
перечислитель.** Так ведут себя `each`, `map`, `select`, `each_slice` — все.
Метод, который вместо этого падает, выпадает из языка: его нельзя поставить в
цепочку и нельзя обернуть в `with_index`.

В сезоне 3 курса — `Enumerable`, и там выяснится, что перечислитель делает
половину работы, которую иначе пришлось бы писать руками.

## 6. Четыре ловушки Ruby для пришедших из других языков

| Ловушка | Как на самом деле |
|---|---|
| «Ноль ложен» | Ложны только `nil` и `false`. `0`, `""`, `[]`, `{}` — истинны. |
| «`nil` — это `false`» | Разные объекты. `nil == false` → `false`. Ложны оба, равны — нет. |
| «Метод с `!` опаснее» | `!` значит «есть парный метод без него», обычно мутирующий. Не «опасно», а «пара». |
| «Присваивание ничего не возвращает» | Возвращает присвоенное. Отсюда `if (row = next_row)` и отсюда же опечатка `=` вместо `==`, которую Ruby не считает ошибкой. |

Первая из них проверяется тестом этой серии, остальные три встретятся дальше по
сезону.

## 7. Цена

`yield` быстрее, чем сохранённый блок: `def m(&b); b.call; end` создаёт объект
`Proc` на каждый вызов, а `yield` — нет. Разница заметна на миллионах итераций
и незаметна на четырёхстах двенадцати.

Правило простое: пока блок нужен только внутри метода — `yield`. Как только
блок надо сохранить, передать дальше или вызвать позже — `&block`, и платишь за
объект осознанно. Это ровно граница между этой серией и следующей.
