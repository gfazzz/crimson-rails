## Теория: блок — аргумент, который не назвали

### Три вопроса, один обход

Можно написать три метода — `total_charge`, `count_heavy`, `total_tea`, — и они
будут отличаться одной строкой в середине; четвёртый вопрос добавит четвёртый
метод. Можно передавать флаги — `ledger.total(:weight, over: 2000)`, — и через
полгода метод примет семь аргументов, половина из которых несовместима.

А можно отдать внутрь само действие:

```ruby
ledger.total_by   { |entry| entry[:charge] }
ledger.count_where { |entry| entry[:weight] > 2000 }
ledger.total_by   { |entry| entry[:cargo] == "чай" ? entry[:charge] : 0 }
```

Обход один и тот же. Меняется то, что происходит с записью внутри обхода.

### `yield`

У блока в Ruby особое положение: он не входит в список аргументов, у него нет
имени, и передаётся он не в скобках, а фигурными скобками или `do ... end`.
Вызывается словом `yield`:

```ruby
def each_entry
  @entries.each { |entry| yield entry }
  self
end
```

`yield entry` — «выполни переданный блок, отдав ему `entry`». Сколько раз
встретился `yield`, столько раз выполнится блок. Это всё.

Мелочь, на которой спотыкаются: **внутренний блок не перехватывает `yield`.**
Выше `@entries.each { ... }` — свой блок, но `yield` внутри него по-прежнему
относится к `each_entry`. Поэтому работает и `each_entry { |e| sum += yield(e) }`
внутри другого метода: `yield` там — от внешнего метода, не от `each_entry`.

### `block_given?`

`yield` без блока поднимает `LocalJumpError`. Проверить наличие можно:

```ruby
def each_entry
  return enum_for(:each_entry) unless block_given?
  ...
end
```

Так устроен весь стандартный Ruby: `[1, 2, 3].each` без блока не падает, а
возвращает `Enumerator`. Твой обход обязан вести себя так же, иначе он будет
чужеродным.

Там, где перечислитель бессмыслен — `total_by` без блока нечего суммировать, —
лучше поднять **свою** ошибку: `LocalJumpError` сообщает, что блока нет, а
`ArgumentError` с текстом сообщает, какому методу и зачем он был нужен.

### Две вещи, которые проверит тест

**Обход возвращает получателя.** `@entries.each { ... }` вернёт `@entries`,
то есть отдаст наружу внутренности объекта. `Array#each` возвращает сам массив,
`Hash#each` — сам хеш. Держись этого: строка `self` в конце.

**Истина по-рубистски.** Ложны только `nil` и `false`; ноль и пустая строка
истинны. Поэтому `found += 1 if yield(entry)` верно, а `... == true` молча врёт
на блоке, возвращающем число. Прочие ловушки языка — в [`theory.md`](theory.md).

### Где это в Rails

`respond_to do |format|`, `ActiveRecord::Base.transaction do`,
`form_with(model: @entry) do |f|` — ни одно из этого не является особым
синтаксисом фреймворка. Это тот же блок. Когда в S4 ты откроешь исходник Rails,
ты увидишь там `yield` и `block_given?` — ровно те, что напишешь сегодня.

## Проверка: ADA задаёт вопросы

```
[ADA · ЛЕНТА ИЗ ЛОНДОНА]
ТРИ ВОПРОСА ДО ТОГО, КАК ТЫ ВОЗЬМЁШЬ ПЕРО.
```

**1.** ADA: «Метод `each_entry` заканчивается строкой `@entries.each { |e| yield e }`.
Что он вернёт и почему это плохо?»

<details><summary>Ответ</summary>

Вернёт `@entries` — сам массив, потому что `Array#each` возвращает получателя.
Плохо дважды: наружу уходит внутреннее состояние объекта (вызывающий получит
ссылку и сможет его испортить) и ломается ожидание — обход в Ruby возвращает
того, кого обходили. Лечится строкой `self` в конце.
</details>

**2.** ADA: «`total_by` обходит записи. Написать внутри свой цикл по `@entries`
или вызвать `each_entry`? Ответ обоснуй, а не выбери.»

<details><summary>Ответ</summary>

Вызвать `each_entry`: обход — одно знание, и жить оно должно в одном месте.
Сегодня `@entries` — массив, завтра ведомость начнёт читать записи из файла
частями, и менять придётся один метод, а не три.

Тонкость, ради которой вопрос задан: `yield` внутри блока, переданного в
`each_entry`, относится к `total_by`, а не к `each_entry`. Поэтому
`each_entry { |entry| sum += yield(entry) }` работает.
</details>

**3.** ADA: «`count_where { |e| e[:charge] }` на записи с платой ноль. Сосчитается
она или нет?»

<details><summary>Ответ</summary>

Сосчитается. В Ruby ложны только `nil` и `false`; ноль — обычное истинное
значение, в отличие от C, Python и JavaScript. Если такая запись не считается,
внутри стоит `== true` или сравнение с нулём, которого там быть не должно.
Остальные ловушки Ruby для пришедших из других языков — в [`theory.md`](theory.md).
</details>

## Разбор типичных ошибок

1. **Забыть `self` в конце обхода.** Метод вернёт массив записей. Тест это
   поймает; жизнь поймает позже и больнее.
2. **`yield` без `block_given?`.** `ledger.each_entry` без блока упадёт с
   `LocalJumpError` — сообщением, по которому непонятно, чей блок отсутствует.
3. **Сравнение с `true` в `count_where`.** Работает на блоках, возвращающих
   сравнение, и молча врёт на блоках, возвращающих число или строку.
4. **Свой цикл по `@entries` в каждом методе.** Три копии одного знания.
   Через две серии, когда ведомость научится читать записи порциями, это
   придётся переписывать трижды.
5. **Вернуть `nil` из `total_by` на пустой ведомости.** Сумма ничего — это
   ноль. `nil` разойдётся по вызывающему коду и всплывёт там, где его никто
   не ждал.
