## Чему ты научишься

- Различать три способа подмешать модуль: `include`, `extend`, `prepend`, — и
  видеть, куда каждый ставит модуль в цепочке предков.
- Хуку `self.included` — как модуль добавляет классу-хозяину методы класса.
- `super` из примеси: перехватить чужой метод, не переписывая его.
- Приёму, который дороже синтаксиса: **наследование — про «чем является»,
  примесь — про «что умеет».** Роль, приписанная наследованием, через полгода
  потребует второго родителя.

Подробнее — в [`theory.md`](theory.md).

## Теория: три места в цепочке

### Модуль описывает роль

```ruby
module Convertible
  def weight_kg = weight * Convertible.factor_for(unit)
end
```

Модуль не знает, как устроен класс-хозяин. Он зовёт `weight` и `unit` и требует
только, чтобы они были. Это и называется ролью: набор умений, которые можно
приписать чему угодно подходящему.

Наследование ответило бы на другой вопрос. `class Entry < Convertible` означало
бы, что запись **является** пересчитываемым, — и заняло бы единственное место
родителя, которое понадобится завтра для чего-то более существенного.

### Три способа и три места

```ruby
class Shipment
  include Abacus::Convertible   # модуль ПОЗАДИ класса
  prepend Abacus::Rounded       # модуль ПЕРЕД классом
end

ship.extend(Abacus::Rounded)    # модуль перед классом, но у одного объекта
```

```ruby
Shipment.ancestors
# [Rounded, Shipment, Convertible, Object, Kernel, BasicObject]
#  └ prepend           └ include
```

Поиск метода идёт слева направо и берёт первый найденный. Отсюда всё
поведение:

| Способ | Куда встаёт | Что из этого следует |
|---|---|---|
| `include` | позади класса | метод класса **побеждает** метод модуля |
| `prepend` | перед классом | метод модуля перехватывает вызов, `super` идёт в класс |
| `extend` | в одиночный класс объекта | затрагивает **один объект**, не трогая остальные |

Практический вывод: если нужно **дать** классу новое умение — `include`. Если
нужно **обернуть** существующий метод — `prepend`. Если нужно изменить
поведение одного объекта — `extend`.

### `super` из примеси

```ruby
module Rounded
  def weight_kg = super.round
end
```

`super` без скобок передаёт те же аргументы и идёт дальше по цепочке предков —
в класс, а оттуда, если там нет, в `Convertible`. Модуль при этом не знает, чей
метод он обернул, и не обязан знать.

Это и есть механизм, которым в Rails работают `around_action`, декораторы и
почти все «расширения поведения без правки исходника».

Через `include` так не выйдет: модуль окажется позади класса, метод класса
победит, и `super` никто не позовёт. Ошибка не выдаст себя — просто округление
не применится.

### Хук `included`

`include` добавляет **методы экземпляра**. Методы класса он не добавляет — и
это регулярно удивляет. Нужен хук:

```ruby
def self.included(base)
  base.extend(ClassMethods)
end

module ClassMethods
  def units = IN_KG.keys
end
```

Ruby зовёт `included` в момент подмешивания и передаёт класс-хозяина. Дальше
`extend` вкладывает `ClassMethods` в его одиночный класс — то есть делает их
методами класса.

Пара «модуль + вложенный `ClassMethods` + хук» встречается так часто, что в
Rails для неё есть готовая обёртка — `ActiveSupport::Concern`. В финале сезона
(`s01e15`) ты прочитаешь её исходник построчно; сегодня ты пишешь то, что она
делает.

### Родня хуков

`included`, `extended`, `prepended`, `inherited`, `method_added` — Ruby
сообщает объекту о событиях, которые с ним происходят. Это не магия
фреймворков: фреймворки построены на этих хуках.

**1.** ADA: «Почему пересчёт — примесь, а не родительский класс?»

<details><summary>Ответ</summary>

Потому что «умеет пересчитывать вес» — не вид записи, а её умение. Запись не
является разновидностью пересчёта.

Практическая сторона важнее философской: родитель у класса один. Отдав его под
пересчёт, ты не сможешь отдать его под то, чем запись действительно является,
когда это понадобится. Примесей можно подмешать сколько угодно.
</details>

**2.** ADA: «`include Rounded` в класс, где `weight_kg` определён своим
методом. Что выполнится и почему это не ошибка?»

<details><summary>Ответ</summary>

Выполнится метод класса. `include` ставит модуль позади класса, а поиск идёт
слева направо и берёт первое найденное.

Не ошибка — так и задумано: подмешанный модуль не должен незаметно
перехватывать то, что класс определил явно. Для перехвата есть `prepend`,
и он читается как заявление о намерении.
</details>

**3.** ADA: «Почему `included` вызывает `extend`, а не `include`?»

<details><summary>Ответ</summary>

Потому что задача — дать классу **методы класса**, а `include` даёт методы
экземпляра. `base.include(ClassMethods)` добавит `units` каждой перевозке, а
не самому классу перевозок, — и `Shipment.units` не появится.

`extend` вкладывает модуль в одиночный класс получателя. Для класса это ровно
то же, что «стать методами класса».
</details>

## Разбор типичных ошибок

1. **`base.include(ClassMethods)` в хуке.** Методы уедут экземплярам.
2. **Забыть хук вовсе.** `Shipment.units` не появится, и причина будет
   неочевидна: методы экземпляра-то подмешались.
3. **`Rounded`, считающий сам, вместо `super`.** Модуль начнёт знать, как
   устроен пересчёт, — и разъедется с ним при первой же правке.
4. **`include` вместо `prepend` для `Rounded`.** Молча не применится.
5. **`IN_KG[unit]` вместо `fetch`.** Неизвестная единица даст `nil`,
   умножение — `NoMethodError` двумя кадрами позже.
6. **Таблица пересчёта всех пар единиц.** Девять значений вместо трёх, и
   каждое новое добавляет строку в квадрате. Пересчёт идёт через общую
   единицу.
