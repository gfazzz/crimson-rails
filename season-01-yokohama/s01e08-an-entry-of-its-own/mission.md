## Обстановка

Хеш не знает, что он запись. Знание о том, когда две записи об одной
перевозке, живёт в вызывающем коде и повторяется перед каждым сравнением,
поиском и группировкой. Однажды его забудут.

## Приказ

Написать `artifacts/entry.rb`: класс `Abacus::Entry` — объект-значение,
который сам отвечает на вопрос о равенстве.

## Договор вызова

```ruby
entry = Abacus::Entry.new(road: "SJI", cargo: "чай", weight: 800, charge: 40)
entry = Abacus::Entry.from("road" => "SJI", "cargo" => "чай",
                           "weight" => 800, "charge" => 40)

entry.road      # => "SJI"
entry.to_h      # => { road: "SJI", cargo: "чай", weight: 800, charge: 40 }
entry.to_s      # => "SJI чай 800 кг 40 сен"
entry.inspect   # => #<Abacus::Entry road="SJI" cargo="чай" weight=800 charge=40>

[japanese, british].uniq.size    # => 1
{ entry => "строка 388" }[twin]  # => "строка 388"
```

## Критерии приёмки

- [ ] Четыре обязательных именованных поля: `road:`, `cargo:`, `weight:`,
      `charge:`. Умолчаний нет.
- [ ] Поля только читаются (`attr_reader`), запись заморожена.
- [ ] `Entry.from(row)` принимает хеш с любыми ключами — строками или
      символами — и **игнорирует лишние поля**: в ведомости встречаются чужие
      колонки.
- [ ] `to_h` возвращает четыре поля символьными ключами.
- [ ] `==` сравнивает по значению; объект другого класса с теми же полями
      равным не считается; сравнение с `nil` или числом возвращает `false`, а
      не поднимает исключение.
- [ ] `eql?` ведёт себя как `==`.
- [ ] `hash` одинаков у равных записей и учитывает класс.
- [ ] Из этого следует и проверяется: `uniq` схлопывает двойников, запись
      годится ключом хеша и элементом `Set`.
- [ ] `to_s` — строка для человека: без `#<`, без имён полей.
- [ ] `inspect` — строка для отладки: с именем класса, именами полей и
      значениями через `inspect` (строки в кавычках).
- [ ] `to_s` и `inspect` дают **разные** строки.
- [ ] `make test` → двадцать одна зелёная проверка.

## Подводный камень

`==` без `hash` — самая частая половина работы. Сравнение будет истинным,
`uniq` при этом оставит оба объекта, и ошибка проявится не исключением, а
неверным количеством. Именно с такой ошибки начался этот сезон.
