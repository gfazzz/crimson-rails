# Теория — s01e08

## 1. Четыре равенства Ruby

| Метод | Кто зовёт | Что значит |
|---|---|---|
| `equal?` | ты, редко | тот же самый объект (`object_id`). Переопределять нельзя |
| `==` | ты, постоянно | равны по значению. Определяешь сам |
| `eql?` | `Hash`, `Set`, `uniq` | равны и одного типа; по умолчанию — то же, что `equal?` |
| `===` | `case/when`, `grep` | «подходит под»: у класса — принадлежность, у диапазона — вхождение, у регулярного выражения — совпадение |

Самая частая путаница — между `==` и `eql?` на числах:

```ruby
1 == 1.0       # true
1.eql?(1.0)    # false
{ 1 => :a }[1.0]   # nil
```

`Hash` пользуется `eql?` именно затем, чтобы целое и дробное не смешивались в
ключах.

## 2. Контракт `hash`

```
a.eql?(b)  ⟹  a.hash == b.hash
```

Только в эту сторону. Разные объекты с одинаковым хеш-кодом — законная
коллизия, хеш-таблица её разрешит, сверив `eql?`.

Нарушение контракта не вызывает исключения. Оно даёт **тихо неверные
количества**: `uniq` оставляет дубликаты, `Set` принимает одно и то же дважды,
`index[key]` возвращает `nil` при наличии ключа.

Как обычно строят `hash`:

```ruby
def hash = [self.class, field_a, field_b].hash
```

Массив умеет считать хеш-код из своих элементов, поэтому руками комбинировать
ничего не нужно.

## 3. Почему значение обязано быть неизменяемым

```ruby
key = Entry.new(road: "SJI", ...)
index = { key => "строка 388" }

key.instance_variable_set(:@road, "NTK")   # если бы поле было изменяемым
index[key]    # nil — объект лежит в корзине, посчитанной по старому хешу
```

Хеш-таблица раскладывает объекты по корзинам один раз, при вставке. Изменение
поля меняет хеш-код, но не перекладывает объект. Ключ теряется, оставаясь в
таблице: `index.keys` его покажет, `index[key]` — нет.

Отсюда правило: **всё, что может стать ключом, должно быть неизменяемым.**
Ruby следует ему и сам: строковый ключ при вставке в хеш копируется и
замораживается.

## 4. `to_s`, `inspect`, `pp`

| | Кто зовёт | Для кого |
|---|---|---|
| `to_s` | `puts`, `"#{}"`, `String()` | человек |
| `inspect` | `p`, консоль, сообщения об ошибках, `.inspect` | тот, кто ищет ошибку |
| `pretty_print` | `pp` | он же, но для больших структур |

Практическое следствие: **в `inspect` не прячут поля.** Сообщение об ошибке,
в котором объект показан как `#<Entry:0x00007f>`, не помогает; а `to_s`,
подставленный вместо `inspect`, скроет разницу между `""` и `"  "`.

Обратная осторожность: если в объекте есть пароль или ключ, `inspect`
переопределяют так, чтобы он их не печатал, — иначе секрет уедет в журнал
вместе с трассой.

## 5. `Struct`, `Data` и рукописный класс

```ruby
Struct.new(:road, :charge, keyword_init: true)   # изменяемый, есть ==/hash/to_h
Data.define(:road, :charge)                      # Ruby 3.2+: неизменяемый
class Entry; end                                 # всё своими руками
```

| | `Struct` | `Data` | свой класс |
|---|---|---|---|
| `==`, `hash`, `to_h` | да | да | пишешь сам |
| неизменяемость | нет | да | как решишь |
| проверка при создании | нет | нет | да |
| своё поведение | можно дописать | можно дописать | естественно |

`Data` появился в Ruby 3.2 и закрывает ровно тот случай, который мы пишем
руками. Делать это руками стоит один раз — чтобы знать, что именно он делает
за тебя; в рабочем коде на современном Ruby объект-значение начинают с
`Data.define`.

## 6. Симметричность, транзитивность и наследники

Равенство обязано быть:

- **рефлексивным**: `a == a`;
- **симметричным**: `a == b` ⟺ `b == a`;
- **транзитивным**: `a == b` и `b == c` ⟹ `a == c`.

`is_a?` вместо `instance_of?` ломает симметричность, как только наследник
добавляет поле: родитель сравнивает свои четыре поля и говорит «равны»,
наследник сравнивает пять и говорит «нет».

Классическая литература по этому вопросу — глава про `equals` в «Effective
Java»; проблема не языковая, а логическая, и в Ruby выглядит так же.

## 7. Где это в Rails

`ActiveRecord::Base#==` сравнивает **по классу и `id`**:

```ruby
Entry.find(1) == Entry.find(1)     # true: одна строка таблицы
Entry.new(road: "SJI") == Entry.new(road: "SJI")   # false: обе без id
```

Это осознанное решение: строка таблицы — сущность, а не значение, у неё есть
судьба. Два новых объекта без `id` не равны даже при одинаковых полях, потому
что неизвестно, станут ли они одной строкой.

А вот `Money`, `Address`, `Period` внутри приложения делают значениями — и
пишут им ровно то, что ты писал сегодня.
