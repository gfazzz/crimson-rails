# Теория — s01e14

## 1. Как Ruby находит файл

```ruby
require "abacus"
```

1. Если имя начинается с `./` или `/` — это путь, и поиск не нужен.
2. Иначе Ruby перебирает каталоги из `$LOAD_PATH` (он же `$:`) и ищет
   `abacus.rb`, `abacus.so` и прочие расширения.
3. Найденный файл выполняется один раз; его **разрешённый абсолютный путь**
   кладётся в `$LOADED_FEATURES` (он же `$"`).
4. Повторный `require` того же пути возвращает `false` и ничего не делает.

Посмотреть можно прямо в irb:

```ruby
$LOAD_PATH.size
$LOADED_FEATURES.grep(/abacus/)
```

Bundler при запуске добавляет в `$LOAD_PATH` каталоги `lib` всех гемов из
`Gemfile.lock`. Больше никакой магии в подключении гемов нет.

## 2. `require` против `require_relative`

| | `require` | `require_relative` |
|---|---|---|
| ищет | по `$LOAD_PATH` | относительно текущего файла |
| дедупликация | по разрешённому пути | по абсолютному пути |
| зависит от каталога запуска | нет | нет |
| уместно | в геме | в приложении, скриптах, тестах |

Опасность смешения: один и тот же файл, подключённый обоими способами, может
попасть в `$LOADED_FEATURES` дважды под разными записями и выполниться дважды.
Классы переоткроются (обычно безвредно), константы переопределятся (с
предупреждением), а объявления вроде `field :base_rate` выполнятся два раза —
и вот это уже может изменить поведение.

Правило простое: **внутри гема — только `require` с полными именами от `lib`.**

## 3. Пространство имён

```ruby
module Abacus
  class Ledger; end
end
```

Гем занимает одно имя верхнего уровня. Причина практическая: два гема,
определивших `::Entry`, несовместимы, и виноватым окажется тот, кто подключил
оба.

Из этого же следует раскладка: `lib/abacus.rb` для модуля, `lib/abacus/ledger.rb`
для `Abacus::Ledger`. Соответствие имени файла и имени класса — соглашение, но
именно на нём построена автозагрузка в Rails (Zeitwerk), где оно становится
обязательным.

## 4. Порядок подключения

Тело класса выполняется при чтении файла. Значит, всё, что нужно **в момент
чтения**, должно быть загружено раньше:

| Нужно раньше | Не важно |
|---|---|
| `include` / `extend` / `prepend` модуля | вызов метода чужого класса |
| наследование (`< Parent`) | ссылка на константу внутри метода |
| константа в теле класса | всё, что происходит во время работы |

Отсюда практика: точка входа перечисляет файлы в порядке зависимостей, а
внутри файлов взаимных `require` стараются не делать — иначе получается
круговое подключение, которое Ruby разрывает молча, оставляя половину
определений.

## 5. Версия и семантика

```
major.minor.patch
  │     │      └── исправление, поведение не менялось
  │     └───────── добавлено новое, старое работает
  └─────────────── старое сломано, нужна правка у пользователя
```

Версия живёт в **одном** месте — обычно `lib/имя/version.rb`, — и паспорт
читает её оттуда. Две записи разойдутся, вопрос только когда.

Отдельный файл `version.rb` удобен тем, что его можно подключить, не загружая
всю библиотеку: сборщику нужна только версия.

## 6. Паспорт: что обязательно

| Поле | Зачем |
|---|---|
| `name`, `version` | без них гем не собрать |
| `summary` | видно в списке гемов; обязательное |
| `authors`, `license` | без лицензии гем юридически неприменим |
| `files` | что попадёт в архив |
| `require_paths` | что добавится в `$LOAD_PATH` |
| `required_ruby_version` | защита от установки на несовместимый Ruby |
| `metadata` | ссылки на исходники, changelog, требование MFA |

Про `files`: `git ls-files` — заготовка из `bundle gem`. Она работает у
автора и не работает в архиве с исходниками, в контейнере сборки и в
vendored-копии. `Dir[...]` не зависит ни от чего, кроме диска.

Про зависимости: `add_dependency` — то, без чего гем не работает;
`add_development_dependency` считается устаревшим способом, современные гемы
держат инструменты разработки в `Gemfile`.

## 7. Что не кладут в гем

- секреты и ключи — `files` собирает по образцу, и `.env` попадает легко;
- тесты и фикстуры — раздувают архив, никому не нужны при установке;
- скомпилированные артефакты;
- `Gemfile.lock` — он про приложение, а не про библиотеку: гем не должен
  диктовать версии зависимостей своим пользователям.

Проверить, что вошло: `gem build abacus.gemspec && tar -tf abacus-1.0.0.gem`.
