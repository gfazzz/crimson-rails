# Теория — s01e13

## 1. Три способа создать метод из данных

```ruby
# 1. define_method + блок — замыкание видно, трасса нормальная
define_method(name) { @attributes[name] }

# 2. class_eval со строкой — быстрее на вызове, но код собирается текстом
class_eval <<~RUBY, __FILE__, __LINE__ + 1
  def #{name}
    @attributes[:#{name}]
  end
RUBY

# 3. method_missing — решение откладывается до вызова (s01e12)
```

Первый способ — основной. Второй встречается в Rails ради скорости: метод,
созданный из строки, не тащит за собой замыкание, и вызов чуть дешевле. Цена —
подстановка в текст программы: имя поля с кавычкой или пробелом превращается в
синтаксическую ошибку или, хуже, в чужой код. Аргументы `__FILE__` и
`__LINE__` нужны, чтобы трасса указывала на настоящее место.

Правило: **строкой — только когда имена приходят из твоего кода и измерено,
что это важно.**

## 2. Почему `def` не видит окружение

```ruby
def field(name)
  def name_method          # ← новая область видимости
    name                   # NameError: undefined local variable
  end
end
```

`def` открывает новую область видимости: тело метода не имеет доступа к
локальным переменным места объявления. Это не ограничение реализации, а
решение языка — иначе метод случайно захватывал бы всё окружение и удерживал
его в памяти.

`define_method` принимает **блок**, а блок — замыкание. Отсюда доступ к `name`
и `default` и отсюда же цена: замыкание живёт столько же, сколько метод.

## 3. Что ещё умеет `define_method`

```ruby
define_method(:charge) { |multiplier = 1| @charge * multiplier }   # аргументы
define_method(:total, instance_method(:charge))                    # из UnboundMethod
define_method(:total, ->(x) { x * 2 })                             # из лямбды
```

Тонкость с лямбдой: она сохраняет строгую проверку числа аргументов, а блок —
нет. Метод, созданный из `proc`, простит лишний аргумент, что для метода
неестественно.

Видимость задаётся отдельно:

```ruby
define_method(:secret) { ... }
private :secret
```

## 4. Макросы: как это выглядит в Rails

```ruby
class Entry < ApplicationRecord
  belongs_to :road
  validates :charge, numericality: true
  scope :heavy, -> { where("weight > 2000") }
end
```

Все три строки — вызовы методов класса в теле класса. `belongs_to` создаёт
`road`, `road=`, `build_road`, `road_changed?`; `validates` складывает правило
в список, принадлежащий классу; `scope` определяет метод класса из лямбды.

Пара, которую стоит узнавать в чужом коде:

```ruby
def self.included(base)
  base.extend(ClassMethods)     # макросы
  base.include(InstanceMethods) # поведение
end
```

Столько же строк, сколько в нашем `Macros`, и ровно тот же смысл.

## 5. Состояние класса и наследование

Переменная класса не наследуется — у наследника её просто нет:

```ruby
class Parent
  @fields = [:a]
  def self.fields = @fields
end

class Child < Parent; end
Child.fields    # nil
```

Три способа это починить:

| Способ | Что получается |
|---|---|
| `def self.fields = @fields ||= []` | у наследника свой пустой список |
| хук `inherited` с `dup` | наследник получает копию родительского |
| `superclass.fields + @fields` | вычисление при каждом обращении |

Второй — самый частый. Главное — `dup`: без него списки общие, и наследник
меняет родителя.

`class_attribute` в Rails делает именно это, добавляя возможность
переопределить значение у наследника, не задев родителя.

## 6. `send`, `public_send`, `instance_variable_get`

| Метод | Обходит | Когда уместен |
|---|---|---|
| `public_send` | ничего | обращение по имени, пришедшему извне |
| `send` | видимость | тесты, метапрограммирование внутри своего класса |
| `instance_variable_get` | и видимость, и интерфейс | отладка; в рабочем коде почти никогда |

Правило: **чем больше метод обходит, тем меньше у него места в обычном коде.**
Имя поля, пришедшее из параметров запроса или из файла настроек, передают
только в `public_send` и только после проверки по списку известных.

## 7. Цена динамики и что с ней делать

Созданный метод стоит ровно столько же, сколько написанный. Стоит другое:

- **время загрузки**: двадцать два поля — двадцать два `define_method`;
- **память**: каждый метод держит своё замыкание;
- **читаемость**: `grep` по коду не найдёт `base_rate`.

Последнее лечится не отказом от макросов, а дисциплиной: список полей должен
быть виден в одном месте (наш `fields`), а имена — перечислимы. Объект, про
который нельзя спросить «что ты умеешь», плох независимо от того, как он
сделан.
