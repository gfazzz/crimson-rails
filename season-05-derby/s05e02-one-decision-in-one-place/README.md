## Дерби, телеграфный зал, 6 октября, 09:30

Телеграфный зал — за стеклянной перегородкой в конце конторы. Двенадцать
аппаратов, у каждого своя линия, и у каждой линии свой почерк стука.

Мисс Эшворт ведёт маршрутную книгу одиннадцать лет. Книга толстая, в
кожаном переплёте, на каждой странице — код и куда уходит всё, что на этот код
приходит: какая линия, какой стол, кто принимает.

Она читает твою вчерашнюю ленту и возвращает её.

— Здесь адрес дороги — `/companies/7`. Семь — это что?

— Номер строки в реестре.

— Номер строки в вашем реестре мне ничего не скажет. — Эшворт открывает книгу
наугад. — По проводу передают код. `GNR`, `MID`, `NER`. Заглавными: у аппарата

никто на линии не знает, что это седьмая строка.

— А если адрес будет и по номеру, и по коду?

Она смотрит на тебя поверх книги.

— Тогда у меня будет две страницы на одну дорогу. И однажды на одну из них
запишут, а на другую нет.

**11:00.** Заходит Кершоу — за телеграммой на свой пост. Смотрит через плечо
Эшворт на твою ленту.

— Код у вас где проверяется?

— В модели: две–четыре буквы.

— А адрес?

— То есть в двух местах. — Кершоу качает головой. — На раме номер рычага

## Чему ты научишься

- Делать адресом записи её код: `to_param` и `param:`.
- Ставить ограничение на параметр маршрута и понимать, что оно решает раньше
  контроллера.
- Выносить решение, которое нужно нескольким действиям, в `before_action`.
- Брать образец из одного места — модели — и в модели, и в маршрутах.
- Приёму, который дороже синтаксиса: **у вещи один адрес.** Второй адрес
  кажется удобством, а оказывается вторым ключом к той же записи, и однажды
  по разным ключам придут к разному.

Подробнее — в [`theory.md`](theory.md).

## Теория: номер, отлитый в чугуне

### Адрес — это ключ

Помощник `company_path(road)` строит адрес, спрашивая у записи `to_param`. По
умолчанию это номер строки. Переопределить — одна строка:

```ruby
class Company < ApplicationRecord
  def to_param = code
end
```

Теперь `company_path(mid)` — `/companies/MID`, и все ссылки, построенные
помощником, поменялись сами. Все, кроме собранных строкой.

В контроллере ищут по тому же ключу:

```ruby
Company.find_by!(code: params[:code])
```

`find_by!` — тот же `find`, только по другому столбцу: нет записи —
`RecordNotFound` — 404.

### Параметр говорит, что несёт

```ruby
resources :companies, only: %i[index show], param: :code
```

`param: :code` меняет образец маршрута: `/companies/:code` вместо
`/companies/:id`. Работает и без этого — `params[:id]` понесёт код, — но тогда
адрес обещает номер, а несёт другое.

### Ограничение решает раньше контроллера

```ruby
resources :companies, only: %i[index show], param: :code,
                      constraints: { code: Company::CODE }
```

Ограничение — часть таблицы маршрутов, а не проверка в действии. Адрес
`/companies/mid` не подходит под образец — значит, этот маршрут его не берёт,
и Rails идёт к следующему. Не подошёл ни один — `RoutingError` — 404.

Разница с проверкой в контроллере не в коде ответа, а в том, **когда** принято
решение. Проверка в контроллере случается, когда маршрут уже выбран. Через две
серии появится `/companies/new`, и понадобится, чтобы маршрут дороги его не
взял: `new` строчными под образец кода не подходит.

### Одно решение в одном месте

```ruby
class Company < ApplicationRecord
  CODE = /[A-Z]{2,4}/
  validates :code, format: { with: /\A#{CODE.source}\z/ }
end
```

Образец один, и спрашивают его двое: модель — когда дорогу заводят, таблица
маршрутов — когда её открывают. Два образца однажды разойдутся, и дорогу можно
будет завести, но нельзя будет открыть.

То же в контроллере:

```ruby
before_action :set_company, only: :show

private

def set_company
  @company = Company.find_by!(code: params[:code])
end
```

Сегодня это решение нужно одному действию. Через три серии — четырём, и все
четыре получат дорогу одинаково.

## Проверка: ADA задаёт вопросы

```
[ADA · ЧАСТНАЯ ЛИНИЯ]
ТРИ ВОПРОСА.
```

**1.** ADA: «Почему не оставить и номер, и код? Старые ссылки не сломаются».

<details><summary>Ответ</summary>

Потому что тогда у дороги два адреса, и это два ключа к одной записи. Ссылки
разойдутся по двум адресам, закладки и журналы тоже; через год кто-то начнёт
кешировать страницу по адресу — и одна копия устареет, а другая нет.

Если старые ссылки жалко, честный ответ на них — перенаправление 301 на новый
адрес: «теперь это там, насовсем». Не вторая страница.
</details>

**2.** ADA: «Ограничение на параметр или проверка в контроллере — ответ всё
равно 404. В чём разница?»

<details><summary>Ответ</summary>

В том, кто решает и когда. Ограничение — строка таблицы маршрутов: видно в
`rails routes`, работает до выбора действия, и адрес, который под него не
подходит, достаётся следующему маршруту.

Проверка в контроллере — после того, как маршрут выбран. Если следующим
маршрутом должен был ответить другой — поздно: запрос уже ушёл не туда.
</details>

**3.** ADA: «Зачем образец кода держать константой в модели?»

<details><summary>Ответ</summary>

Чтобы решение было одно. Модель проверяет введённое, маршрут — адрес; оба
спрашивают одно и то же — «похоже ли это на код дороги». Написанный дважды,
ответ однажды будет дан по-разному: модель пропустит пятибуквенный код,
маршрут не откроет.
</details>

## Разбор типичных ошибок

1. **`to_param` не переопределён.** Контроллер ищет по коду, а ссылки ведут по
   номеру.
2. **Оба адреса сразу.** Одна дорога под двумя ключами.
3. **`params[:id]`, несущий код.** Работает — и обманывает того, кто читает.
4. **Нет ограничения на параметр.** Любая строка доходит до действия; адрес
   `new` через две серии окажется кодом дороги.
5. **Образец в маршрутах свой.** Модель и таблица разойдутся — на длине, на
   регистре, на одной букве.
6. **`find_by` без `!`.** Нет дороги — `nil` — 500 вместо 404.
7. **Поиск без учёта регистра.** `mid` и `MID` — два адреса одной дороги.
