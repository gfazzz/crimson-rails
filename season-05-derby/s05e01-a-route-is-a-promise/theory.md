# Теория — s05e01

## 1. Запрос и ответ

Окно в реестр — это программа, которая отвечает на запросы по HTTP. Больше она
ничего не делает.

| Запрос | Ответ |
|---|---|
| **глагол**: `GET`, `POST`, `PATCH`, `DELETE` | **код**: `200`, `303`, `404`, `422`… |
| **адрес**: `/companies/7` | **заголовки**: тип, куда перенаправить |
| **заголовки**: что готов принять | **тело**: страница, поток, JSON |
| **тело** (у форм) | |

Глагол — это не украшение. `GET` обещает ничего не менять: его можно
повторить, закешировать, отправить заранее. Всё, что меняет реестр, идёт
другими глаголами, и этой серии они не нужны.

## 2. Таблица маршрутов

`config/routes.rb` — не код, который выполняется на каждый запрос, а
объявление, из которого Rails при загрузке строит таблицу: глагол и образец
адреса → контроллер и действие.

```ruby
get "companies/:id", to: "companies#show", as: :company
```

Таблицу видно целиком:

```bash
bin/rails routes                 # все
bin/rails routes -c companies    # только ведущие в CompaniesController
bin/rails routes -g company      # только те, где в строке есть «company»
```

И её можно спросить, не отправляя запроса:

```ruby
Rails.application.routes.recognize_path("/companies/7")
# => { controller: "companies", action: "show", id: "7" }
```

Маршруты перебираются **сверху вниз**, и побеждает первый подошедший. Что из
этого следует, видно в следующей серии.

## 3. `resources`

Семь маршрутов на один ресурс — соглашение Rails, а не закон HTTP. Оно
окупается тем, что у всех приложений на Rails одинаковая табличка:

| Действие | Глагол и адрес | Имя |
|---|---|---|
| `index` | `GET /companies` | `companies_path` |
| `new` | `GET /companies/new` | `new_company_path` |
| `create` | `POST /companies` | — |
| `show` | `GET /companies/:id` | `company_path(road)` |
| `edit` | `GET /companies/:id/edit` | `edit_company_path(road)` |
| `update` | `PATCH /companies/:id` | — |
| `destroy` | `DELETE /companies/:id` | — |

`only:` и `except:` оставляют нужные. Правило одно: **таблица маршрутов —
обещание**, и обещать можно только то, что выполнишь. Маршрут без действия не
опасен сегодня, но его прочтут: следующий, кто сядет за код, помощник
`new_company_path`, форма, которую на него отправят.

Есть и `resource` в единственном числе — для того, что существует в одном
экземпляре на человека (`resource :profile`): без `index` и без `:id` в адресе.

## 4. Контроллер и неявная отрисовка

```ruby
def show
  @company = Company.find(params[:id])
end
```

Что происходит без единой строки про ответ:

1. Rails создаёт **новый объект контроллера на каждый запрос**. Переменные
   объекта не переживают запрос — и не должны.
2. `params[:id]` — кусок адреса, который в образце назван `:id`. Всегда
   строка.
3. После действия Rails ищет шаблон `companies/show` для формата запроса
   (`.html.erb`) и отдаёт его с кодом 200.
4. Переменные объекта контроллера видны в шаблоне. Это единственный способ,
   которым действие передаёт что-то представлению.

Если нужно ответить не шаблоном — `render`, `redirect_to` или `head`. Один
раз: второй вызов в том же действии — `DoubleRenderError`.

## 5. Коды, которые нужны сезону

| Код | Значит | Где в сезоне |
|---|---|---|
| **200** OK | вот что просили | списки, страницы |
| **303** See Other | сделано, смотри там | после формы (e04) |
| **404** Not Found | того, о чём спросили, нет | отсутствующая запись, чужая запись (e06) |
| **406** Not Acceptable | в таком виде не отвечу | формат, которого нет (e11) |
| **422** Unprocessable Content | запрос понят, но принять нельзя | неудачная форма (e04) |
| **500** Internal Server Error | окно сломалось | никогда нарочно |

Коды читают не люди. Их читают браузер, поисковик, телеграфный аппарат,
который спросит реестр по коду дороги, — и Turbo, который по коду решает, что
делать со страницей.

## 6. Откуда берётся 404

В Rails есть таблица исключений, которые означают не поломку, а ответ:
`config.action_dispatch.rescue_responses`. В ней, среди прочего:

| Исключение | Код |
|---|---|
| `ActionController::RoutingError` | 404 |
| `ActiveRecord::RecordNotFound` | 404 |
| `ActionController::ParameterMissing` | 400 |
| `ActionController::UnknownFormat` | 406 |
| `ActiveRecord::RecordInvalid` | 422 |

Поэтому `find` даёт 404 сам. В разработке вместо страницы 404 показывается
отладочная — это `config.consider_all_requests_local`; на проде — файл
`public/404.html`.

`find_by` исключения не бросает: вернёт `nil`, и дальше решать тебе. Иногда
это правильно — когда «нет» тоже ответ. Для страницы одной записи — нет.

## 7. Имена маршрутов и `to_param`

```ruby
company_path(road)   # => "/companies/7"
```

Помощник спрашивает у записи `road.to_param` — по умолчанию это `id` строкой.
Поэтому адрес строкой (`"/companies/#{road.id}"`) и адрес от помощника
совпадают — до того дня, когда `to_param` поменяют. В следующей серии это и
произойдёт.
