## Чему ты научишься

- Писать контроллер Stimulus: цели, значения, действия.
- Подключать поведение так, чтобы оно работало после визита Turbo, фрейма и
  отказа формы — не только при первой загрузке.
- Брать числа правила с сервера, а не писать их в скрипте второй раз.
- Проверять, что окно и сервер говорят одно и то же.
- Приёму, который дороже синтаксиса: **своё JS — только там, где сервер не
  нужен.** Всё, что сервер знает, он и рисует (s05e09). В окно уходит только
  то, для ответа на что хватает окна, — и оно ничего не решает.

Подробнее — в [`theory.md`](theory.md).

## Теория: у стола

### Контроллер

```js
import { Controller } from "@hotwired/stimulus"

export default class extends Controller {
  static targets = ["pence", "reading"]
  static values = { penceInShilling: Number, shillingsInPound: Number }

  connect() { this.show() }

  show() {
    const pence = Number(this.penceTarget.value)
    this.readingTarget.textContent = Number.isInteger(pence) && pence > 0 ? this.read(pence) : "—"
  }
}
```

Файл `app/javascript/controllers/money_controller.js` — контроллер `money`.
Регистрировать его не нужно: `controllers/index.js` подключает всё, что лежит в
папке (importmap, `pin_all_from`).

### Разметка говорит, что к чему

```erb
<p data-controller="money"
   data-money-pence-in-shilling-value="<%= ApplicationHelper::PENCE_IN_SHILLING %>"
   data-money-shillings-in-pound-value="<%= ApplicationHelper::SHILLINGS_IN_POUND %>">
  <%= form.label :pence %>
  <%= form.number_field :pence, aria: { describedby: "pence-reading" },
        data: { money_target: "pence", action: "input->money#show" } %>
  <output id="pence-reading" data-money-target="reading" aria-live="polite">—</output>
</p>
```

| Атрибут | Что значит |
|---|---|
| `data-controller="money"` | этот элемент ведёт контроллер `money` |
| `data-money-target="pence"` | элемент доступен как `this.penceTarget` |
| `data-action="input->money#show"` | на событие `input` — метод `show` |
| `data-money-pence-in-shilling-value` | `this.penceInShillingValue`, уже числом |

Скрипт не ищет элементы по классам и не вешает обработчики: разметка сама
говорит, что она такое. Это s03e01 — атрибут как договор с разметкой, — только
договор уже написан за тебя.

### Подключение, а не загрузка

`connect()` зовётся каждый раз, когда элемент с `data-controller` **появился**
в документе: при первой загрузке, после визита Turbo, после отказа формы,
после фрейма и потока. И `disconnect()` — когда исчез.

В s05e07 было видно, почему это важно: для Turbo страница не загружается, а
подменяется, и код на `DOMContentLoaded` выполнится один раз — на первой
странице. Stimulus следит за документом сам и подключает поведение к тому,
что пришло.

Это та же мысль, что у своего элемента в s03e09 — `connectedCallback`, —
только без своего тега: поведение прицепляется к обычной разметке.

### Одно правило — в двух местах

Правило чтения фунтов теперь есть и в `ApplicationHelper#money`, и в
контроллере. Это цена, и её не прячут:

- **числа** правила — одни: они приходят в скрипт значениями, из констант
  помощника;
- **согласие** — проверяется: проверка серии набирает восемь сумм и сравнивает
  чтение окна с тем, что говорит сервер;
- **решение** — одно: чтение в окне ничего не решает, пенсы проверяет модель.

**1.** ADA: «Почему не Turbo? Пусть сервер и читает сумму — правило ведь у него».

<details><summary>Ответ</summary>

Потому что вопрос «сколько это в фунтах» не требует ничего, чего нет в окне.
Запрос на каждую клавишу — это запрос на каждую клавишу: провод, очередь,
задержка, и чтение, которое отстаёт от набора. Turbo хорош, когда правда на
сервере; здесь правды нет — есть число и арифметика.
</details>

**2.** ADA: «Правило чтения повторено в Ruby и в JS. Это против одного
решения в одном месте».

<details><summary>Ответ</summary>

Да, и это цена. Её уменьшают трижды: числа правила приходят из одного места;
согласие двух копий проверяется на многих суммах; и решает только одна копия
— серверная. Окно лишь показывает.

Если бы чтение в окне что-то решало — например, запрещало отправку, — копий
не должно было бы быть вовсе.
</details>

**3.** ADA: «`turbo:load` приходит после каждого визита. Зачем Stimulus?»

<details><summary>Ответ</summary>

Затем, что визит — не единственный способ, которым разметка появляется. Фрейм
(s05e08) и поток (s05e09) вставляют куски без визита, и `turbo:load` о них не
скажет. Форма, вернувшаяся с отказом, — тоже. Stimulus подключает поведение
к элементу, когда появился **элемент**, откуда бы он ни пришёл, — и снимает,
когда исчез.
</details>

## Разбор типичных ошибок

1. **Код на `DOMContentLoaded`.** Работает на первой странице и нигде больше.
2. **Чтение только по вводу.** Бланк, вернувшийся с отказом, стоит без чтения,
   пока не нажмёшь клавишу.
3. **Числа правила в скрипте.** Две копии чисел — та же беда, что два образца
   кода (s05e02).
4. **«NaN» и «£-1».** Неверная сумма — не сумма.
5. **Чтение не связано с полем.** Глазами видно, вслух — нет.
6. **Проверка платы в окне вместо модели.** То, что у стола, никто не
   проверяет.

- «Чем значение контроллера лучше числа, записанного в скрипте?»

Красный анти-паттерн:

- *«ADA, перепиши форму бланка на Stimulus, чтобы всё проверялось сразу, без
  сервера».* — перепишет, и проверки появятся в окне — там, где их никто не
  проверяет. Сервер по-прежнему обязан проверять всё сам, и копий правил
  станет вдвое больше. Спрашивать надо иначе: «что в этой форме нельзя
  сделать без запроса к серверу — и только это оставить окну».
