# Теория — s05e10

## 1. Когда своё JS, а когда нет

Сезон 3 учил писать JavaScript; этот сезон учит, где его **не** писать.

| Задача | Чем | Почему |
|---|---|---|
| показать то, что знает сервер | шаблон, фрейм, поток | правда на сервере, рисовать он уже умеет |
| изменить то, что хранит сервер | форма, 303 / 422 / поток | решать должен сервер |
| ответить на вопрос, для которого хватает окна | Stimulus | запрос не нужен |
| состояние, которое живёт в окне (s03e10) | Stimulus, адрес | серверу оно ни к чему |

Признак — «что нужно, чтобы ответить». Если хватает того, что уже на экране, —
окно. Если нужна база — сервер.

## 2. Устройство Stimulus

Stimulus — это одна идея: **поведение прицепляется к разметке атрибутами** и
само подключается, когда разметка появляется.

```html
<div data-controller="money"
     data-money-pence-in-shilling-value="12">
  <input data-money-target="pence" data-action="input->money#show">
  <output data-money-target="reading"></output>
</div>
```

| Понятие | Атрибут | В контроллере |
|---|---|---|
| контроллер | `data-controller="имя"` | класс в `имя_controller.js` |
| цель | `data-имя-target="x"` | `this.xTarget`, `this.xTargets`, `this.hasXTarget` |
| значение | `data-имя-x-value="…"` | `this.xValue` — уже нужного типа |
| действие | `data-action="событие->имя#метод"` | метод |
| класс | `data-имя-x-class="…"` | `this.xClass` |
| выход | `data-имя-x-outlet="селектор"` | другой контроллер |

У части элементов событие по умолчанию: для `input` — `input`, для формы —
`submit`, для кнопки — `click`; тогда пишут просто `money#show`.

## 3. Жизненный цикл

| Метод | Когда |
|---|---|
| `initialize()` | один раз на экземпляр |
| `connect()` | элемент с `data-controller` появился в документе |
| `disconnect()` | исчез |
| `xTargetConnected(el)` | появилась цель |
| `xValueChanged(new, old)` | изменилось значение — и один раз при подключении |

Stimulus следит за документом (`MutationObserver`) и не знает, откуда пришла
разметка: из первой загрузки, визита Turbo, фрейма, потока или вставки своим
кодом. Поэтому поведение работает везде одинаково — и снимается, когда
элемент ушёл, без утечек.

`xValueChanged` зовётся и при подключении — поэтому часто хватает его одного
вместо `connect`.

## 4. Stimulus и свой элемент

| | свой элемент (s03e09) | Stimulus |
|---|---|---|
| где поведение | в классе элемента | в контроллере |
| как прицепить | свой тег `<crimson-time>` | атрибут у любого элемента |
| жизненный цикл | `connectedCallback` / `disconnectedCallback` | `connect` / `disconnect` |
| параметры | атрибуты, `observedAttributes` | значения (`static values`) |
| несколько поведений на элементе | нет | да: `data-controller="a b"` |

По сути одно и то же. Stimulus удобнее там, где поведение — у обычной
разметки, которую рисует сервер: поле, кнопка, список.

## 5. Где взять данные

Контроллер не ходит за данными — он берёт их из разметки:

- **значения** (`values`) — числа, строки, логические, массивы, объекты (JSON
  в атрибуте);
- **сама разметка** — текст элементов, значения полей.

Всё, что контроллеру нужно знать от сервера, сервер кладёт в разметку при
отрисовке. Так правило остаётся у сервера, а окно — только читает.

## 6. Проверка поведения в окне

Здесь, как в s05e07, проверка идёт в браузере. Что именно проверяется и
почему не иначе:

| Свойство | Как |
|---|---|
| чтение на каждую клавишу | `send_keys` по одной, после каждой — чтение |
| без запросов | число записей `performance.getEntriesByType('resource')` до и после |
| после визита | бланк открывается щелчком со страницы дороги, метка на окне цела |
| согласие с сервером | восемь сумм сравниваются с `ApplicationHelper#money` |

Проверять контроллер по тексту файла бессмысленно: верный код можно написать
десятью способами, а свойство одно.

## 7. Чего эта серия не закрывает

- **Stimulus с запросами к серверу** — возможно (`fetch` в контроллере), и
  почти всегда хуже фрейма или потока;
- **выходы (`outlets`) и связи между контроллерами** — окну не нужны;
- **сборщики и npm** — importmap хватает; `bin/importmap pin` подключает
  пакет, не собирая ничего.
