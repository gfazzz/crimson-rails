— Автомат умеет спрашивать, — говорит Эшворт. — Не «покажите страницу», а

— Как он читает?

— Как договорились. Поля по именам, числа — числами. — Она кладёт на стол
карточку с образцом. — Страницу он не поймёт: там заголовки, ссылки, шапка.
А если спросить у окна то, чего оно не умеет, — пусть так и скажет. Не
присылает страницу вместо ответа.

## Чему ты научишься

- Отвечать одним действием в нескольких видах: `respond_to` с HTML, JSON и
  CSV.
- Понимать, как Rails узнаёт, что нужно спрашивающему: расширение адреса и
  заголовок `Accept`.
- Писать форму JSON-ответа через Jbuilder — как договор: имена, числа, полные
  адреса.
- Отдавать файл, а не страницу: `send_data` и `Content-Disposition`.
- Приёму, который дороже синтаксиса: **ответ — для того, кто спросил.** Код,
  тип и форма ответа существуют не для красоты: по ним машина решает, что
  получила. Неправильный вид ответа хуже отказа — его примут.

Подробнее — в [`theory.md`](theory.md).

## Теория: три спрашивающих

### Один адрес — три вида

```ruby
def index
  @company = Company.find_by!(code: params[:company_code])
  @settlements = @company.settlements.order(:period)

  respond_to do |format|
    format.html
    format.json
    format.csv { send_data csv, type: :csv, disposition: "attachment",
                                 filename: "#{@company.code}-settlements.csv" }
  end
end
```

| Как спросили | Что получили |
|---|---|
| `GET /companies/MID/settlements` из браузера | страница, `index.html.erb` |
| `…/settlements.json` или `Accept: application/json` | JSON, `index.json.jbuilder` |
| `…/settlements.csv` | файл, `text/csv`, «сохранить как MID-settlements.csv» |
| `…/settlements.xml` | 406: в таком виде не отвечу |

Расширение в адресе — `(.:format)` в каждом маршруте, который объявил
`resources`. Заголовок `Accept` — то, что спрашивающий сам говорит о себе.

### JSON — договор

```ruby
# settlements/index.json.jbuilder
json.company @company.code
json.settlements @settlements do |settlement|
  json.period settlement.period
  json.pence settlement.pence
  json.reading money(settlement.pence)
  json.state settlement.state
end
```

Три правила, и каждое — из прошлых сезонов:

- **деньги — целыми пенсами** (s04e02). Чтение фунтами — рядом строкой, не
  вместо: аппарату нужно число, а «£801 0s 0d» — для глаз;
- **имена полей не меняют** — как адреса (s05e02): на них уже рассчитывает
  тот, кто читает;
- **адреса — полные**: `company_settlements_url`, со схемой и хостом.
  Аппарат не знает, откуда пришёл ответ.

### Файл, а не страница

`send_data` с `disposition: "attachment"` говорит браузеру «сохранить», а
имя файла — какой. На странице ссылка на файл помечена `download`: Turbo не
перехватывает таких ссылок, иначе он запросил бы файл и попытался нарисовать
его страницей (s05e07).

### Отказ — в формате вопроса

Аппарат, спросивший `…/ZZZ/settlements.json`, должен получить 404 — и JSON.
Страница 404 для него — строка, которую не разобрать.

```ruby
rescue_from ActiveRecord::RecordNotFound do |error|
  raise error unless request.format.json?
  render json: { error: "not_found", message: "Такой записи в реестре нет." }, status: :not_found
end
```

Человеку по-прежнему отвечает страница 404: для него исключение идёт дальше.

### Приёмка — обход, а не список

Приёмка сезона — отдельный файл проверок. Она не знает адресов наизусть: она
читает таблицу маршрутов, засевает реестр и обходит **каждую** страницу окна.
На каждой спрашивает то, что сезон обещал с первой серии:

| Обещание | Серия |
|---|---|
| у каждого маршрута есть кому ответить | s05e01 |
| на реестре, где всё есть, — 200; где ключ ведёт в никуда — 404 | s05e01, s05e06 |
| страница читается вслух: язык, главная часть, один заголовок, путь в реестр | s05e03 |
| каждая форма уходит туда, где её принимают | s05e04 |
| ни одна ссылка во фрейме не ведёт в «Content missing» | s05e08 |
| обход запросами GET ничего в реестре не меняет | s05e05 |

Маршрут, добавленный завтра, попадёт в обход сам.

## Проверка: ADA задаёт вопросы

```
[ADA · ЧАСТНАЯ ЛИНИЯ]
ТРИ ВОПРОСА. ПОСЛЕДНИЕ В СЕЗОНЕ.
```

**1.** ADA: «Аппарат попросил `.xml`. Почему не отдать ему страницу — пусть
разбирается?»

<details><summary>Ответ</summary>

Потому что он разбираться не будет — он примет. Аппарат получит 200, решит,
что спросил правильно, и начнёт читать страницу как строки реестра. Ошибка
появится не здесь, а через неделю в сверке.

406 говорит правду: в таком виде не отвечу. Её поймёт и аппарат, и тот, кто
его настраивал.
</details>

**2.** ADA: «В JSON пенсы — числом, а рядом ещё и строка "£801 0s 0d". Зачем
обе?»

<details><summary>Ответ</summary>

Число — для машины: его складывают, сравнивают, сверяют. Строка — для
человека, который смотрит на ответ глазами, и для аппарата, который печатает
ленту. Вместо числа строку ставить нельзя: машине её пришлось бы разбирать
обратно, и разбирать по-своему.
</details>

**3.** ADA: «Приёмка обходит все страницы. Чем это лучше, чем проверить каждую
серию ещё раз?»

<details><summary>Ответ</summary>

Тем, что серии проверяют то, что в них сделано, а обход — то, что сезон
обещал **везде**. Новая страница, форма или фрейм, добавленные после сезона,
попадут в обход без единой строки в проверке: таблица маршрутов сама скажет,
что обходить.
</details>

## Разбор типичных ошибок

1. **Деньги в JSON строкой или дробью.** Машине нужно целое число пенсов.
2. **Адреса в JSON без хоста.** Аппарат не знает, откуда пришёл ответ.
3. **CSV страницей.** Касса видит текст в окне вместо файла.
4. **Ссылка на CSV без `download`.** Turbo перехватит её и попытается
   нарисовать.
5. **`format.any` — «на всё отвечу страницей».** Вместо 406 — неправда.
6. **404 для аппарата — страницей.** Разбирать нечего.
7. **Пустой список вместо 404.** «Дороги нет» и «у дороги нет расчётов» —
   разные ответы.
