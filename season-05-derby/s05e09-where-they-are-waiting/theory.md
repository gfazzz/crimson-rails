# Теория — s05e09

## 1. Что такое поток

Ответ с типом `text/vnd.turbo-stream.html` — это список элементов:

```html
<turbo-stream action="replace" target="settlement_42">
  <template><tr id="settlement_42"> … </tr></template>
</turbo-stream>
<turbo-stream action="append" target="payments_company_7">
  <template><li>1891-09: £801 0s 0d — оплачено.</li></template>
</turbo-stream>
```

Turbo разбирает его и выполняет по порядку. `<template>` — потому что его
содержимое браузер разбирает, но не показывает: в нём можно нести строку
таблицы, которая вне `<table>` была бы выброшена.

Поток приходит тремя путями:

| Путь | Когда | Где в курсе |
|---|---|---|
| ответ на форму | Turbo прислал `Accept` с потоком первым | здесь |
| `<turbo-stream>` в разметке страницы | страница вставлена в документ | — |
| канал (`turbo_stream_from`) | сервер сам шлёт, когда что-то случилось | сезон 6 |

По умолчанию Turbo просит поток только у форм с глаголом не `GET`. Ссылку или
форму `GET` можно попросить о том же атрибутом `data-turbo-stream`; окну это не
нужно.

## 2. `respond_to`

```ruby
respond_to do |format|
  format.turbo_stream                          # payments/create.turbo_stream.erb
  format.html { redirect_to …, status: :see_other }
end
```

Rails сравнивает `Accept` запроса со списком и выбирает первый подходящий
**по порядку в `Accept`**, а не в блоке. Не подошёл никто — `UnknownFormat` —
406.

`format.turbo_stream { render turbo_stream: [...] }` — поток без файла
шаблона. Файл удобнее, когда действий больше одного.

## 3. Действия

| Действие | Что делает | Шаблон обязателен |
|---|---|---|
| `append`, `prepend` | дописать в конец / в начало цели | да |
| `before`, `after` | вставить перед целью / после | да |
| `replace` | заменить цель целиком | да |
| `update` | заменить содержимое цели | да |
| `remove` | убрать цель | нет |
| `refresh` | обновить страницу (Turbo 8) | нет |

`target` — один id; `targets` — селектор, и действие выполняется со всеми
совпадениями.

Хитрость `append`: если в добавляемом куске есть элемент с тем же id, что уже
лежит в цели, Turbo **уберёт старый** и допишет новый в конец. Поэтому
повторная доставка того же потока не удваивает строк.

## 4. Помощники turbo-rails

```erb
<%= turbo_stream.replace @settlement %>
<%# цель dom_id(@settlement), содержимое render(@settlement) %>

<%= turbo_stream.append "payments", partial: "payments/entry", locals: { … } %>

<%= turbo_stream.update "status" do %>текст<% end %>
```

Передавая запись, помощник сам берёт `dom_id` и частичный шаблон по
соглашению. Это и есть причина держать один частичный шаблон на строку:
строка таблицы и строка в потоке — одна и та же разметка.

## 5. Цели

Поток ничего не создаёт на пустом месте. Правило: **каждая цель есть на
странице до ответа**, и на каждой странице, с которой форму могут отправить.

| Цель | Что поставить заранее |
|---|---|
| строка, которую заменят | `id` у строки |
| список, в который допишут | пустой контейнер с `id` |
| сообщение | пустая живая область с `id` и `role` |

Живая область заранее — требование доступности: машины, читающие вслух,
объявляют изменения в областях, которые уже были в документе, и молчат о
новых.

## 6. Поток и фрейм

Форма внутри фрейма шлёт заголовок `Turbo-Frame`. Если ответ — поток, Turbo
применяет его ко всему документу, а не к фрейму: цель ищется везде. Если
ответ — 303, Turbo идёт за перенаправлением с заголовком фрейма и берёт
оттуда фрейм (s05e08). Оба пути работают, и поэтому контроллер может о фреймах
не знать.

## 7. Поток или своё JS

| | поток | своё JS (s03e05–e07) |
|---|---|---|
| где правда | в базе | копия в окне |
| что по проводу | разметка | данные |
| где знание «куда класть» | в потоке | в скрипте |
| без скрипта | 303, форма работает | разметка работает, запрос — нет |
| когда хорош | правда на сервере, куски уже умеют рисоваться | состояние живёт в окне, сервер не нужен |

Второй случай — `s05e10`.

## 8. Чего эта серия не закрывает

- **поток по каналу, без запроса** — сезон 6: подтверждение, пришедшее по
  проводу, появится у всех, у кого открыт лист;
- **своё действие потока** (`StreamActions`) — можно, окну не нужно;
- **`refresh` с морфингом** — Turbo 8, упомянут.
