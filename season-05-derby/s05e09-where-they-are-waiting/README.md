## Чему ты научишься

- Отвечать на форму потоком: `respond_to` и `format.turbo_stream`.
- Писать действия потока: `replace`, `append`, `update` — и их цели.
- Ставить цели на страницу заранее: строка с `dom_id`, пустая живая область,
  пустой журнал.
- Отвечать тем, кто потока не просил, как всегда: 303 или 422.
- Приёму, который дороже синтаксиса: **поток — не ответ, а распоряжение
  странице.** Распоряжение с адресом, которого нет, выполняется молча — никак.
  Проверять поток — значит приложить его к странице и посмотреть, что стало.

Подробнее — в [`theory.md`](theory.md).

## Теория: распоряжение с адресом

### Два ответа на одно действие

```ruby
def create
  @settlement.pay!
  respond_to do |format|
    format.turbo_stream
    format.html { redirect_to company_settlements_path(@company), status: :see_other }
  end
end
```

Форма, отправленная через Turbo, просит в `Accept` первым
`text/vnd.turbo-stream.html`. `respond_to` видит это и отрисовывает
`payments/create.turbo_stream.erb`. Форма без Turbo — обычный `Accept` — и
ответ как в s05e04: 303.

### Действия и цели

```erb
<%= turbo_stream.replace @settlement %>

<%= turbo_stream.append dom_id(@company, :payments) do %>
  <li><%= @settlement.period %>: <%= money(@settlement.pence) %> — оплачено.</li>
<% end %>

<%= turbo_stream.update dom_id(@company, :payment_status) do %>
  Расчёт <%= @settlement.period %> с <%= @company.code %> оплачен.
<% end %>
```

| Действие | Что делает с целью |
|---|---|
| `replace` | заменяет элемент целиком |
| `update` | заменяет содержимое, элемент остаётся |
| `append` / `prepend` | дописывает в конец / в начало |
| `before` / `after` | вставляет рядом |
| `remove` | убирает |

`turbo_stream.replace @settlement` — цель `dom_id(@settlement)`, содержимое —
частичный шаблон `settlements/_settlement`. Тот же шаблон рисует строку в
таблице: строка в таблице и строка в потоке — одна.

### Цели ставят заранее

Поток ничего не создаёт на пустом месте. Всё, во что он целится, обязано быть
на странице **до** ответа:

```erb
<tr id="<%= dom_id(settlement) %>"> … </tr>
<p id="<%= dom_id(@company, :payment_status) %>" role="status"></p>
<p id="<%= dom_id(@company, :payment_alert) %>" role="alert"></p>
<ul id="<%= dom_id(@company, :payments) %>"></ul>
```

Пустые живые области — не лишние теги. Читающий вслух услышит то, что в
области появилось, только если область была на странице раньше (s03e04).

Страница, с которой нажимают, — не одна: лист расчётов открывают сам по себе
и видят вклеенным в страницу дороги (s05e08). Цели обязаны найтись на обеих —
и находятся, потому что обе рисует один шаблон.

### Устаревшая страница

Два кассира открыли лист, оба видят «Оплатить». Первый нажал. Второй нажал
минутой позже — `pay!` под блокировкой бросает `AlreadyPaid` (s04e09).

```ruby
rescue Settlement::AlreadyPaid => error
  @settlement.reload
  render :refused, status: :unprocessable_content    # поток: строка как есть + причина
```

Поток отказа приносит на устаревшую страницу правду: строку в том виде, в
каком она есть, без кнопки, и причину в область для отказов.

### Что было в Нью-Йорке

| | `telegraph`, сезон 3 | поток, здесь |
|---|---|---|
| кто решает, что показать | скрипт в окне | сервер |
| что приходит | данные, JSON | готовые куски разметки |
| куда класть | знает скрипт | сказано в потоке |
| состояние | в окне, отдельно от отрисовки | в базе |
| без скрипта | журнал работает из разметки | форма работает через 303 |

Ни одно не лучше вообще. Поток лучше там, где правда живёт в базе и сервер
уже умеет её рисовать.

## Проверка: ADA задаёт вопросы

```
[ADA · ЧАСТНАЯ ЛИНИЯ]
ТРИ ВОПРОСА.
```

**1.** ADA: «Почему поток, а не 303 на лист? Лист перерисуется и покажет то же».

<details><summary>Ответ</summary>

Покажет — ценой всего листа. Двести строк отрисуются заново, прокрутка
вернётся к началу, фокус уйдёт с кнопки, на которой стоял кассир. Поток
меняет ровно три места и больше ничего.

И 303 никуда не делся: кто потока не просил — без Turbo, программа по
проводу, — получает его.
</details>

**2.** ADA: «Цель потока — id строки. Что будет, если этого id на странице нет?»

<details><summary>Ответ</summary>

Ничего. Turbo не найдёт цели и молча пропустит действие. Ответ 200, в
журнале сервера — успех, в базе — оплачено; на экране — прежняя кнопка
«Оплатить». Кассир нажмёт ещё раз и получит отказ, которого не поймёт.

Поэтому проверка серии прикладывает поток к той самой странице, с которой
нажали, и требует, чтобы каждая цель нашлась.
</details>

**3.** ADA: «Два кассира нажали "Оплатить" на одной строке. Что увидит второй?»

<details><summary>Ответ</summary>

Отказ, 422, — и потоком: его строка заменится на настоящую, уже без кнопки,
а в области для отказов появится причина. Выплата при этом случилась один
раз: `pay!` читает строку под блокировкой (s04e09).

Устаревшая страница — не ошибка кассира. Это то, что бывает всегда, когда
окон больше одного.
</details>

## Разбор типичных ошибок

1. **Цель потока, которой нет на странице.** Всё «работает», ничего не видно.
2. **Строка без `id`.** Заменять нечего.
3. **Живая область появляется вместе с текстом.** Её не услышат.
4. **`remove` вместо `replace`.** Строка оплаченного расчёта исчезла из листа.
5. **Поток несёт целую страницу.** Макет внутри строки таблицы.
6. **Отказ — 200 или 500.** Turbo не покажет его или покажет страницу ошибки.
7. **Без `format.html`.** Без Turbo выплата отвечает 406.
8. **Оплата мимо `pay!`.** Выплата без блокировки — дважды.

Красный анти-паттерн:

  они на странице, с которой нажали».
