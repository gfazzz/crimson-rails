# Теория — s05e08

## 1. Протокол фрейма

Всё, что делает фрейм, — один обмен:

```
GET /companies/MID/edit
Turbo-Frame: card_company_7
```

```html
<!-- ответ: любая страница, в которой где-то есть -->
<turbo-frame id="card_company_7"> … </turbo-frame>
```

Turbo берёт из ответа фрейм с тем же id и ставит его содержимое на место
старого. Остальной ответ выбрасывается. Если такого фрейма в ответе нет —
событие `turbo:frame-missing` и надпись «Content missing».

Сервер может знать, что пришёл запрос фрейма: `turbo_frame_request?` и
`turbo_frame_request_id` в контроллере. turbo-rails пользуется этим сам — на
запрос фрейма отдаёт ответ без макета приложения, потому что его всё равно
выбросят.
Тебе это знание почти никогда не нужно: страница, которая одинаково хороша
целиком и кусками, проще страницы, которая ведёт себя по-разному.

## 2. Кто куда ведёт

| Элемент | Что он ведёт |
|---|---|
| ссылка или форма внутри фрейма | этот фрейм |
| … с `data-turbo-frame="другой"` | фрейм `другой` |
| … с `data-turbo-frame="_top"` | всю страницу |
| фрейм с `target="_top"` | все его ссылки ведут всю страницу |
| ссылка вне фрейма с `data-turbo-frame="id"` | фрейм `id` снаружи |

`data-turbo-action="advance"` на фрейме или ссылке — сменить при этом и
адрес в окне: иначе после щелчка во фрейме адрес остаётся прежним, и
«обновить» покажет не то, что на экране.

## 3. Ленивые и немедленные

```erb
<%= turbo_frame_tag "sheet", src: sheet_path %>                  <%# сразу %>
<%= turbo_frame_tag "sheet", src: sheet_path, loading: :lazy %>  <%# когда видно %>
```

Ленивый фрейм подгружается, когда попадает в видимую часть окна
(`IntersectionObserver`). Содержимое внутри тега — то, что
видно до подгрузки: «загружается…» или ссылка на тот же адрес для тех, у кого
скрипта нет.

Что выигрывает страница:

- ответ страницы дороги не ждёт двести шестьдесят восемь расчётов;
- лист расчётов кешируется (сезон 6) отдельно от страницы;
- ошибка в листе не роняет страницу дороги: во фрейме будет сообщение, а
  страница — на месте.

## 4. Формы во фрейме

Форма внутри фрейма шлёт `Turbo-Frame` так же, как ссылка. Дальше — коды
сезона:

| Ответ формы | Что сделает Turbo |
|---|---|
| 303 | пойдёт по `Location` **с тем же заголовком** и возьмёт фрейм оттуда |
| 422 | возьмёт фрейм из этого ответа |
| 200 | ошибка: ответ на форму обязан перенаправить или отказать |

Поэтому после правки контроллер отвечает ровно как в s05e05, а обязанность
держать фрейм — на странице, куда он перенаправил.

## 5. `dom_id`

```ruby
dom_id(@company)            # => "company_7"
dom_id(@company, :card)     # => "card_company_7"
dom_id(Company.new)         # => "new_company"
```

Один способ дать id куску страницы про запись — и одинаковый на всех
страницах, где этот кусок встречается. `dom_id` берёт номер строки, а не
`to_param`: id элемента страницы в адрес не попадает.

## 6. Фрейм и доступность

`<turbo-frame>` для читающего вслух — обычный контейнер: у него нет роли и
имени. Если содержимое фрейма заменяется у человека на глазах (правка на
месте), имеет смысл, чтобы после замены фокус оказался в форме, а после
сохранения — на новой карточке. Turbo ставит фокус на элемент с `autofocus`
внутри нового содержимого.

## 7. Чего эта серия не закрывает

- **обновление нескольких кусков одним ответом** — `s05e09`, потоки;
- **фрейм, который сам перезапрашивается по времени** — сезон 6;
- **`<turbo-frame refresh="morph">`** — фрейм, который при обновлении
  страницы морфится, а не заменяется; Turbo 8, окну не нужен.
