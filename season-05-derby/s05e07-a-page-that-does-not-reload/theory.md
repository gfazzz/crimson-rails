# Теория — s05e07

## 1. Что такое визит

Turbo Drive называет переход **визитом**. У визита два вида:

| Вид | Когда | Что делает |
|---|---|---|
| `advance` | ссылка, форма | запрашивает страницу, заменяет тело, `pushState` |
| `replace` | `data-turbo-action="replace"` | то же, но `replaceState`: без новой записи в истории |
| `restore` | «назад», «вперёд» | показывает снимок из кеша; запрос — только если снимка нет |

Порядок событий визита, на которые можно подписаться:

```
turbo:click → turbo:before-visit → turbo:visit → turbo:before-fetch-request
→ turbo:before-fetch-response → turbo:before-render → turbo:render → turbo:load
```

`turbo:load` приходит после каждого визита — и один раз при первой загрузке.
Это его отличие от `DOMContentLoaded`, который приходит только при первой.

## 2. Что заменяется

| Часть | Что с ней делает Turbo |
|---|---|
| `<body>` | заменяет целиком |
| `<title>`, `<meta>` в `<head>` | заменяет |
| стили и скрипты в `<head>` | оставляет те, что совпадают по адресу; новые добавляет |
| `data-turbo-track="reload"` | если адрес такого ресурса сменился — полная перезагрузка |
| элементы с `data-turbo-permanent` и `id` | переносит из старого тела в новое как есть |
| `window`, `document`, соединения | не трогает |

`data-turbo-track="reload"` у стилей и скриптов макета — для выката: новая
версия окна со старым скриптом в памяти вела бы себя странно, и Turbo, увидев
новый адрес ресурса, перезагружает окно.

## 3. Постоянные элементы

```erb
<div id="telegram-draft" data-turbo-permanent>…</div>
```

Условия: `id` одинаков на старой и новой странице, и на новой элемент тоже
помечен. Переносится **старый** элемент — со всем, что в нём изменилось с
загрузки: значение поля, раскрытость, позиция прокрутки, проигрываемый звук.

Постоянный элемент — для того, что принадлежит окну, а не странице: черновик,
плеер, открытое соединение. Не для данных: данные на новой странице могут
быть другими, а постоянный элемент их не обновит.

## 4. Кеш снимков

Уходя со страницы, Turbo клонирует её тело и кладёт в кеш (по умолчанию —
десять последних). Снимок используется дважды:

- при `restore` — показывается вместо запроса;
- при `advance` на уже посещённый адрес — показывается **превью**, пока идёт
  запрос, и заменяется ответом.

| Что объявить | Где | Эффект |
|---|---|---|
| `data-turbo-temporary` | у элемента | убрать его из снимка |
| `turbo-cache-control: no-preview` | `<meta>` страницы | снимок не показывать как превью |
| `turbo-cache-control: no-cache` | `<meta>` страницы | снимок не хранить вовсе |

Сообщения `flash`, раскрытые меню, подсказки — `data-turbo-temporary`.
Страницы, где устаревшее содержимое опасно показать даже на полсекунды, —
`no-cache`.

## 5. Когда Drive не нужен

| Случай | Как |
|---|---|
| ссылка на файл, который браузер должен скачать | `data-turbo="false"` у ссылки |
| ссылка на другой сайт | Turbo её и так не трогает |
| часть страницы, которую нельзя трогать | `data-turbo="false"` у контейнера |
| всё приложение | не подключать `turbo-rails` — и потерять всё сразу |

## 6. Подтверждение

```erb
<%= button_to "Убрать из реестра", company_path(@company), method: :delete,
              form: { data: { turbo_confirm: "Убрать?" } } %>
```

Turbo зовёт `window.confirm` до отправки; «нет» — запроса нет вовсе. Без
скрипта вопроса не будет, и форма уйдёт: подтверждение — удобство, а не
защита. Защита — у модели (s04e05) и, в сезоне 7, у прав.

`Turbo.config.forms.confirm` можно заменить своим окном вопроса; сезону
хватает браузерного.

## 7. Как это проверяется

В процессе, без браузера, видно всё, что делает сервер: коды, адреса, тело.
Не видно, что сделал браузер с этим телом. Поэтому серия идёт в браузере:

| Что | Чем |
|---|---|
| браузер | Chrome без окна, через Selenium |
| сервер | Puma, которую Capybara поднимает в том же процессе |
| «не перезагружалась» | метка на `window`, которую перезагрузка стирает |
| подтверждение | `accept_confirm` / `dismiss_confirm` |

Это те же системные тесты Rails (`test/system`), только собранные вне
приложения. Их предмет — сезон 8.

## 8. Чего эта серия не закрывает

- **часть страницы, которая обновляется сама** — `s05e08`, фреймы;
- **обновление по ответу формы без перехода** — `s05e09`, потоки;
- **поведение, которое должно переподключаться после визита** — `s05e10`,
  Stimulus;
- **морфинг** (`turbo_refreshes_with method: :morph`) — Turbo 8 умеет
  обновлять страницу, сохраняя прокрутку и фокус; окну пока не нужен.
