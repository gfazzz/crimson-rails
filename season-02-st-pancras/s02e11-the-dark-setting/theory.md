# Теория — s02e11

## 1. Как записывают цвет

```css
color: #7b1220;                 /* шестнадцатеричная запись, 3/4/6/8 знаков */
color: rgb(123 18 32 / 0.8);    /* современный синтаксис, без запятых */
color: hsl(353 75% 28%);        /* тон, насыщенность, светлота */
color: oklch(38% 0.14 20);      /* воспринимаемая светлота */
color: currentColor;            /* нынешнее значение color */
color: transparent;             /* = rgb(0 0 0 / 0) */
```

`#rgba` и `#rrggbbaa` — те же записи с прозрачностью: `#7b122080`.

`hsl()` удобнее `rgb()` для подбора оттенков одного тона, но обманывает:
`hsl(60 100% 50%)` (жёлтый) и `hsl(240 100% 50%)` (синий) объявлены одинаково
светлыми, а выглядят совершенно по-разному. `oklch()` этого не делает — его
светлота воспринимаемая, и потому палитра, построенная на нём, даёт
предсказуемый контраст.

## 2. Палитра

```css
html {
  --paper: #f6f1e7;
  --ink: #1c1a17;
  --rule: #8a7f68;
  --crimson: #7b1220;
  --on-crimson: #f6f1e7;
}
```

Два правила именования:

1. **по роли, а не по виду.** `--paper`, не `--beige`: в тёмном наборе бумага
   станет почти чёрной, и `--beige: #16151a` будет читаться как насмешка;
2. **пара для каждого фона.** Всякий раз, когда объявляется цвет фона, рядом
   объявляется цвет набора поверх него: `--crimson` и `--on-crimson`. Иначе
   однажды красное окажется на красном.

## 3. Тёмный набор

```css
@media (prefers-color-scheme: dark) {
  html {
    --paper: #16151a;
    --ink: #e8e3d8;
    --rule: #7a7466;
    --crimson: #f0929c;
    --on-crimson: #16151a;
  }
}
```

Значения `prefers-color-scheme`: `light`, `dark`. Настройка приходит из
системы, часто по расписанию — днём светлая, вечером тёмная.

Внутри добавки объявляют **только палитру**. Всё прочее (отступы, кегли,
раскладка) пришлось бы поддерживать дважды, и однажды правку внесут в одну.

Если переключатель на странице всё-таки нужен, его делают поверх запроса:
атрибут на корне (`data-theme="dark"`), правило `[data-theme="dark"]` с той же
палитрой — и значение по умолчанию, взятое из системной настройки, а не
навязанное.

## 4. `color-scheme`

```css
html { color-scheme: light dark; }
```

Не свойство оформления, а объявление для браузера: какие темы полоса
поддерживает. По нему красятся встроенные части — поля ввода, полосы
прокрутки, выпадающие списки, фон за краем документа.

Без него тёмная полоса получает светлую полосу прокрутки и белую вспышку в
момент загрузки, до применения свода.

## 5. Почему не инверсия

```css
html { filter: invert(1) hue-rotate(180deg); }   /* ✘ */
```

Три причины:

1. выворачивается **всё**, включая изображения: схема линии станет негативом;
2. красное становится голубым, а оттенки — своими дополнениями. Смысл цвета
   теряется: красная помета перестаёт быть красной;
3. светлый штрих на тёмном фоне расплывается оптически (ирадиация). Текст,
   годный в светлом наборе, в вывернутом выглядит жирнее и хуже читается.

Поэтому в тёмном наборе берут не чистый белый (`#e8e3d8`) и более светлые
акцентные цвета, чем в светлом: `#7b1220` → `#f0929c`.

## 6. Коэффициент контраста

Отношение относительных яркостей, от 1 до 21. Считается по WCAG:

```
L = 0.2126 R + 0.7152 G + 0.0722 B     (после гамма-коррекции каналов)
contrast = (L_светлее + 0.05) / (L_темнее + 0.05)
```

| Что | Порог | Критерий |
|---|---|---|
| основной текст | 4,5 | 1.4.3 (AA) |
| крупный текст: от 24px, или 19px полужирного | 3 | 1.4.3 (AA) |
| линии и элементы управления, несущие смысл | 3 | 1.4.11 (AA) |
| текст, повышенный уровень | 7 | 1.4.6 (AAA) |

Три вещи, о которых забывают:

- коэффициент считается **для пары**. Изменив фон, надо пересчитать все тексты
  на нём;
- порог — нижняя граница, а не цель. `#e8e3d8` на `#16151a` даёт 14 и читается
  лучше, чем чистый белый с его 19;
- **чисто декоративные** линии порога не требуют. Границы ячеек расписания
  декоративными не являются: без них не видно, где кончается одна станция.

## 7. Цвет — не единственный признак

WCAG 1.4.1: цвет не должен быть **единственным** способом передать смысл.

| Вместо | Добавить |
|---|---|
| ссылка только цветом | подчёркивание |
| ошибка поля только красной рамкой | текст ошибки и значок |
| статус только цветной точкой | подпись или форма значка |
| легенда графика только цветом | штриховка, форма маркера, подпись |

Дальтонизм красно-зелёного ряда есть примерно у каждого двенадцатого мужчины и
каждой двухсотой женщины. Прибавьте к этому чёрно-белую печать и экран на
солнце.

## 8. `light-dark()`

```css
html { color-scheme: light dark; }
body {
  color: light-dark(#1c1a17, #e8e3d8);
  background-color: light-dark(#f6f1e7, #16151a);
}
```

Функция берёт первое значение при светлой схеме и второе при тёмной, опираясь
на `color-scheme`. Медиазапрос при этом не нужен вовсе.

Когда удобнее она: цветов мало и они объявлены в одном месте. Когда удобнее
палитра с медиазапросом: тем больше двух (светлая, тёмная, повышенный
контраст, печать) — тогда каждая тема остаётся отдельным блоком, который
видно целиком.

## 9. Соседние настройки читателя

```css
@media (prefers-contrast: more) { … }
@media (prefers-contrast: less) { … }
@media (forced-colors: active) { … }   /* режим высокой контрастности системы */
```

В режиме `forced-colors` система **сама** назначает цвета, а авторские
отменяет. Полагаться на цвет фона там нельзя вовсе; вместо этого есть
системные ключевые слова (`Canvas`, `CanvasText`, `LinkText`, `ButtonFace`) и
свойство `forced-color-adjust`.

Главное правило того режима: всё, что нарисовано фоном или рамкой нулевой
толщины, исчезнет. Значок, сделанный фоном, надо продублировать текстом.
