# Теория — s02e09

## 1. От чего считается размер

| Считается от | Единицы |
|---|---|
| корневого кегля | `rem` |
| собственного кегля | `em`, `ex`, `ch`, `cap`, `lh` |
| окна | `vw`, `vh`, `vi`, `vb`, `vmin`, `vmax`, `dvh`, `svh`, `lvh` |
| контейнера | `cqw`, `cqi`, `cqb` (нужны контейнерные запросы) |
| ничего | `px` |
| бумаги | `pt`, `pc`, `cm`, `mm`, `in`, `Q` |

Последняя строка на экране не работает: `1in` браузер считает равным `96px` по
соглашению, а не по линейке. На печати те же единицы честные — и там им место.

`px` в CSS — тоже не физический пиксель экрана, а «условный пиксель»: на
плотных экранах он занимает несколько настоящих. Годится он для одного:
толщины линии, которая не должна расти вместе с текстом.

## 2. `rem` и `em`

```css
html  { }                       /* кегль читателя, не объявлен */
body  { font-size: 1.125rem; }  /* 1.125 × кегль читателя */
.card { font-size: 0.9em; }     /* 0.9 × кегль родителя */
```

`em` считается от собственного кегля элемента — и потому **складывается** при
вложенности: три уровня по `0.9em` дают `0.73`, пять дают `0.59`. Классическая
беда вложенных списков.

Когда `em` уместен: размер обязан зависеть от текста рядом.

```css
button { padding: 0.5em 1em; }   /* поле растёт вместе с подписью */
h2 { margin-block-end: 0.5em; }  /* зазор пропорционален заголовку */
```

Правило: **`rem` по умолчанию, `em` — когда зависимость от соседнего текста
осмысленна.**

## 3. Кегль читателя

Значение по умолчанию — `16px`, но это **настройка**, а не константа.
Читатель, которому трудно читать, ставит `20px` или `24px` в настройках
браузера — и ждёт, что страницы вырастут.

```css
html { font-size: 16px; }    /* ✘ настройка отменена молча */
html { font-size: 100%; }    /* ✔ то же самое, но от настройки */
html { font-size: 112.5%; }  /* ✔ крупнее настройки на восьмую */
```

Приём «62.5%, чтобы `1rem` равнялся десяти пикселям» когда-то был популярен.
Он делает ровно то, чего делать нельзя: пересчитывает настройку читателя в
удобные автору числа, а потом возвращает её обратно — и любой забытый
пересчёт даёт текст в десять пикселей.

## 4. Знак как единица

```css
p { max-inline-size: 66ch; }
```

`1ch` — ширина знака `0` в текущем шрифте, `1ex` — высота строчной `x`,
`1cap` — высота прописной. Все три меняются вместе со шрифтом и кеглем.

Мера строки (мерная длина) — от 45 до 75 знаков для прозы. Короче — глаз
прыгает, длиннее — теряет начало следующей строки. Число это не из вкуса, а из
типографики: у Брингхерста оно выведено из скорости возвратного движения глаза.

В пикселях мера строки неверна по определению: при другом кегле в те же
пиксели влезет другое число букв.

## 5. Доли окна

```
vw / vh    1% ширины / высоты окна
vi / vb    1% по строке / по блоку — логические, переживают смену письма
vmin/vmax  меньшая / большая из двух
svh/lvh/dvh  малая / большая / динамическая высота окна на телефоне
```

Последняя тройка появилась из-за адресной строки в мобильных браузерах:
`100vh` там больше видимой высоты, и низ блока оказывается под панелью. `100dvh`
следит за ней, `100svh` берёт наименьший вариант.

Доли окна никогда не употребляют для кегля **без границ**: на телефоне текст
станет нечитаем, на широком мониторе — огромен.

## 6. `clamp()`, `min()`, `max()`

```css
font-size: clamp(1rem, 0.9rem + 0.8vi, 1.4rem);
inline-size: min(100%, 40rem);
padding-inline: max(1rem, 3vi);
```

`clamp(a, b, c)` — то же, что `max(a, min(b, c))`: не меньше `a`, не больше
`c`, в остальном `b`.

**Ловушка доступности.** Предпочтительный член обязан содержать слагаемое,
считающееся от шрифта:

```css
clamp(1.8rem, 1.5rem + 1.5vi, 2.6rem)   ✔
clamp(1.8rem, 5vi, 2.6rem)              ✘
```

Во втором случае размер зависит только от ширины окна. Читатель увеличивает
шрифт — окно не изменилось, текст остался прежним. Это нарушение WCAG 1.4.4
(Resize Text), и на глаз оно неотличимо от правильного варианта.

Внутри `min()`, `max()` и `clamp()` работает арифметика без `calc()`:
складывать и вычитать можно разные единицы, умножать и делить — только на
числа.

## 7. Пользовательские свойства

```css
html { --gutter: 1.5rem; }
main { padding: var(--gutter); }
main { padding: var(--gutter, 1rem); }   /* запасное значение */
```

Три отличия от переменных препроцессора:

1. **наследуются** — объявленные у корня, доступны всей полосе; объявленные
   у элемента, доступны его потомкам;
2. **живут в каскаде** — их можно переопределить правилом, медиазапросом,
   темой (и это `s02e11`);
3. **считаются в браузере** — значение подставляется при вычислении, а не при
   сборке.

Незамеченная ловушка: `var(--нет-такого)` без запасного значения делает
объявление недействительным, и свойство берётся по наследству. Не ошибка, не
предупреждение — просто другое значение.

## 8. `line-height` без единиц

```css
body { line-height: 1.5; }     /* ✔ множитель, наследуется как множитель */
body { line-height: 24px; }    /* ✘ длина, наследуется как длина */
```

С единицей потомок получает **вычисленную длину** родителя: заголовок кеглем
в два раза крупнее унаследует межстрочное расстояние мелкого текста и слипнется
сам с собой.

## 9. Область просмотра

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Без неё мобильный браузер притворяется, что окно шириной около 980 условных
пикселей, и уменьшает готовую страницу целиком — вместе со всеми мерами.

Чего в ней быть не должно: `user-scalable=no` и `maximum-scale` меньше
двойки. Оба отнимают у читателя щипок для увеличения; WCAG 1.4.4 считает это
нарушением, а iOS с некоторых версий их и вовсе игнорирует — но в коде они
по-прежнему встречаются.
