## Чему ты научишься

- Различать единицы, которые считаются от кегля, от знака и от окна.
- Объявлять шкалу кеглей пользовательскими свойствами — в одном месте.
- Делать размер текучим через `clamp()` так, чтобы увеличение шрифта
  продолжало работать.
- Мерить строку в знаках, а не в пикселях.
- Приёму, который дороже синтаксиса: **корневой кегль принадлежит читателю.**
  Всё остальное считается от него, и тогда «крупный набор» получается сам.

Подробнее — в [`theory.md`](theory.md).

## Теория: от чего считать

### Три семейства единиц

| Считается от | Единицы | Где уместно |
|---|---|---|
| кегля | `rem` (корневого), `em` (своего) | отступы, зазоры, ширины блоков |
| знака | `ch`, `ex`, `cap` | мера строки |
| окна | `vw`, `vi`, `vb`, `dvh` | текучие размеры, полноэкранные блоки |
| ничего | `px` | толщина линейки, и только |

`pt`, `mm`, `cm`, `in` на экране не означают длину: браузер пересчитывает их по
условному разрешению 96 на дюйм. Это единицы бумаги, и там они честные.

### `rem` против `em`

```css
html  { /* кегль не объявлен: его назначил читатель */ }
body  { font-size: 1.125rem; }     /* 1.125 от кегля читателя */
.note { font-size: 0.9em; }        /* 0.9 от кегля родителя */
```

`rem` — от корня, один и тот же везде. `em` — от собственного кегля элемента,
и потому складывается при вложенности: список внутри списка внутри списка
уезжает в ничто.

Правило: **`rem` по умолчанию, `em` — когда размер обязан зависеть от текста
рядом.** Внутреннее поле кнопки в `em` растёт вместе с её подписью; в `rem` —
нет.

### Кегль читателя — не пустяк

Настройку «крупный шрифт» ставят не из любопытства. `font-size: 16px` в корне
отменяет её молча: читатель жмёт «крупнее», и ничего не происходит.

Поэтому корневой кегль не объявляют вовсе. А если очень надо — только
процентом: `font-size: 112.5%` считается от настройки, а не вместо неё.

### Шкала

```css
html {
  --type-small: clamp(0.82rem, 0.8rem + 0.1vi, 0.9rem);
  --type-body:  clamp(1rem, 0.96rem + 0.2vi, 1.125rem);
  --type-h1:    clamp(1.8rem, 1.5rem + 1.5vi, 2.6rem);
}
h1 { font-size: var(--type-h1); }
```

Пользовательские свойства наследуются: объявленные у корня, они доступны всей
полосе. Шкала из пяти ступеней — это пять решений, принятых один раз; кегль,
выбранный на месте, — шестое решение, о котором шкала не знает.

### `clamp()` и одна ловушка

```css
clamp(минимум, предпочтительное, максимум)
```

Предпочтительный член обязан содержать слагаемое в `rem`:

```css
clamp(1.8rem, 1.5rem + 1.5vi, 2.6rem)   /* ✔ растёт и от окна, и от кегля */
clamp(1.8rem, 5vi, 2.6rem)              /* ✘ увеличение шрифта не работает */
```

Во втором случае размер зависит только от ширины окна. Читатель жмёт
«крупнее» — окно не изменилось, размер тот же. Это нарушение WCAG 1.4.4, и
ловится оно только проверкой, потому что на глаз выглядит одинаково.

### Мера строки

```css
p { max-inline-size: 66ch; }
```

`1ch` — ширина знака `0` текущего шрифта. Читаемая строка — от сорока пяти до
семидесяти пяти знаков; дальше глаз теряет начало следующей.

В пикселях эта мера неверна по определению: при другом кегле в те же пиксели
влезет другое число букв.

### Область просмотра

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Без этой строки телефон печатает страницу шириной около 980 условных пикселей
и уменьшает её целиком — вместе со всеми мерами. `user-scalable=no` и
`maximum-scale=1` отнимают у читателя щипок для увеличения; это не настройка
вида, а отобранная возможность.

### Где это в Rails

```erb
<%# app/views/layouts/application.html.erb %>
<meta name="viewport" content="width=device-width, initial-scale=1">
```

Rails кладёт эту строку в макет по умолчанию, и потому её никто не замечает —
пока кто-нибудь не соберёт вид без макета. Шкала же живёт в
`app/assets/stylesheets` и к Rails отношения не имеет вовсе: это тот же свод.

## Проверка: ADA задаёт вопросы

```
[ADA · ВНУТРЕННЯЯ ЛИНИЯ]
ТРИ ВОПРОСА.
```

**1.** ADA: «`font-size: 16px` у корня. Читатель поставил в браузере крупный
шрифт. Что он увидит?»

<details><summary>Ответ</summary>

То же, что и раньше. Объявление в пикселях считается не от настройки, а вместо
неё — настройка перестаёт действовать, и никакого сообщения об этом нет.

Именно поэтому корневой кегль не объявляют. Если размер по умолчанию не
устраивает — процент: он считается от настройки читателя.
</details>

**2.** ADA: «`clamp(1rem, 4vi, 2rem)`. Что здесь неверно?»

<details><summary>Ответ</summary>

Предпочтительный член зависит только от ширины окна. Увеличение шрифта в
браузере окна не меняет — значит, текст не растёт вовсе.

Чинится слагаемым: `clamp(1rem, 0.9rem + 1.5vi, 2rem)`. Теперь размер растёт и
от окна, и от кегля читателя.
</details>

**3.** ADA: «`max-inline-size: 600px` против `66ch`. В чём разница на
практике?»

<details><summary>Ответ</summary>

В пикселях мера строки верна ровно для одного кегля. Читатель увеличил шрифт —
в те же шестьсот пикселей влезло не шестьдесят шесть знаков, а сорок, и строки
стали рваными.

`ch` считается от знака текущего шрифта, поэтому мера остаётся мерой при любом
кегле. Ровно то же говорит Прингл про дюймы.
</details>

## Разбор типичных ошибок

1. **`font-size` в пикселях у корня.** Настройка читателя отменена молча.
2. **Кегль, выбранный на месте.** Шестое решение мимо шкалы; через год их
   двенадцать.
3. **`clamp()` без слагаемого в `rem`.** Увеличение шрифта перестаёт работать.
4. **Голая доля окна как кегль.** На узком экране нечитаемо, на широком
   огромно.
5. **Мера строки в пикселях.** Верна ровно для одного кегля.
6. **Отступы в пикселях.** Текст вырос, воздух вокруг него — нет.
7. **`pt` и `mm` на экране.** Единицы бумаги, пересчитанные по условному
   разрешению.
8. **Нет объявления области просмотра.** Телефон уменьшает полосу целиком.
9. **`user-scalable=no`.** У читателя отобран щипок.
10. **`line-height` с единицей.** Наследуется готовая длина, а не множитель.

толщины линеек, и полоса переживает крупный набор без единой правки.

Он разъезжается: заголовки вырастают, поля остаются, таблица налезает на
служебную колонку. Ровно то, о чём говорил Прингл.

порядок, не та единица. Вместе они означают одно: тот, кто готовил образец,
работал по памяти, а не по макету.
