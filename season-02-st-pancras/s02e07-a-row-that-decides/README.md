- Знать, что `flex: 1 1 auto` значит по частям и почему `flex-basis` важнее

## Теория: ряд

### Два объявления

```css
nav ul {
  display: flex;      /* дети встали в ряд */
  flex-wrap: wrap;    /* ряду разрешено стать двумя */
}
```

Без второго ряд не переносится: он сжимает детей до предела, а дальше
вылезает за край. Именно так выглядит большинство «поломанной вёрстки на
телефоне».

### Две оси

| | Главная ось | Поперечная ось |
|---|---|---|
| задаётся | `flex-direction` | перпендикулярно ей |
| распределяет | `justify-content` | `align-items` (`align-content` — ряды) |
| у `row` это | слева направо | сверху вниз |
| у `column` это | сверху вниз | слева направо |

Путаница между ними — самая частая ошибка с флексом. Смена
`flex-direction: column` меняет смысл обоих свойств разом, и `justify-content:
center` внезапно центрирует по вертикали.

### Зазор — не поле

```css
gap: 0.5rem 1.5rem;   /* между рядами; между пунктами */
```

`gap` не принадлежит ни одному из детей: он появляется **между** ними и не
появляется по краям. Полями то же самое делается с оговорками — крайнему
полагается не то же, что среднему, — и ещё одна тонкость: во флексе поля
**не схлопываются**. Собственное поле ребёнка прибавится к `gap`, а не
растворится в нём.

Отсюда правило: объявил `gap` — сними у детей поля по той же оси.

### `flex` по частям

```css
flex: 1 1 auto;
/*    ↑ ↑ ↑                                              */
/*    │ │ flex-basis:  с какого размера начинаем          */
/*    │ flex-shrink:   можно ли сжимать                   */
/*    flex-grow:       делить ли излишек                  */
```

Считается всё от `flex-basis`, а не от `width`: сначала браузер берёт базу,
складывает, сравнивает с шириной ряда и делит разницу. `flex: 1` — сокращение
для `1 1 0%`, то есть «раздели поровну, забыв про содержимое». `flex: auto` —
`1 1 auto`, «раздели излишек пропорционально содержимому». Разница между ними
и есть разница между равными колонками и колонками по тексту.

### Что флекс не делает

Флекс раскладывает **в одном направлении**. Ряд ничего не знает о ряде ниже:
колонки двух соседних рядов не выравниваются между собой. Для этого нужна
сетка — она в `s02e08`.

И ещё: `order` и `row-reverse` меняют порядок на экране, не трогая порядок в
разметке. Клавиатура, голосовой браузер и выделение текста идут по разметке.
Поэтому переставлять ими можно только то, где порядок не несёт смысла, — а
чаще нельзя вовсе.

### Где это в Rails

```erb
<nav>
  <ul>
    <% @lines.each do |line| %>
      <li><%= link_to line.name, line_path(line) %></li>
    <% end %>
  </ul>
</nav>
```

Шаблон печатает список; сколько в нём пунктов — решают данные. Ряд, который
сам решает, когда стать двумя, — единственный, который это переживёт: заранее
неизвестно ни число пунктов, ни длина названий.

## Проверка: ADA задаёт вопросы

```
[ADA · ВНУТРЕННЯЯ ЛИНИЯ]
ТРИ ВОПРОСА.
```

**1.** ADA: «`display: flex` без `flex-wrap`. Пунктов стало вдвое больше. Что
произойдёт?»

<details><summary>Ответ</summary>

Сначала пункты сожмутся: `flex-shrink` по умолчанию `1`. Когда сжимать станет
некуда — по минимальной ширине содержимого, — ряд вылезет за край родителя, и
появится горизонтальная прокрутка у всей страницы.

Заметно это не на том экране, на котором верстали.
</details>

**2.** ADA: «`gap: 1rem` у ряда и `margin-inline-end: 1rem` у каждого пункта.
Какой зазор?»

<details><summary>Ответ</summary>

`2rem` между всеми, и `1rem` лишний справа от последнего.

Во флексе поля не схлопываются — это свойство обычного потока, а флекс из него
вышел. Поле ребёнка прибавляется к зазору, а не растворяется в нём. Поэтому
`gap` и собственные поля детей вместе не употребляют.
</details>

**3.** ADA: «`order: -1` у третьего пункта оглавления. Что увидит зрячий
читатель и что услышит незрячий?»

<details><summary>Ответ</summary>

Зрячий увидит его первым. Незрячий услышит третьим — голосовой браузер идёт по
разметке. Клавиша Tab тоже пойдёт по разметке и прыгнет из начала ряда в
середину.

`order` и `row-reverse` — средства для случаев, где порядок ничего не значит.
В оглавлении он значит.
</details>

## Разбор типичных ошибок

1. **`display: flex` без `flex-wrap`.** Ряд сжимается до предела, потом
   вылезает.
2. **Маркеры и отступ под них остались.** Ряд начинается не от края полосы.
3. **Зазор держится на полях детей.** Крайнему достаётся не то же, что
   среднему.
4. **`gap` и поля вместе.** Они складываются: во флексе поля не схлопываются.
5. **`justify-content` вместо `align-items`.** Смена оси меняет смысл обоих.
6. **`width` там, где нужен `flex-basis`.** Считается от базы, а не от ширины.
7. **`order` или `row-reverse` в оглавлении.** Экран расходится с разметкой.
8. **Проверка на своём экране.** Перенос смотрят на узком окне, а не на том,
   где верстали.
