# Теория — s02e01

## 1. Три слоя, которые нельзя смешивать

| Слой | Отвечает на вопрос | Чем задаётся |
|---|---|---|
| содержание | что сказано | текст |
| разметка | чем это является | HTML |
| оформление | как это выглядит | CSS |

Смешение первых двух даёт текст без структуры; смешение вторых двух — разметку,
которую нельзя переоформить. Первое лечится тяжело, второе очень тяжело: чтобы
понять, что `<p class="h2-like">` был заголовком, нужен человек, который это
помнит.

Правило, из которого всё следует: **в разметке принимают решения только о
смысле.** Всё, что начинается со слов «чтобы выглядело», решается в CSS.

## 2. Полный список того, что заменяет `div`

```
header  footer  main  nav  aside  section  article
h1…h6   p       ul ol dl li dt dd
figure  figcaption  blockquote  cite  q
table   caption  thead tbody tfoot  tr th td
form    fieldset  legend  label
time    abbr   address   mark   code   kbd   samp
details summary   dialog   progress   meter
```

Тридцать с лишним элементов. Практический приём: прежде чем взять `div`,
прочитай этот список. В восьми случаях из десяти нужный тег там есть.

Оставшиеся два случая — настоящие: обёртка ради раскладки (например, элемент
сетки, который не является разделом) и группировка ради стиля. Тогда `div`
законен, и это осознанное решение, а не отказ от решения.

## 3. `section` против `article` против `div`

- **`article`** — то, что имеет смысл вынуть целиком: запись, карточка,
  комментарий, одна полоса расписания;
- **`section`** — раздел внутри чего-то, **обязательно с заголовком**;
- **`div`** — ни то ни другое.

Проверка для `section`: если у куска нет заголовка, это не раздел. Секция без
заголовка для голосового браузера выглядит как пустой ориентир — она хуже
`div`, потому что обещает структуру и не даёт её.

## 4. Дерево заголовков

Заголовки образуют оглавление документа — то самое, которое строят браузерные
расширения, голосовые браузеры и поисковые роботы.

```
h1  Мидлендская линия
├── h2  Дерби — Лондон
│   └── h3  Служебные остановки
└── h2  Лестер — Бедфорд
```

Два обязательства: один `h1` и никаких пропусков уровня.

Про «один `h1`» спорят: стандарт разрешает несколько, если каждый в своей
секции. На практике поддержка этого механизма в голосовых браузерах неполная,
и правило «один `h1` на страницу» остаётся рабочим.

**Скрытые заголовки.** Если раздел нужен голосовому браузеру, но не нужен
глазу, заголовок пишут и прячут стилями — приёмом `visually-hidden` (не
`display: none`: он прячет и от голосового браузера тоже). Разберём в `s02e04`.

## 5. Ориентиры

| Элемент | Роль |
|---|---|
| `header` | шапка страницы или раздела |
| `nav` | перечень переходов |
| `main` | основное содержание, ровно одно |
| `aside` | рядом, но не по теме |
| `footer` | выходные данные, примечания |
| `form`, `section` | ориентиры, **только если у них есть имя** |

Имя даётся заголовком внутри или `aria-label`. Правило: когда ориентиров
одного вида больше одного, имена обязательны — иначе выбрать между ними нельзя.

`header` и `footer` внутри `article` — не ориентиры страницы, а шапка и
подвал этой статьи. Вложенность меняет роль.

## 6. Машиночитаемые атрибуты

```html
<time datetime="1891-04-06">6 апреля</time>
<time datetime="PT4H20M">4 ч 20 мин</time>
<abbr title="Ноттингем">Нтм.</abbr>
<data value="1067">узкая колея</data>
<address>Сеймур-стрит, 47</address>
```

Смысл один: человеку — текст в любой форме, машине — значение в единственной.
Для расписаний это не украшение: длительность `PT4H20M` можно сложить, а «4 ч
20 мин» — нет.

## 7. Связи внутри документа

```html
<a href="#note-1">[1]</a>   …   <li id="note-1">…</li>
```

Записанная связь проверяема автоматически, незаписанная — никак. Отсюда
правило вёрстки длинных документов: всё, что человек восстанавливает глазами
(сноска к тексту, подпись к иллюстрации, заголовок к столбцу), должно быть
записано явно.

В `s02e02` тем же приёмом связываются ячейки таблицы с заголовками — и там
цена незаписанной связи становится наглядной.

## 8. Валидатор

```
validator.w3.org/nu/
```

Проверяет не то же, что тесты курса: он ловит нарушения синтаксиса и правил
вложенности (`<li>` вне списка, `<p>` внутри `<p>`), но молчит про смысл —
страница из одних `div` для него безупречна.

Пользоваться стоит обоими: валидатор отвечает «законно ли», тесты сезона — «о
чём это говорит».
