# Теория — s02e03

## 1. Что форма обещает браузеру

Разметка формы — это набор обещаний: какие значения бывают, какие обязательны,
что с ними делать. Браузер их исполняет: даёт подходящий ввод, проверяет,
сообщает об ошибке на языке пользователя и не отправляет, пока не сойдётся.

Написанное позже — на JavaScript или на сервере — не отменяет обещаний, а
повторяет их. Поэтому начинают с разметки: она единственная, которую видит и
браузер, и вспомогательная техника, и сервер (через отправленные имена).

## 2. Типы полей и что даёт каждый

| `type` | Ввод | Проверка |
|---|---|---|
| `text` | строка | `pattern`, `minlength`, `maxlength` |
| `number` | цифры, стрелки | `min`, `max`, `step` |
| `date`, `time`, `month`, `week` | календарь, часы | `min`, `max`, формат |
| `email`, `url`, `tel` | клавиатура под задачу | формат (у `tel` — нет) |
| `range` | ползунок | границы по определению |
| `color`, `file`, `password` | особый ввод | — |
| `checkbox`, `radio` | переключение | `required` (для `radio` — по группе) |

Отдельно `<select>`: выбор из известного списка. Правило: **если множество
значений известно и мало — это выбор, а не ввод.** Опечатка в названии станции
— беда, которой не должно существовать.

## 3. Проверка браузером: что есть

```html
required            значение должно быть
min / max           границы для чисел и дат
step                шаг: 1, 0.5, любой
minlength/maxlength длина строки
pattern             регулярное выражение целиком
type                формат по типу
```

Псевдоклассы для оформления: `:required`, `:optional`, `:valid`, `:invalid`,
`:in-range`, `:out-of-range`, `:user-invalid`.

Последний важен на практике: `:invalid` срабатывает сразу после загрузки, и
пустое обязательное поле краснеет до того, как читатель к нему притронулся.
`:user-invalid` ждёт, пока с полем поработают.

`pattern` сопоставляется **целиком**: `[A-Z]{3}` означает ровно три буквы,
якоря не нужны и добавлять их не надо.

## 4. Три уровня проверки

| Уровень | Задача | Можно обойти |
|---|---|---|
| разметка | поймать опечатку у пользователя | да, тривиально |
| сервер | не пустить мусор в систему | нет |
| база | последний рубеж целостности | нет |

Разметка — про удобство, сервер — про правильность. Путать их опасно в обе
стороны: проверка только в разметке не защищает ничего, проверка только на
сервере заставляет читателя отправлять форму, чтобы узнать про опечатку.

В сезонах 4 и 7 будет видно третий уровень: ограничение в базе против
валидации в модели — тот же разговор на другом этаже.

## 5. Подписи: три способа и один неверный

```html
<label for="id">Текст</label><input id="id">   связь по идентификатору
<label>Текст <input></label>                    связь вложением
<input aria-label="Текст">                      подпись без видимого текста
<input placeholder="Текст">                     ❌ не подпись
```

Третий способ — для случаев, когда подпись видна из окружения (поле поиска
рядом с кнопкой «Найти»). Им не злоупотребляют: невидимая подпись невидима и
для зрячего пользователя тоже.

## 6. Группы

```html
<fieldset>
  <legend>Класс вагона</legend>
  …три переключателя с одним name…
</fieldset>
```

Два разных механизма, которые легко перепутать:

- **общий `name`** делает переключатели взаимоисключающими. Это работа
  браузера;
- **`fieldset` + `legend`** сообщает, что у группы полей общий вопрос. Это
  работа для чтения.

Нужны оба. Для флажков `name` может быть общим (тогда отправятся все
отмеченные) или разным — по смыслу.

## 7. `get` против `post`

| | `get` | `post` |
|---|---|---|
| где значения | в адресе | в теле запроса |
| закладка, пересылка | да | нет |
| повторная отправка | безопасна | требует подтверждения |
| для чего | поиск, фильтр, выборка | создание, изменение, удаление |

Правило: **`get` — когда запрос можно повторить безнаказанно.** Поиск поезда
можно, оплата билета нет.

## 8. `autocomplete`

```html
<input name="from" autocomplete="off">
<input name="email" autocomplete="email">
```

Значения стандартизованы (`name`, `email`, `street-address`, `cc-number`…), и
браузер по ним подставляет сохранённое. Отключать без причины вредно: это
ухудшает ввод и особенно мешает тем, кому набирать тяжело.
