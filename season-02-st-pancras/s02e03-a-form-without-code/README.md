## Чему ты научишься

- Связывать подпись с полем так, чтобы связь существовала не только на глаз.
- Выбирать тип поля по смыслу значения и получать проверку даром.
- Объявлять границы допустимого разметкой: `required`, `min`, `max`,
  `pattern`.
- Приёму, который дороже синтаксиса: **всё, что известно заранее, объявляют, а
  не проверяют потом.** Проверка, написанная позже, повторяет знание, которое
  уже было.

Подробнее — в [`theory.md`](theory.md).

## Теория: форма, которая проверяет себя сама

### Подпись — это связь, а не соседство

```html
<label for="date">День поездки</label>
<input type="date" id="date" name="date">

<label>День поездки <input type="date" name="date"></label>
```

Оба варианта законны: первый связывает по `for`/`id`, второй — вложением.
Результат один: голосовой браузер произносит подпись при переходе к полю, а
щелчок по подписи ставит курсор в поле — мелочь, которой пользуются все и
которую никто не замечает, пока её нет.

Текст рядом с полем этого не делает. Для машины он просто текст.

### `placeholder` — не подпись

```html
<input type="text" placeholder="Код станции">     <!-- подписи нет -->
```

Подсказка исчезает при первом же символе. Пользователь, отвлёкшийся на
середине формы, больше не знает, что это за поле; голосовой браузер читает
подсказку не везде и не всегда; контраст серого текста подсказки почти всегда
недостаточен.

Правило: `placeholder` показывает **пример значения** («например, MID») и
живёт рядом с `label`, а не вместо него.

### Тип поля — это договор

```html
<input type="date">     календарь, проверка формата, min/max по датам
<input type="time">     часы и минуты
<input type="number">   min, max, step, клавиатура с цифрами
<input type="email">    проверка на собаку и точку
<input type="text">     ничего
```

Выбор типа даёт три вещи сразу: удобный ввод, проверку и подходящую
клавиатуру на телефоне. Всё это — бесплатно и одинаково во всех браузерах.

`type="text"` для даты означает: писать календарь самому, проверять формат
самому, объяснять формат словами самому.

### Границы объявляют, а не проверяют

```html
<input type="date" min="1891-04-01" max="1891-04-30" required>
<input type="number" min="1" max="6" step="1">
<input type="text" pattern="[A-Z]{3}">
```

Браузер не отправит форму, пока значение не сойдётся, и сам покажет сообщение
на языке пользователя. Ни строки кода.

Важно, что это **объявление**: те же ограничения потом повторит сервер (и
обязан повторить — разметку легко обойти), но повторит он их зная, что они
уже где-то записаны, а не изобретая заново.

### `fieldset` и `legend`

```html
<fieldset>
  <legend>Класс вагона</legend>
  <input type="radio" id="class-1" name="class" value="1">
  <label for="class-1">Первый</label>
  …
</fieldset>
```

Переключатели одной группы объединены **общим `name`** — только это и делает
их взаимоисключающими. А `fieldset` с `legend` сообщает, что у трёх вопросов
один заголовок: голосовой браузер произнесёт «Класс вагона, первый,
переключатель, один из трёх».

Без `fieldset` это три отдельных вопроса без общего смысла.

### `get` или `post`

Поиск ничего не меняет — значит `get`: результат попадает в адресную строку,
его можно положить в закладки, переслать и открыть заново. `post` — для того,
что меняет состояние, и его результат повторить нельзя.

### Где это в Rails

```erb
<%= form_with url: spravka_path, method: :get do |f| %>
  <%= f.label :date, "День поездки" %>
  <%= f.date_field :date, min: "1891-04-01", max: "1891-04-30", required: true %>
<% end %>
```

`f.label` и `f.date_field` сами расставят согласованные `for` и `id` — ошибиться
станет трудно. Но решение о типе поля и о границах по-прежнему принимаешь ты, и
если написать `f.text_field :date`, Rails послушно напечатает поле без
календаря и без проверки.

## Проверка: ADA задаёт вопросы

```
[ADA · ВНУТРЕННЯЯ ЛИНИЯ]
ТРИ ВОПРОСА.
```

**1.** ADA: «Поле объяснено только подсказкой внутри. Что сломается?»

<details><summary>Ответ</summary>

Подсказка исчезнет при первом символе, и поле останется без названия — для
того, кто вернулся к форме через минуту, и для того, кто её слушает.

Плюс третье, менее очевидное: по подписи нельзя щёлкнуть, чтобы попасть в
поле. Для переключателей это разница между попаданием в кружок диаметром в
десять точек и попаданием в слово.
</details>

**2.** ADA: «`required` и `min` легко обойти: достаточно послать запрос мимо
формы. Зачем они тогда?»

<details><summary>Ответ</summary>

Затем, что они решают другую задачу. Проверка в разметке — не защита, а
**помощь**: она ловит опечатку там, где человек её сделал, и объясняет, что
не так, до отправки.

Защита живёт на сервере и обязана быть там в любом случае. Одно не заменяет
другое: разметка избавляет читателя от лишнего круга, сервер — систему от
мусора.
</details>

**3.** ADA: «Три переключателя без общего `name`. Как это выглядит?»

<details><summary>Ответ</summary>

Как три независимых переключателя, каждый из которых можно включить отдельно.
Выбрать «первый класс и третий класс» станет возможно, и форма это примет.

Взаимное исключение задаётся **именем**, а не внешним видом и не `fieldset`.
`fieldset` отвечает за другое — за то, что у группы есть общий вопрос.
</details>

## Разбор типичных ошибок

1. **Подпись рядом, но не связана.** Для глаза подпись есть, для всего
   остального её нет.
2. **`placeholder` вместо `label`.** Подпись, исчезающая при вводе.
3. **`type="text"` для даты, времени, числа.** Отказ от готовой проверки и
   готового ввода.
4. **Поле без `name`.** Не отправится вовсе, и молча.
5. **`novalidate` на форме.** Выключает ровно то, ради чего всё писалось.
6. **Переключатели с разными именами.** Перестают исключать друг друга.
7. **Группа переключателей без `fieldset`.** Три вопроса вместо одного.
8. **Список станций без пустого первого пункта.** `required` не сработает:
   что-то уже выбрано.
