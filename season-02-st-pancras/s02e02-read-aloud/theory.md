# Теория — s02e02

## 1. Что такое табличные данные

Таблица уместна, когда у значения **два измерения**: оно принадлежит строке и
столбцу одновременно. Время принадлежит станции и поезду — это таблица.
Список станций без времён — это список, и `<ul>` честнее.

Проверка: попробуй прочесть ячейку вслух так, чтобы фраза имела смысл.
«Дерби, номер три, шесть двадцать» — таблица. «Пункт, Дерби» — список.

## 2. Полный состав таблицы

```html
<table>
  <caption>…</caption>
  <colgroup><col><col span="2"></colgroup>
  <thead><tr><th scope="col">…</th></tr></thead>
  <tbody><tr><th scope="row">…</th><td>…</td></tr></tbody>
  <tfoot><tr><td>…</td></tr></tfoot>
</table>
```

Порядок в разметке фиксирован: `caption`, `colgroup`, `thead`, `tbody`,
`tfoot`. При этом `tfoot` отображается внизу независимо от того, где написан.

`colgroup` и `col` не несут смысла для чтения — они существуют, чтобы
оформлять столбцы целиком (ширина, фон). Полезны там, где иначе пришлось бы
вешать класс на каждую ячейку столбца.

## 3. `scope`: четыре значения

| Значение | Заголовок чего |
|---|---|
| `col` | своего столбца |
| `row` | своей строки |
| `colgroup` | нескольких столбцов, которые накрывает `colspan` |
| `rowgroup` | группы строк, обычно в `<tbody>` с `rowspan` |

Алгоритм сопоставления заголовков в браузерах существует и работает без
`scope` — но только для простых таблиц: одна строка шапки, один столбец
заголовков. Как только появляется второй ярус, догадка перестаёт быть
надёжной, и разные голосовые браузеры расходятся в показаниях.

Правило: **`scope` пишут всегда.** Он стоит три слова и снимает вопрос.

## 4. `headers` — когда `scope` не выражает связь

```html
<th id="morning">Утренние</th>
<th id="t3">№ 3</th>
…
<td headers="derby morning t3">6:20</td>
```

Нужен при нерегулярной шапке: ярусов больше двух, ячейки относятся к
заголовкам, стоящим не над ними. Цена — `id` у каждого заголовка и список у
каждой ячейки; поддерживать такое руками тяжело, шаблоном — терпимо.

Практика: если таблица требует `headers`, сначала проверь, нельзя ли разбить
её на две простые. Обычно можно, и читателю от этого лучше.

## 5. Объединение ячеек

```html
<th colspan="2">Утренние</th>     <!-- две колонки -->
<th rowspan="3">Мидленд</th>      <!-- три строки -->
```

`colspan` и `rowspan` — единственное место в таблице, где легко потерять
ячейку. Инвариант простой: **сумма `colspan` во всех строках одинакова**, и
проверять его надо машиной. Глаз его не проверяет: браузер молча достраивает
недостающие ячейки.

Для `rowspan` инвариант сложнее (ячейка занимает место в следующих строках),
и именно поэтому его стараются избегать в данных, которые генерируются.

## 6. Печать и прокрутка

`thead` и `tfoot` повторяются на каждой печатной странице — это поведение
описано в стандарте и реализовано браузерами. Для расписания, которое печатают
книгой, свойство ключевое: вторая страница длинной таблицы без шапки
нечитаема.

То же и на экране: `position: sticky` на `thead th` закрепляет шапку при
прокрутке — но только если `thead` существует.

## 7. Чего в таблице быть не должно

| Приём | Почему нет |
|---|---|
| таблица для раскладки страницы | голосовой браузер объявит её таблицей данных |
| `<br>` вместо строк | строка таблицы — это `<tr>` |
| пустой `<td>` вместо заголовка строки | строка теряет имя |
| вложенная таблица | почти всегда признак раскладки |
| `<table>` без `<caption>` в документе с несколькими таблицами | их не различить в списке |

Исключение про раскладку ровно одно: вёрстка писем для почтовых клиентов.
Там таблицы — единственное, что работает везде, и это осознанный компромисс
с чужой средой, а не способ верстать страницы.

## 8. Как это читает голосовой браузер

Упрощённо: при входе в таблицу объявляется подпись и размер («таблица, Дерби —
Лондон, шесть строк, пять столбцов»). Дальше при переходе по ячейкам
произносятся те заголовки, которые **изменились** с прошлой ячейки:

```
Дерби, номер три, 6:20
номер семь, 8:05          ← станция та же, её не повторяют
Ноттингем, номер три, 6:58 ← сменилась строка
```

Отсюда видно, зачем нужны оба `scope`: без `row` не будет станции, без `col` —
поезда, и ячейка превратится в число.
