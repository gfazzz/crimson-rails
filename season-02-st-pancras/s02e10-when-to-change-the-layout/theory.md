# Теория — s02e10

## 1. Что такое медиазапрос

```css
@media (min-width: 45em) { … }
```

Условие, при котором правила внутри действуют. Всё, что снаружи, действует
всегда — и это главное свойство, из которого следует вся дисциплина.

Полный вид: `@media <тип> and (<признак>) { … }`. Типов осталось четыре —
`all`, `screen`, `print`, `speech`; остальные (`tv`, `handheld`, `projection`)
объявлены устаревшими и игнорируются.

## 2. Сперва узкое

```css
/* основа: достаётся всем */
.layout { grid-template-columns: minmax(0, 1fr); }

/* добавка: достаётся тем, у кого окно шире */
@media (min-width: 45em) {
  .layout { grid-template-columns: minmax(0, 1fr) 12rem; }
}
```

Результат тот же, что у обратного порядка через `max-width`, но отличаются
два обстоятельства:

1. **что достанется, если добавка не доехала.** Стиль загружен частично,
   запрос не поддержан, полоса открыта в режиме чтения — читатель получает
   основу. Узкая раскладка в широком окне работоспособна; широкая в узком —
   нет;
2. **что автор перечисляет.** Добавляя, он пишет, что появилось. Отнимая —
   что должно исчезнуть, а этот список нигде не записан, и его забывают.

## 3. Где ставить перелом

Перелом — ширина, на которой полоса перестаёт читаться. Находится сужением
окна, а не выбором из списка.

Числа вида «телефон 480, планшет 768, ноутбук 1024» описывают модели, которые
устареют, и не описывают ни одного настоящего окна: браузер открывают в
половину экрана, делят пополам, раскрывают на два монитора.

Признак хорошего перелома: его можно назвать словами. «Здесь служебная колонка
перестаёт мешать набору» — перелом. «Здесь планшет» — не перелом.

## 4. Почему `em`

`em` в медиазапросе считается от **начального** кегля браузера — от настройки
читателя. Не от `font-size` корня: внутри запроса его ещё нет, условие
проверяется раньше.

Отсюда полезное следствие: читатель, увеличивший шрифт вдвое, получает перелом
вдвое раньше. Текста в строку влезает меньше — узкая раскладка нужна ему на
более широком окне, и она включается сама.

С `px` этого не бывает: окно не изменилось, значит и условие не изменилось.

## 5. Признаки, которых не видно

```css
@media (prefers-color-scheme: dark)        { … }   /* s02e11 */
@media (prefers-reduced-motion: reduce)    { … }
@media (prefers-contrast: more)            { … }
@media (prefers-reduced-transparency: reduce) { … }
@media (pointer: coarse)                   { … }   /* палец, не мышь */
@media (hover: none)                       { … }   /* наведения не бывает */
@media (any-pointer: fine)                 { … }
@media (orientation: landscape)            { … }
@media (scripting: none)                   { … }
```

Первые четыре — настройки читателя. `prefers-reduced-motion` ставят не из
вкуса: движущийся интерфейс вызывает у части людей тошноту и головокружение.
Уважить этот запрос стоит четырёх строк:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

Это единственный случай в курсе, где `!important` уместен: правило обязано
победить любое авторское, включая написанное позже и точнее.

`pointer: coarse` и `hover: none` описывают устройство ввода, а не размер
экрана. Планшет с мышью и ноутбук с сенсорным экраном ломают привычное
«узкий — значит пальцем».

## 6. Запись диапазонов

```css
@media (width >= 45em) { … }              /* то же, что min-width: 45em */
@media (30em <= width <= 60em) { … }      /* полоса значений */
@media (400px < width) { … }              /* строгое неравенство */
```

Короче и читается как неравенство. Поддержка повсеместная с 2023 года;
`min-width` остаётся понятным всем и потому пока чаще встречается.

Логика: `and`, `,` (означает «или»), `not`.

```css
@media (min-width: 45em) and (orientation: landscape) { … }
@media print, (prefers-contrast: more) { … }
```

## 7. Печатный набор

```css
@media print {
  nav, .skip { display: none; }
  body { color: #000; background-color: #fff; max-inline-size: none; }
  a { text-decoration: none; }
  h2, h3 { break-after: avoid; }
  table { break-inside: avoid; }
}
```

Что стоит сделать: снять фон (принтер напечатает его краской), убрать
навигацию и служебные ссылки, снять предел ширины, запретить разрыв страницы
сразу после заголовка и внутри таблицы.

Чего делать нельзя: прятать содержание. Печать нажали ради него.

Проверяется предпросмотром печати в браузере — это единственный способ увидеть,
что получится.

## 8. Прокручиваемая область

```html
<figure class="scroller" role="region" aria-labelledby="schedule" tabindex="0">
  <table>…</table>
</figure>
```

```css
.scroller { overflow-x: auto; }
```

`overflow` кроме `visible` делает элемент **контекстом прокрутки**. Три вещи,
которые к этому прилагаются:

- `tabindex="0"` — иначе в область не попасть клавишей, а значит и не
  прокрутить её без мыши. Это единственный случай, когда `tabindex="0"` ставят
  на неинтерактивный элемент, и он записан в практиках WAI;
- `role="region"` плюс имя — чтобы читатель, попавший сюда, услышал, где он;
- объявление **вне** медиазапросов: узким окно делает не только телефон, но и
  крупный шрифт.

## 9. Контейнерные запросы

```css
.list { container-type: inline-size; container-name: list; }
@container list (min-width: 30em) { .card { grid-template-columns: 8rem 1fr; } }
```

Медиазапрос знает про окно и ничего не знает про место, куда положили блок.
Карточка в узкой колонке широкого окна получит «широкие» стили и сломается.
Контейнерный запрос спрашивает не окно, а ближайшего предка, объявившего себя
контейнером.

Правило выбора: **раскладка страницы — медиазапрос; раскладка узла, который
кладут в разные места, — контейнерный.**
