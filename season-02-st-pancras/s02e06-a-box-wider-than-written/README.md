## Чему ты научишься

- Из чего складывается коробка и почему `width: 300px` даёт 340 на экране.
- Переводить весь свод на меру по внешнему краю одной строкой.
- Схлопыванию полей: трём случаям, когда оно бывает, и тому, чем оно
  прекращается.
- Прятать элемент от глаза, оставляя его в обходе с клавиатуры.
- Приёму, который дороже синтаксиса: **сторона называется логически.** `block`

## Теория: из чего сложена коробка

### Четыре слоя

```
┌─ margin ───────────────────────────────┐  снаружи, прозрачно
│ ┌─ border ───────────────────────────┐ │
│ │ ┌─ padding ──────────────────────┐ │ │
│ │ │ ┌─ content ──────────────────┐ │ │ │
│ │ │ │                            │ │ │ │
```

`padding` и `border` окрашиваются фоном коробки, `margin` — нет: он всегда
принадлежит тому, что снаружи.

### Две меры одной ширины

```css
width: 300px;
padding: 20px;
border: 1px solid;
```

| `box-sizing` | Что означает `300px` | Что займёт на экране |
|---|---|---|
| `content-box` (по умолчанию) | ширина набора | 342px |
| `border-box` | ширина по внешнему краю рамки | 300px |

Значение по умолчанию — `content-box`, то есть мера Прингла. Это наследие
раннего CSS, и переучить его нельзя, но можно объявить один раз для всего:

```css
:where(*, *::before, *::after) { box-sizing: border-box; }
```

После этого `width` значит то, что от него ждут, и три коробки по `33.33%`
складываются в полосу, а не вылезают из неё.

Псевдоэлементы объявляются отдельно: `*` их не покрывает.

### Схлопывание полей

Вертикальные поля соседей не складываются — берётся большее. Абзац с нижним
полем `20px` и следующий за ним с верхним `30px` разделит зазор в `30px`, а не
в `50px`.

Случаев схлопывания три:

1. **соседи** — как выше;
2. **родитель и первый (последний) ребёнок** — поле ребёнка выходит наружу
   родителя, и зазор появляется снаружи, а не внутри;
3. **пустой блок** — собственные верхнее и нижнее поля схлопываются друг с
   другом.

Схлопывания не бывает по горизонтали и не бывает у коробок, вынутых из потока
(флексы, гриды, `position: absolute`, `overflow` кроме `visible`). Второй
случай прекращается тем, что между полями родителя и ребёнка оказалась хоть
какая-то материя: внутреннее поле или рамка у родителя.

Дисциплина, снимающая вопрос целиком: зазор объявляет кто-то один и всегда
вниз. Тогда схлопывать нечего — сверху полей нет ни у кого, и видно это в
своде с первого взгляда.

### Логические стороны

| Физически | Логически |
|---|---|
| `margin-top` / `margin-bottom` | `margin-block-start` / `margin-block-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `width` / `height` | `inline-size` / `block-size` |
| `text-align: left` | `text-align: start` |

`block` — направление, в котором идут строки; `inline` — направление самой
строки. В русском и английском это «сверху вниз» и «слева направо», в арабском
inline идёт справа налево, в вертикальном японском наборе меняются оба.

Логические свойства переживают смену направления письма без единой правки — а
`lang` у полосы уже объявлен с `s02e04`.

### Спрятать от глаза, не убрав из набора

```css
.skip {
  position: absolute;
  inline-size: 1px;
  block-size: 1px;
  padding: 0;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
}

.skip:focus { position: static; inline-size: auto; block-size: auto; clip-path: none; }
```

`display: none` и `visibility: hidden` убирают элемент отовсюду, включая обход
с клавиатуры. Приём выше убирает только с глаз: коробка остаётся, но она
размером в точку, вынута из потока и обрезана.

Размер именно `1px`, а не ноль: коробку нулевого размера часть браузеров
выбрасывает из дерева доступности — то есть делает то же, что `display: none`,
только незаметно.

### Где это в Rails

```erb
<%= link_to "К расписанию", "#schedule", class: "skip" %>
```

Блочная модель не знает, что напечатало разметку, — и это факт сам по себе.
Зато в Rails такая ссылка пишется один раз, в `layouts/application.html.erb`,
и дальше стоит на каждой странице сама.

## Проверка: ADA задаёт вопросы


**1.** ADA: «`width: 50%`, `padding: 1rem`, рамка `1px`. Два таких блока рядом
помещаются в родителя?»

<details><summary>Ответ</summary>

При `content-box` — нет: каждый займёт `50% + 2rem + 2px`. При `border-box` —
да, ровно.

Первый случай и есть причина, по которой `box-sizing: border-box` объявляют
первой строкой свода: проценты в вёрстке нужны постоянно, а складывать их с
пикселями нельзя.
</details>

**2.** ADA: «Два абзаца: у верхнего нижнее поле `20px`, у нижнего верхнее
`30px`. Какой зазор?»

<details><summary>Ответ</summary>

`30px`. Вертикальные поля соседей схлопываются в одно — большее из двух.

Если бы они складывались, зазоры копились бы при каждой вложенности, и вёрстка
любого текста превратилась бы в вычитание. Схлопывание — механизм полезный;
неприятен он только тогда, когда о нём не знают.
</details>

**3.** ADA: «Почему `1px`, а не `0`, у спрятанной ссылки в обход?»

<details><summary>Ответ</summary>

Коробка нулевого размера в части браузеров выпадает из дерева доступности —
то есть спрятанная ссылка перестаёт быть ссылкой, а выглядит это ровно так же,
как правильный приём.

Один пиксель плюс `overflow: hidden` или `clip-path` даёт коробку, которая для
глаза не существует, а для всего остального существует.
</details>

## Разбор типичных ошибок

1. **`box-sizing` объявлен без псевдоэлементов.** `*` их не покрывает, и
   однажды одна коробка померится иначе.
2. **Предел ширины задан долей окна.** В широком окне строка снова разъедется:
   доля — не предел.
3. **Назначенная высота у текстового блока.** Текст вылезет или обрежется, и
   не на твоём экране.
4. **Поля вверх и вниз вперемешку.** Зазор берётся больший, и каждый второй
   выглядит «не сработавшим».
5. **`margin` сокращением с ненулём.** Это и верхнее поле тоже.
6. **`padding-left` вместо `padding-inline-start`.** Переживёт всё, кроме
   смены направления письма.
7. **У родителя нет внутреннего поля.** Поле первого ребёнка выходит наружу, и
   зазор появляется не там.
8. **`display: none` у ссылки в обход.** Спрятали и от клавиатуры тоже.
9. **Нулевой размер вместо `1px`** или отсутствие правила на фокус. Ссылка
   пропадает из дерева или не возвращается тому, кто на неё попал.
