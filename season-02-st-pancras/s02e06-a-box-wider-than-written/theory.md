# Теория — s02e06

## 1. Коробка

Каждый элемент в потоке — коробка из четырёх вложенных областей:

```
margin   снаружи, прозрачно, принадлежит внешнему миру
border   рамка
padding  внутреннее поле, окрашено фоном коробки
content  набор
```

`padding` и `border` красятся фоном коробки, `margin` — нет, его фон всегда
чужой. Отсюда практическое: чтобы отодвинуть текст от рамки, нужен `padding`;
чтобы отодвинуть коробку от соседа — `margin`.

## 2. Две меры

```css
width: 300px; padding: 20px; border: 1px solid;
```

| `box-sizing` | `300px` — это | Займёт |
|---|---|---|
| `content-box` | ширина набора | 342px |
| `border-box` | ширина по внешнему краю рамки | 300px |

По умолчанию — `content-box`. Это решение раннего CSS, и переучить его нельзя,
но можно объявить иначе один раз:

```css
:where(*, *::before, *::after) { box-sizing: border-box; }
```

`*` псевдоэлементы не покрывает — их перечисляют отдельно. `:where()` здесь
затем, чтобы правило весило ноль и не спорило ни с чем (`s02e05`).

С `border-box` проценты становятся пригодны для вёрстки: три коробки по
`33.33%` с полями и рамками складываются в полосу, а не вылезают из неё.

## 3. Схлопывание полей

Вертикальные поля не складываются — берётся большее. Три случая:

| Случай | Что происходит |
|---|---|
| соседи | зазор равен большему из двух полей |
| родитель и первый/последний ребёнок | поле ребёнка выходит наружу родителя |
| пустой блок | собственные верхнее и нижнее схлопываются друг с другом |

Чего схлопывание не делает:

- не бывает по горизонтали — только по блочной оси;
- не бывает у коробок вне обычного потока: флекс- и грид-элементы,
  `position: absolute` и `fixed`;
- прекращается любой материей между полями: внутреннее поле или рамка у
  родителя, `overflow` кроме `visible`, отдельный контекст форматирования.

Второй случай — самый неприятный: зазор появляется **снаружи** родителя, и
выглядит это как «фон уехал», а не как «поле не сработало».

## 4. Дисциплина зазора

Схлопывание перестаёт удивлять, если зазор объявляет кто-то один:

```css
h1, h2, h3, p, figure, table { margin-block-end: 1.25rem; }
```

Поля только вниз — схлопывать нечего. Цена: пространство перед заголовком
приходится отдавать тому, что выше. Зато свод читается без вычитания.

Другие рабочие дисциплины — на будущее:

```css
.flow > * + * { margin-block-start: 1rem; }   /* зазор только между соседями */
.column { display: flex; flex-direction: column; gap: 1rem; }
```

`gap` полей не создаёт вовсе и потому не схлопывается никогда. Он появится в
`s02e07`, и после него дисциплина зазора сама собой сводится к нему.

## 5. Логические стороны

| Физически | Логически |
|---|---|
| `margin-top` / `margin-bottom` | `margin-block-start` / `margin-block-end` |
| `padding-left` / `padding-right` | `padding-inline-start` / `padding-inline-end` |
| `width` / `height` | `inline-size` / `block-size` |
| `max-width` / `min-height` | `max-inline-size` / `min-block-size` |
| `text-align: left` | `text-align: start` |
| `border-left` | `border-inline-start` |

`inline` — направление, в котором идёт строка; `block` — направление, в
котором строки накапливаются. Пара задаётся `writing-mode` и `direction`, и
браузер берёт её из `lang` и стилей, а не угадывает.

Сокращения по осям: `margin-inline: auto` (обе горизонтальные стороны),
`padding-block: 1rem 2rem` (верх и низ).

Зачем это, если полоса на русском: во-первых, тот же свод переживёт арабскую
или японскую версию справочника; во-вторых, логическое имя точнее описывает
намерение — «отступ после абзаца», а не «отступ снизу».

## 6. Сокрытие без потери доступности

```css
.visually-hidden {
  position: absolute;
  inline-size: 1px;
  block-size: 1px;
  padding: 0;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
}
```

Каждая строка нужна:

| Строка | Зачем |
|---|---|
| `position: absolute` | иначе коробка займёт строку в потоке |
| `1px` × `1px` | нулевой размер выбрасывает элемент из дерева доступности |
| `padding: 0` | иначе внутреннее поле вернёт коробке размер |
| `overflow: hidden` | текст, не влезший в 1×1, иначе виден |
| `clip-path: inset(50%)` | обрезает надёжнее, включая тень и обводку |
| `white-space: nowrap` | текст не переносится и не растягивает коробку |

Что **не** годится: `display: none`, `visibility: hidden`, `opacity: 0` (эта
оставляет коробку в потоке и кликабельной), вынос за экран через
`position: absolute; left: -9999px` (у RTL-раскладки появляется полоса
прокрутки, а голосовые браузеры иногда читают порядок не тот).

Парное правило обязательно:

```css
.skip:focus { position: static; inline-size: auto; block-size: auto; clip-path: none; }
```

Без него ссылка спрятана и от того, кто на неё попал клавишей.

## 7. Что ещё делает контекст форматирования

Коробка с `overflow` кроме `visible`, `display: flow-root`, флекс, грид или
`position: absolute` создаёт **отдельный контекст форматирования**. Внутри
него:

- поля не схлопываются наружу;
- плавающие элементы не вылезают за границы;
- содержимое не перекрывает соседей.

`display: flow-root` — способ создать его, не меняя ничего другого. Это
современная замена приёма `clearfix`, который два десятилетия писали
псевдоэлементом.
