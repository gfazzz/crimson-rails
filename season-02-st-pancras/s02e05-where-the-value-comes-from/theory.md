# Теория — s02e05

## 1. Задача каскада

У одного элемента одно значение каждого свойства. Объявлений, метящих в это
свойство, обычно несколько: встроенная таблица браузера, таблица читателя,
твой свод, а внутри свода — ещё пять правил. Каскад — это порядок, в котором
из них выбирается одно. Он определён и одинаков везде.

Вопросы задаются сверху вниз, и первый же различивший ответ решает дело.

```
1. слой и происхождение с учётом важности
2. специфичность селектора
3. порядок в документе
```

## 2. Происхождение и важность

| Происхождение | Что это |
|---|---|
| user-agent | встроенная таблица браузера |
| user | таблица читателя, его настройки крупного шрифта |
| author | твой `.css` |

Обычный порядок силы: user-agent < user < author. С `!important` порядок
**переворачивается**:

```
1. user-agent !important        ← сильнейший
2. user !important
3. author !important
4. author
5. user
6. user-agent                   ← слабейший
```

Переворот не случайность. Читатель, которому нужен шрифт втрое крупнее, ставит
`!important` — и остаётся в своём праве, что бы ни объявил автор. `!important`
задуман как право пользователя, а не как приём автора.

## 3. Специфичность

Три разряда, слева направо:

```
[ идентификаторы , классы/атрибуты/псевдоклассы , теги/псевдоэлементы ]
```

| Селектор | Вес |
|---|---|
| `#schedule` | 1-0-0 |
| `.timetable td` | 0-1-1 |
| `a:hover` | 0-1-1 |
| `[scope="row"]` | 0-1-0 |
| `th, td` | 0-0-1 (у каждого свой вес) |
| `main > table td::first-line` | 0-0-4 |
| `:where(td)` | 0-0-0 |
| `*`, `>`, `+`, `~` | не считаются |

Сравнение лексикографическое: `1-0-0` бьёт `0-99-99`. Это не сумма и не число
в системе счисления — это три независимых разряда, из которых смотрится
первый различающийся.

Особые случаи:

- `:is(...)`, `:not(...)`, `:has(...)` весят столько, сколько **самый тяжёлый**
  селектор внутри. `:is(#a, p)` — `1-0-0`;
- `:where(...)` весит `0-0-0` всегда;
- `style="…"` в разметке весит больше любого селектора;
- `!important` — не разряд специфичности, а вопрос выше по списку.

## 4. Порядок

При равном происхождении и равной специфичности побеждает объявление, которое
идёт позже: ниже в файле, в файле, подключённом позже.

Отсюда дисциплина свода: **сверху вниз от общего к частному.** Тогда два
механизма перестают спорить — то, что ниже, заодно и точнее, и читающий файл
глазами приходит к тому же выводу, что и браузер.

Если файл этого порядка не держит, разбираться приходится каждый раз заново, и
единственный быстрый способ победить — `!important`. Так свод и вырождается.

## 5. `@layer` — четвёртый уровень

Слои появились, чтобы задать порядок групп правил **независимо от
специфичности**:

```css
@layer reset, base, components;

@layer components { .timetable td { text-align: right } }
@layer reset      { td { text-align: left } }
```

Любое правило слоя `components` бьёт любое правило слоя `reset`, как бы они ни
весили и в каком бы порядке ни стояли. Правила вне слоёв сильнее всех слоёв.

Слои — то, чего не хватало библиотекам: подключил чужой свод в слой `vendor` и
перебиваешь его чем угодно. В этой серии мы обходимся без них намеренно: пока
свод один и умещается на полутора листах, дисциплина порядка нужнее механизма.

## 6. `:where()` и основание

```css
:where(*, *::before, *::after) { box-sizing: border-box; }
:where(body, h1, h2, p, table) { margin: 0; }
```

То же без `:where()` весило бы `0-0-1` и спорило бы с каждым правилом для
тега. Обнулённое — не спорит ни с чем: любое правило ниже перебивает его
молча, и автору не приходится считать веса.

Это и есть определение основания: слой, который обязан уступать.

## 7. Наследование — другой механизм

Каскад выбирает из **объявленного для этого элемента**. Если не объявлено
ничего, вступает наследование.

| Наследуется | Не наследуется |
|---|---|
| `color`, `font-*`, `line-height` | `margin`, `padding`, `border` |
| `text-align`, `letter-spacing` | `background`, `width`, `height` |
| `list-style`, `cursor`, `visibility` | `display`, `position`, `overflow` |

Принцип в списке есть: наследуется то, что относится к тексту, не наследуется
то, что относится к коробке. Рамка, доставшаяся каждому потомку, была бы
бедствием.

Практическое следствие: **наследуемое объявляют один раз, у корня.** Иначе
получается двадцать мест, где менять шрифт, и девятнадцать, где его забудут.

## 8. Четыре ключевых слова

```css
color: inherit;   взять у родителя, даже если свойство ненаследуемое
color: initial;   значение по спецификации (для color — чёрный)
color: unset;     inherit для наследуемых, initial для остальных
color: revert;    откатить до значения предыдущего происхождения
```

`revert` — самый полезный и самый малоизвестный: он возвращает не «ничего», а
то, что дал браузер. `all: revert` на элементе снимает всё авторское
оформление разом.

## 9. Инструмент вместо гадания

В любом браузере: инспектор → панель «Styles». Перечёркнутое объявление
проиграло, и наведение показывает победителя. Панель «Computed» отвечает на
вопрос «какое значение вышло», а не «какое объявлено»; у каждой строки
раскрывается список всех объявлений в порядке каскада.

Это быстрее любого рассуждения о весах — и единственный способ поймать случай,
когда правило вообще не применяется, потому что селектор ни во что не попал.
