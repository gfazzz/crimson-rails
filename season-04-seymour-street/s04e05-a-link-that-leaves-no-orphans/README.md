## Чему ты научишься

- Ставить ссылку на другую ведомость: столбец, индекс и внешний ключ.
- Объявлять `belongs_to` и `has_many` и понимать, что они не гарантия.
- Выбирать `dependent:` осознанно и знать цену каждого варианта.
- Различать «ссылка обязана быть» и «ссылка обязана вести на существующее».
- Приёму, который дороже синтаксиса: **убрать можно только то, на что никто
  не ссылается.** Всё остальное — не уборка, а перенос беспорядка в другое
  место.

## Теория: сцепка

### Три вещи и одна строка

```ruby
add_reference :consignments, :company, null: false, foreign_key: true
```

Делает сразу:

| Что | Зачем |
|---|---|
| столбец `company_id` | сама ссылка |
| индекс по нему | «все перевозки этой дороги» без чтения всей ведомости; удаление дороги — тем более |
| внешний ключ | ссылка ведёт на существующую строку |

И `null: false` — отдельно от ключа. Это **разные** правила: `null: false`
требует, чтобы ссылка была; внешний ключ — чтобы она вела на существующее.
Ссылка, которой нет, и ссылка в никуда — разные беды.

### Связь в модели

```ruby
class Consignment < ApplicationRecord
  belongs_to :company
end

class Company < ApplicationRecord
  has_many :consignments, dependent: :restrict_with_error
end
```

`belongs_to` стоит там, где лежит столбец с ключом. Запомнить просто: **кто
ссылается, тот и принадлежит.**

С Rails 5 `belongs_to` обязателен по умолчанию — добавляет валидацию
присутствия. Это вежливость; гарантию по-прежнему даёт внешний ключ.
`optional: true` снимает валидацию и не трогает ключ.

### `dependent:` — это решение, а не настройка

| Значение | Что делает | Когда |
|---|---|---|
| `:restrict_with_error` | отказывает, `destroy` даёт `false`, ошибка в `errors` | есть кому показать отказ |
| `:restrict_with_exception` | отказывает падением | некому показать |
| `:destroy` | удаляет связанные, по одному, с колбэками | связанные не имеют смысла без родителя |
| `:delete_all` | удаляет одним запросом, без колбэков | то же, но их много |
| `:nullify` | обнуляет ссылку | связь необязательна |
| не указан | ничего; отказывать будет внешний ключ | почти всегда ошибка |

Для ведомости Палаты `:destroy` был бы неверен: убрать дорогу — это не повод
потерять её перевозки и деньги за них. `:nullify` невозможен: у столбца
`null: false`.

И главное: `dependent:` — **правило модели**. Внешний ключ ничего про него не
знает и откажет в любом случае; `dependent:` решает, будет ли отказ объяснён.

### Что бывает без внешнего ключа

Строка, ссылающаяся на несуществующую: **сирота**. Её особенность — она не
болит сразу. Отчёт по дороге её пропустит (`JOIN` не найдёт пары), свод
сойдётся не полностью, и однажды сумма не сойдётся на величину, которую никто
не может объяснить.

Найти сирот потом можно только перебором:

```sql
SELECT * FROM consignments c
LEFT JOIN companies co ON co.id = c.company_id
WHERE co.id IS NULL;
```

Внешний ключ стоит ровно того, чтобы этого запроса никогда не понадобилось.

**1.** ADA: «`belongs_to` объявлен. Зачем ещё внешний ключ?»

<details><summary>Ответ</summary>

Затем же, зачем индекс рядом с `validates :uniqueness`.

`belongs_to` — способ найти дорогу по перевозке и валидация присутствия. Ни
то, ни другое не мешает положить `company_id = 999`: ни `insert_all`, ни
консоль, ни скрипт переноса валидаций не зовут, а само число никем не
проверяется.

Внешний ключ проверяет его при записи — и при удалении с другой стороны.
</details>

**2.** ADA: «`dependent: :destroy` на `has_many`. Что случится с базой?»

<details><summary>Ответ</summary>

Удаление одной строки превратится в удаление многих — по одной, с колбэками
на каждую.

Иногда это то, что нужно: строки заказа без заказа не имеют смысла. Иногда —
катастрофа: перевозки без дороги имеют смысл, и это деньги.

Признак: **спросите, есть ли у связанных записей ценность сами по себе.**
Если есть — `dependent: :destroy` неверен, каким бы удобным ни казался.
</details>

**3.** ADA: «Внешний ключ есть, `dependent:` не указан. Что увидит
пользователь?»

<details><summary>Ответ</summary>

`ActiveRecord::InvalidForeignKey` — то есть пятисотую.

База откажет правильно, но не объяснит: в её отказе нет ни «у этой дороги
есть перевозки», ни «сначала разберитесь с ними». Это та же пара, что в
прошлой серии: ключ — гарантия, `dependent:` — объяснение.
</details>

## Разбор типичных ошибок

1. **`belongs_to` без внешнего ключа.** `company_id = 999` ляжет.
2. **Внешний ключ без индекса.** Удаление дороги начинает читать всю
   ведомость.
3. **`null: false` забыт.** Ключ стерпит `NULL`: «ссылки нет» для него не
   нарушение.
4. **`dependent: :destroy` там, где связанные ценны сами по себе.**
5. **`dependent:` не указан.** Пятисотая вместо объяснения.
6. **`optional: true` «чтобы не мешало».** Валидация снята, а `null: false`
   остался — падение базы вместо сообщения.
7. **`belongs_to` на той стороне, где нет столбца.** Ссылается тот, кто
   принадлежит.
8. **Столбец назван не по соглашению** (`sender_id` вместо `company_id`) без
   указания `foreign_key:` и `class_name:`. Rails не догадается.
9. **Удаление «в обход» через `delete`.** Колбэки и `dependent:` не
   сработают; останется отказ базы.
10. **Сироты, найденные позже.** Их приходится искать перебором, и обычно
    после того, как свод не сошёлся.

с перевозками из реестра не вынуть.

Уиттл раскладывает отказавшие бланки на столе. Все четыре — с одной станции:

— Так он же есть в реестре, — говорит Уиттл. — Карточка двести девять.

— Ноль, — говорит Уиттл. — Карточки ноль не бывает.

— Не бывает. — Кроссли смотрит на бланки. — Тридцать лет не бывало, и тридцать
лет это никого не останавливало: в тексте можно написать что угодно. Теперь
