## Обстановка

Отправитель в бланке записан текстом: `GNR`, `GWR`, `G.W.R.`, «Грейт Вестерн,
через контору в Суиндоне». Тридцать лет отдел сверки сличает написания —
неделя работы на каждый месяц ведомости.

Вместо текста нужен номер карточки. И то, что не даст этому номеру указывать в
никуда.

## Приказ

Поставить сцепку между ведомостями.

## `db/migrate` — `AddSenderToConsignments`

Ссылка на дорогу-отправителя. Нужны три вещи, и `add_reference` умеет все три:

| Что | Зачем |
|---|---|
| столбец `company_id` | сама ссылка |
| индекс по нему | «все перевозки этой дороги» без чтения всей ведомости |
| внешний ключ | ссылка ведёт на существующую строку |

Плюс `null: false` — отдельным правилом. Это **не то же самое**, что внешний
ключ: ключ следит, чтобы ссылка вела на существующее, `null: false` — чтобы
ссылка вообще была.

## `app/models`

| Модель | Что добавить |
|---|---|
| `Consignment` | принадлежит дороге |
| `Company` | имеет много перевозок; дорогу с перевозками убрать нельзя, и отказ должен объясниться |

Про `dependent:` — это решение, а не настройка:

| Значение | Что значит здесь |
|---|---|
| `:destroy` | убрать дорогу — потерять её перевозки и деньги за них |
| `:nullify` | невозможен: у столбца `null: false` |
| `:restrict_with_exception` | отказ падением; показывать его некому |
| `:restrict_with_error` | отказ с объяснением, `destroy` возвращает `false` |

## Критерии приёмки

**Схема**

- [ ] У перевозки есть `company_id`, целое, обязательное.
- [ ] По нему есть индекс.
- [ ] Есть внешний ключ на `companies` по столбцу `company_id`.

**База не оставляет сирот**

- [ ] Сырой `INSERT` перевозки с `company_id = 999999` отвергается
      (`InvalidForeignKey`).
- [ ] Сырой `INSERT` без отправителя отвергается (`NotNullViolation`).
- [ ] Сырой `DELETE` дороги, у которой есть перевозки, отвергается.
- [ ] Дорога без перевозок удаляется.

**Связь в модели**

- [ ] `consignment.company` возвращает дорогу.
- [ ] `company.consignments` возвращает её перевозки.
- [ ] Перевозка без дороги негодна, и ошибка привязана к связи.

**Удаление объясняется**

- [ ] `company.destroy` у дороги с перевозками возвращает `false`, ошибка — в
      `errors[:base]`, дорога на месте.
- [ ] Перевозки при этом не удаляются.
- [ ] Пустая дорога удаляется.

**Прежнее цело**

- [ ] Уникальность кода из `s04e04` держится; плата из `s04e02` — целая.

**Схема как факт**

- [ ] Версия схемы равна версии последней миграции.
- [ ] Откат на одну ступень снимает `company_id`.
- [ ] Откат до нуля оставляет пустую схему.

- [ ] `make test` → семнадцать зелёных проверок.

## Подводный камень

Первый: `foreign_key: true` забыт. `add_reference` без него делает столбец и
индекс — выглядит как готовая связь и ничего не гарантирует.

Второй: `optional: true` «чтобы не мешало». Валидация снимается, `null: false`
остаётся, и вместо сообщения читатель получает падение базы.

Третий: `dependent: :destroy`, поставленный по привычке. Спросите, имеют ли
связанные записи ценность сами по себе. Перевозки имеют.
