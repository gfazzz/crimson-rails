## Обстановка

Сорок одна тысяча перевозок за пять лет. Первый свод считался час и успел
четыре тысячи строк; в журнале машины — сто двадцать три тысячи обращений к
ведомости участков, по три на перевозку.

Ответ при этом был бы правильным. Через девять часов.

## Приказ

Спросить один раз вместо сорока одной тысячи.

Миграций в этой серии нет: схема не меняется.

## `app/models/leg.rb`

| Отбор | Что делает |
|---|---|
| `through_company(code)` | участки, прошедшие по дороге с таким кодом |

Реестр здесь нужен для отбора, а не для чтения: его объекты никому не
понадобятся.

## `app/models/consignment.rb`

### Отборы

| Отбор | Что делает |
|---|---|
| `unsettled` | нерассчитанные перевозки |
| `sent_between(from, to)` | отправленные в промежутке, включая оба конца |
| `through_company(code)` | прошедшие через дорогу с таким кодом — по участкам, а не по отправителю |

Все три обязаны оставаться **отборами**, а не строками: складываться друг с
другом и уходить в базу одним запросом.

### `self.route_sheet(relation = all)`

Маршрутный лист: на каждую перевозку — номер бланка и коды дорог по порядку
пути.

```ruby
[{ reference: "B-1041", roads: %w[GNR NER] }, ...]
```

Требование одно, и оно же проверяется: **число запросов не зависит от числа
строк.** Ни к участкам, ни к реестру.

### `self.miles_by_company(relation = all)`

Сколько миль прошла каждая дорога по отобранным перевозкам:

```ruby
{ 1 => 48, 2 => 380, 3 => 380 }   # id дороги => мили
```

Считать должна база, **одним** запросом. Отбор подставляется подзапросом, а не
списком из сорока одной тысячи чисел.

## Критерии приёмки

**Отбор — кусок запроса**

- [ ] Пока у отбора не спросили строк, в базу ничего не уходит.
- [ ] Два отбора складываются в **один** запрос.
- [ ] `unsettled` отбирает нерассчитанные.
- [ ] `sent_between` включает оба конца промежутка.
- [ ] `through_company` отбирает по дорогам пути, а не по отправителю.

**Цена обхода**

- [ ] Маршрутный лист верен: бланки и коды дорог по порядку.
- [ ] Число запросов к участкам **не растёт** от того, что строк стало
      больше.
- [ ] Реестр не спрашивают построчно.

**Считает база**

- [ ] Свод по милям уходит одним запросом и даёт верные суммы.
- [ ] Свод считается только по отобранным перевозкам.

**Дёшево**

- [ ] `pluck` просит один столбец, а не все графы.
- [ ] Проверка «есть ли хоть одна» останавливается на первой строке.

**Прежнее цело**

- [ ] Связи и порядок участков из `s04e06` работают.
- [ ] Схема не менялась.

- [ ] `make test` → шестнадцать зелёных проверок.

## Подводный камень

Первый: `joins` вместо `includes` там, где связь потом читают. Отбор станет
правильным, а N+1 останется — и это самая частая правка «починил и не
починилось».

Второй: `scope` без лямбды. `scope :recent, where(sent_on: Date.current)`
вычислится один раз, при загрузке класса, и «сегодня» застынет навсегда.
Правильно — `-> { ... }`.

Третий: `relation.to_a` посреди цепочки — например `.select(:id).to_a` в
подзапросе. Ленивость кончится, и вместо подзапроса уедет список из сорока
одной тысячи чисел.

девяносто первого, по одной в день.
