## Чему ты научишься

- Заводить промежуточную ведомость вместо «связи многих со многими».
- Ставить составной уникальный индекс и выбирать порядок столбцов.
- Читать связь по цепочке: `has_many through:` и `source:`.
- Выбирать `dependent:` по существу, а не по привычке — здесь `:destroy`
  верен, а в прошлой серии был бы ошибкой.
- Приёму, который дороже синтаксиса: **как только у связи появляются свои
  графы, она перестаёт быть связью.** Держать их негде, и приходится заводить
  то, что нужно было завести сразу.

Подробнее — в [`theory.md`](theory.md).

## Теория: третья ведомость

### Два способа связать многих со многими

```ruby
has_and_belongs_to_many :companies          # таблица companies_consignments
has_many :legs
has_many :companies, through: :legs         # таблица legs со своей моделью
```

Первый — таблица из двух столбцов и ничего больше. Второй — обычная модель,
которая просто ссылается на двоих.

Признак выбора один: **есть ли у связи собственные сведения.** «Дорога
участвовала» — сведений нет, годится первое. «Участок номер два, сто
девяносто миль» — сведения есть, и держать их в таблице из двух столбцов
негде.

На практике `has_and_belongs_to_many` почти всегда оказывается преждевременным:
сведения появляются позже, и таблицу приходится переделывать на живых данных.
Поэтому Rails-сообщество давно предпочитает `through` по умолчанию.

### Составной уникальный индекс

```ruby
add_index :legs, %i[consignment_id position], unique: true
```

Уникальна **пара**, а не каждый из столбцов. Позиций «1» в ведомости столько
же, сколько перевозок; двух первых участков на одной перевозке — ни одного.

**Порядок столбцов решает, что индексом можно искать.** Индекс годится для
поиска по своему началу:

| Запрос | Индекс `[consignment_id, position]` |
|---|---|
| по `consignment_id` | годится |
| по паре | годится |
| по одной `position` | не годится |

Участки всегда ищут внутри перевозки — значит `consignment_id` идёт первым.
Поставь наоборот, и индекс станет уникальным так же, а полезным перестанет.

В модели ему соответствует:

```ruby
validates :position, uniqueness: { scope: :consignment_id }
```

`scope:` — это и есть «в пределах». И как всегда: валидация говорит, индекс
держит.

### Цепочка

```ruby
class Consignment
  has_many :legs, -> { order(:position) }, dependent: :destroy, inverse_of: :consignment
  has_many :companies, through: :legs
end

class Company
  has_many :legs, dependent: :restrict_with_error
  has_many :carried_consignments, through: :legs, source: :consignment
end
```

`through:` не заводит вторую связь — он читает существующую по цепочке и
превращается в `JOIN`. `source:` нужен там, где имя связи у нас не совпадает
с именем на том конце: `carried_consignments` ведёт к `Consignment`, но связь
в `Leg` называется `consignment`.

Область видимости у связи (`-> { order(:position) }`) делает порядок частью
самой связи: читать участки не по порядку пути бессмысленно.

### `dependent:` во второй раз

В прошлой серии `:destroy` был бы ошибкой: перевозки имеют цену сами по себе.
Здесь он верен: участок без своей перевозки не значит ничего.

Признак остался тот же — **есть ли у связанных записей смысл в одиночку.** Не
«хочется ли убрать», а «имеют ли они смысл».

```

```

**1.** ADA: «Составной индекс `[consignment_id, position]`. Что он ускорит?»

<details><summary>Ответ</summary>

Поиск по `consignment_id` и по паре. Поиск по одной `position` — нет.

Индекс отсортирован по первому столбцу, внутри него — по второму. Искать
можно по началу этого порядка: как в справочнике, отсортированном по фамилии,
а потом по имени, — найти всех Смитов легко, всех Джонов невозможно.

Отсюда правило выбора порядка: **первым идёт то, по чему ищут всегда.**
</details>

**2.** ADA: «`has_and_belongs_to_many` или `has_many through:`?»

<details><summary>Ответ</summary>

`through:`, если у связи есть или появятся собственные сведения. Здесь они
есть: мили и порядковый номер.

И практически всегда `through:`, потому что «появятся» — это вопрос времени, а
переделывать связь на живых данных дороже, чем завести модель сразу.

`has_and_belongs_to_many` остаётся честным выбором ровно для одного случая:
связь без сведений, которая такой и останется. Например теги, которые ничего
про себя не рассказывают.
</details>

**3.** ADA: «Почему `dependent: :destroy` верен здесь и был бы ошибкой в
прошлой серии?»

<details><summary>Ответ</summary>

Потому что вопрос не в том, что удобно удалить, а в том, что имеет смысл в
одиночку.

Перевозка без дороги имеет смысл: это груз, который везли, и деньги, которые
за него взяли. Участок без перевозки не значит ничего — это строка «сто
девяносто миль» без указания, чего.

Признак работает в обе стороны и не зависит от того, как связь называется.
</details>

## Разбор типичных ошибок

1. **`has_and_belongs_to_many` там, где у связи есть сведения.** Держать их
   негде.
2. **Уникальный индекс на один столбец вместо пары.** Первых участков в
   ведомости столько же, сколько перевозок.
3. **Столбцы в составном индексе переставлены.** Уникальность та же, польза
   другая.
4. **`uniqueness` без `scope:`.** Модель запрещает то, что должно быть
   можно.
5. **Внешний ключ только на одну сторону.** Вторая продолжает ссылаться в
   никуда.
6. **Забытый индекс по второй ссылке.** «Все участки этой дороги» читают всю
   ведомость.
7. **`dependent: :destroy` на дороге.** Убрали дорогу — потеряли раздел
   выручки.
8. **`dependent:` не указан у участков.** Перевозку не убрать, а причина
   неочевидна.
9. **`through` без `source:` при несовпадающих именах.** Rails не догадается.
10. **Порядок участков не объявлен.** Читать путь не по порядку бессмысленно,
    а сортировка на каждом вызове забывается.

Сходится всё, кроме четырёх перевозок.

Тех самых — Колвик-Сайдингс, уголь.

— У меня по ним два участка, — говорит Уиттл, водя пальцем по листу. — Приняла
Великая северная, сдала она же. Двенадцать миль.

Ты смотришь на ленту. В машине по этим перевозкам **три** участка.

Первый — Великая северная, двенадцать миль. Третий — она же, ноль миль,
«сдача». Второй — между ними: дорога `MDL`, сто девяносто миль.

— Сто девяносто? — Уиттл берёт лист обратно. — От Колвик-Сайдингс до Ноттингема
четыре мили. Куда тут сто девяносто?

Кроссли уже считает на полях.

— Сто девяносто из двухсот двух — это девяносто четыре процента платы.

В зале раздела сорок человек с линейками. Ни один из них никогда не видел эти
четыре перевозки: сквозными они не считались — приняла и сдала одна дорога.
