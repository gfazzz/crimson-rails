## Season 4. Previously

## Что даёт сезон

Active Record и схему в объёме, после которого база перестаёт быть местом, где
«лежат данные», и становится тем, чем она является: последней инстанцией,
которая отказывает.

Критерий отбора тот же, что в сезонах 1–3: **концепт входит, только если без
него Rails выглядит магией.** Поэтому здесь есть миграции, типы, связи,
индексы, ограничения, запросы и транзакции — и нет ни одного гема сверх того,
что ставит `rails new`.

Главная мысль сезона объявлена в первой серии и проверяется в последней:
**валидация в модели — просьба, ограничение в схеме — отказ.** Одна не
заменяет другую, и день, когда разница становится видна, всегда наступает
внезапно.

**Чем сезон кончается.** Ты добавляешь уникальный индекс на живой ведомости.
Миграция падает. Список строк, на которых она упала, — и есть дело, которое
тянется с первой серии первого сезона.

## Контракт проверки сезона

`SPEC.md` §4. Для этого сезона:

**Обязан проверять** — целостность на уровне базы: ограничение держит,
уникальный индекс существует, связь не оставляет сирот. Почти каждая проверка
вставляет строку **сырым SQL, мимо модели**: так в жизни выглядят консоль,
скрипт переноса и соседняя система, которой отдали доступ к той же базе.

**Не засчитывается как проверка** — прохождение валидации в модели без индекса
за ней; «объект сохранился»; сравнение текста миграции с эталоном.

## Среда

Ruby 3.2 или новее, Rails 8, SQLite. Установка — в
[`docs/GETTING_STARTED.md`](../docs/GETTING_STARTED.md).

```bash
cd season-04-seymour-street/app
bundle install
bin/rails db:prepare
```

Прогон — обычный minitest, без внешнего раннера:

```bash
make test SEASON=04             # весь сезон
make test SERIES=s04e01         # одна серия
```

Три вещи, которые стоит знать про эту среду:

- **приложение одно на сезон.** Артефакт серии — не файл, а слой приложения:
  миграция, модель, индекс. Поэтому `starter/` и `solution/` здесь не файлы в
  корне серии, а **патч-наборы**, которые ложатся в приложение по своим путям
  (`SPEC.md` §3);
- **проверка живёт вне приложения.** Она получает путь к нему через
  `LEDGER_APP`, поднимает его `config/environment` и спрашивает базу. Отсюда
  же прогон эталона: он идёт на копии приложения и вашу работу не трогает;
- **база — SQLite, и этого достаточно.** `NOT NULL`, `UNIQUE`, `FOREIGN KEY`
  и `CHECK` он держит по-настоящему, а всё, что проверяют серии, переносится
  на PostgreSQL без изменений.

## Сквозной артефакт: `ledger`

Реестр Расчётной палаты. Растёт от серии к серии:

```
app/
├── db/migrate/         e01–e10 — форма реестра, слой за слоем
├── db/schema.rb        слепок: то, что база знает про себя
├── app/models/         e03–e10 — записи, связи, области видимости
└── test/               пусто до сезона 8: проверки курса лежат в сериях
```

В сезоне 5 поверх этого реестра появится интерфейс — маршруты, контроллеры,
Hotwire, — и `telegraph` из сезона 3 будет сравниваться с Turbo: одна и та же
задача, решённая своим JS и средствами Rails 8.

## Как проходить серию

```bash
cd season-04-seymour-street/s04e01-a-ledger-that-knows-its-shape
cp -R starter/. ../app/          # патч-набор ложится в приложение
# написать то, что помечено TODO
cd ../app && bin/rails db:migrate && cd -
make test
```

Эталон — на копии приложения, вашу работу не трогает:

```bash
make solution
```

Если база пришла в непонятное состояние (чаще всего — прогнали пустую
заготовку, а заполнили после):

```bash
cd ../app && bin/rails db:migrate:reset
```
